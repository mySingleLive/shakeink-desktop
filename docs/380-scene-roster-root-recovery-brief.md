# 场景根结构错误的保留式恢复

R42 实际首个失败为 native/stop/invalid_schema/object-roster-extra。只扩展具体场景清单的恢复，仍最多四代、不改变普通任务或非 stop、错误根类型/超额等边界，不放宽任何接受规则。

首次正常结束且原解析器得到含自有 roster 数组（不超过原 2000 项）及额外根字段的对象时，原 strict schema 仍拒绝。仅用已知 roster 行的现有 proofRow 投影建立一次来源保留证明，绝不剥根字段后直接成功或部分入账。原回复完整保留为不可信资料。

进入独立的“根结构恢复”态后，本请求剩余代次中所有 stop 的结构失败均继续使用第一阶段 schema 完整重生，不切换定点事务或重建 stable slot。每次携带原完整失败根草稿与当前完整失败回复，原已证提及、完整窗口、原成员组、限定和关系都由现有 retention 强制保留。最终必须通过原 strict wire、所有 source/ownership/retention/final 门；重复错误或丢资料仍失败。仅捕获一次，不重复调用 capture；正常无额外根字段的已有 typed 路径逐字保持，其 source-present 不准 reject 门不变。保护只涵盖首次可独立核验的资料，不把未知键或未定位 claim 当真，也不宣称它们已完整恢复；最终全部正文和资料复核仍必需。

每次实际完整 prompt/schema 预算先验，不截断资料，不增加次数、不扩网络/授权/取消恢复。不可解析首答的现有完整重生规则保持。新状态可在不可解析首答后遇到额外根时进入；已经冻结 typed 的事务不能退回整份重生。

同时仅更新 PRIVATE RPC 观察器：完整锚定已知场景清单错误格式，保存最多 5 个互异预置业务标签组成的有界字符串；未知标签/附加文本不回显。保持现有固定 category、旧标签以外行为、委托顺序、方法身份和私有 700/600 写入，不读取响应结果、原文、headers 或 Key。新 v5 bundle 与 driver 只更换观察器路径，计时与验收门不变。
