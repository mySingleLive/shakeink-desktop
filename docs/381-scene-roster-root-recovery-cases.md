# 根结构恢复用例

1. 实际场景桥：首答严格 roster 加额外根被拒，次答严格完整 roster 才通过；仍第一 schema、两代用量/权限路径，首答不直接剥字段采用。直接 strict parser 继续拒根额外字段。
2. 根额外首答已有可证好行与坏行：完整重生必须保留每个可证提及、完整引用、owner 分组、限定及两端关系；删除/缩窗/换归属/桥接/错端点持续四代仍失败，不靠计数通过。
3. 新态只 capture 一次、一直第一 schema，不进入 typed prepare；首次不可解析后可进入，原 typed 事务后回复错根仍原 typed，不回退。原草稿与当前完整失败回复保持，不积已被取代的历史。
4. 非 stop/missing/unknown、错误 roster 类型/无 roster/数组根/超额、网络/授权/取消/usage 原失败边界保持；四代上限/generic 两代不变，预算 N/N-1 和完整原数据不截断。
5. 原所有 source/retention/CF/owner 负控保持。旧额外根持续失败的合成次数预期仅按新恢复规则更新，不放宽直接解析或最终接受断言。
6. PRIVATE observer：先真实 RED 验证原 classifier 未保存已知业务标签，后 GREEN；六个单标签及合法有界组合只保存预置字面值，未知/伪造/超长/重复/尾随秘密不落标签。原 12 项委托/真实 Worker/权限与恢复控制仍全部通过，原消息和返回不变。
7. 独审后正常 fresh 全文，v5 路径以外驱动逐字不变，公开记录只固定分类/计数/哈希。剩余失败按实际标签处理，不把本轮当完成。
