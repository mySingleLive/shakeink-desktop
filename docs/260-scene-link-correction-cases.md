# 场景关联校验纠错用例

日期：2026-10-31。依据259及其独立方案审核。只使用合成资料；先新增RED，随后最小实现。使用Node24，不运行全仓测试。

- **SL-01 精确内层纠错**：分别使characterId、sceneId、itemId引用不存在的ID或错误类型的已有ID，及parentId引用另一合法PLACE或给根场景新增父级。首轮严格拒绝，第二轮生成提示必须含固定字段路径和对应类型/确认父级说明；模型改正后保留完整text、四原生字段、有效引用及父级。不得把非法值或名称/别名带入反馈。
- **SL-02 持续失败/拒绝集合不变**：以上错误连续生成仍在两次后拒绝，最终固定公开类别和invalidFields/feedback一致，非法资料不被覆盖或删除后接受。父级仍为原身份类别，三个关联字段给各自固定引用类别。额外字段、显式错误entityType、非法facts形状、错目标及无效证据继续由原组拒绝。
- **SL-03 外层有界恢复**：真实controller→runImportAi→generateImportAiJson合成链路，目标sceneId前两次非法、第三次有效，精确2请求/3生成。第二请求instruction必须保留场景关联地点字段及对应目录类型指导；全文资料及任务ID最终一致。
- **SL-04 外层持续失败**：同链路持续非法sceneId，精确2请求/4生成，任务failed，无该目标伪成功artifact；场景不被跳过。
- **SL-05 完整目录及轮次隔离**：合法关联指向请求完整可信目录中的条目，即使该条目未出现在有界provider payload仍合法；最终结果和输入对象不被改动。坏关联之后一次抛网络错误、取消或其它结构错误，不得沿用旧字段分类；角色及普通scene分析保持原通用行为。
- **SL-06 回归与实际验收**：原场景结构/原生字段/控制元数据/引文/有限纠错/调度/取消排空组，角色兼容、严格实体引用和原生发布组，TypeScript及构建。新session使用正确加密应用身份、全部原件/1402章/全文覆盖、默认全选全部本轮场景；最终全部未过滤任务和资料ID与候选一致，父级逐ID完全等于确认值，无失败/跳过/丢弃/映射警告，源和正文不变，正常保存退出并重开逐字段及逐章核对。历史部分成功和定向单目标请求不能替代完整验收。
