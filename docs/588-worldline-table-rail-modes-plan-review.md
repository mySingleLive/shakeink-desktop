# 588 方案独立审核：事件表时间轴对齐 / 等距两种模式

审核对象：`docs/588-worldline-table-rail-modes-plan.md`（方案与用例同一文档），对照调研 `docs/588-worldline-table-rail-modes-research.md`、已批准设计稿 `design/worldline-rail-modes/index.html` 与 docs/586。基于 `7b89b23`，行号均为 `7b89b23` 的行号（方案文档行号为当前未提交稿）。只读核对源码，没有运行应用；真实数据数字用 `~/shakeink-test-roots/worldline-ui-583-evidence/588/times.json` 加临时脚本（同 `order-588.ts` 的读法，按段计数，运行后已删除）复算。

结论：需求 R1～R6 都有对应条目，“卡片布局不依赖模式、只换时间轴”的切法正确，对齐模式规则整体可实现。但分组框布局的递推写法会多加一次 `CARD_GAP`；嵌套分组框的 1px 边框让屏幕上的卡片头与 `card.head` 逐层错开，F60 的孙级卡片会让 RM-B2 失败；年徽章位置与设计稿不一致；RM-E4 的期望值 224 用错了口径（按段计数是 61）。这几处要先改方案，再进入实现。

## 必须修改

1. **父卡片之后的子事件会被多加一次 `CARD_GAP`。**
   方案 §1（`plan.md:21`）写“未折叠：`y += 父卡片高 + GROUP_HEAD_GAP`，再排子事件”。但子事件走的是同一个 `block()`，它开头就有 `if (!first) y += CARD_GAP`（`worldline-layout.ts:702`）。现有代码正是靠这一行得到父卡片到首个子卡的 6px（`worldline-layout.ts:731-732`，WU-19j `worldline-layout.test.ts:170`）。照方案原文实现，首个子卡 `top = 父顶 + 36 + 4 + 6 = 父顶 + 46`，RM-01 期望的 `父底 + 4` 不成立，§3 的“39px”推导也随之变化。
   设计稿的 `layout()` 也有同样的问题（`index.html:157` 先 `y += 36 + 4`，`:150` 子事件再加 6），所以设计稿中实际间隔是 10px，不能拿它当证据。
   修正：写明父卡片之后 `y += 父卡片高 + GROUP_HEAD_GAP − CARD_GAP`，或者给 `block()` 传一个“紧跟标题栏”的参数，让首个子事件不再加 `CARD_GAP`。RM-01 用手算值覆盖这一点：首个子卡 `top − 父顶 = 40`。

2. **分组框边框让嵌套卡片在屏幕上逐层下移 1px；父卡片收起时的几何前后矛盾。**
   - `renderLevel` 把框内卡片和内层框放进框的 DOM 子树，坐标相对框计算（`EventTable.tsx:374-376`，`originTop = g.top`）。`.groupBox` 有 1px 边框（`worldline.module.css:195`），Tailwind preflight 让 `*` 都是 `border-box`（`node_modules/tailwindcss/preflight.css:12`，`globals.css:1`）。绝对定位的子元素以框的 padding box 为参照，所以每进一层框，屏幕位置比布局坐标多 1px。现在也存在这个偏差，只是贝塞尔引线掩盖了它。对齐模式改成水平引线，再加上 RM-B2 的 ≤1px 阈值，深度 2 就差 2px。F60 有孙级（`tests/helpers/worldline-f60.ts:3,51`），RM-B2 会失败。
   - 同一处还有矛盾：§1 写折叠时 `group.bottom = 父底`，也就是框高 36（border-box，含上下边框）；RM-B5（`plan.md:111`）又要求“上缘 = 框上缘 + 1px 边框，高 36”和“折叠后框高 = 36 + 2px 边框”。框内容区只有 34px，放不下从 +1 开始的 36px 卡片，卡片会压住框的下边框。
   - 标题栏的头部中线也算不到 18：方案写的是“无上边框，`.head` 35px，下边框 1px”（`plan.md:25`），中线在 17.5px 处，再加框边框的 1px，屏幕上是 18.5px。
   修正：选定一种几何写进 §1，并让 RM-01 和 RM-B5 都按它手算。例如 `.slotHead { top: -1px; left: -1px; right: -1px }`，让标题栏外缘与框外缘重合，`head = top + 18`，`.groupHead .head` 取 36px 且下边框画在内部（或用 `box-shadow: inset`）；同时让框内子层抵消边框，比如框改用 `outline` / `box-shadow` 画边，或者 `renderLevel` 的 `originTop/originLeft` 每层减 1。RM-B2 必须覆盖深度 2 的卡片（F60 的“冲突中有人受伤”一类孙事件）。

3. **展开卡片不满足“圆点、日期与卡片头部中线在同一水平线”（R1），RM-B2 没有限定范围。**
   展开卡片的 `.head` 是 42px（`worldline.module.css:111`），中线在 `top + 1 + 21 = top + 22`，而方案规定“展开不改变 `head`”（`plan.md:23`），仍取 `top + 17`，对齐模式下差 5px。展开的父卡片还多一处冲突：`.groupHead .head { height: 35px }` 与 `.open .head { height: 42px }` 特异度相同，结果取决于 CSS 顺序。
   修正：二选一并写入方案。(a) `head = top + (expanded ? 22 : 17)`，父卡片同理。布局本来就知道 `expanded`（`worldline-layout.ts:716`），等距模式的圆点只会随之移动几 px。(b) 保持现状，在 R1 的说明和 RM-B2 / RM-E1 中写明只断言收起的卡片。推荐 (a)。另外写明展开时标题栏 `.head` 的高度。

4. **年徽章位置与已批准设计稿不一致，夹着回退卡片时会压在回退卡片的圆点上。**
   方案 §3（`plan.md:53`）把徽章放在“相邻两张**非回退**卡片 head 的中点”。两者之间有回退卡片时，这个中点可能正好落在某张回退卡片的 head 上。徽章画在圆点的 x 处（`.railBadge left: 158px`，`worldline.module.css:182`），会盖住圆点和 `↺` 标签。设计稿取的是**紧邻的上一张卡**：`badges.push({ y: i ? (cs[i - 1].y + c.y) / 2 : c.y - 22 …})`（`design/worldline-rail-modes/index.html:184`），与当前徽章年份比较，而不是与上一张非回退卡片比较。
   修正：改为“非回退卡片的 `yearKey` 与当前徽章年份不同时，在它与紧邻上一张卡（含回退卡片）head 的中点加徽章”。RM-05 增加一例：两张非回退卡片之间夹一张回退卡片，徽章 y 等于回退卡片 head 与新年份卡片 head 的中点。

5. **RM-E4 的期望值 224 是全局口径，方案规则按段计算，真实数据应为 61。**
   `order-588.ts` 的 `runMax` 跨段累计，从不按段清零，所以 224 是全表计数。方案 §3 的规则是“段内已出现的最大时间”。我在同一份数据上按 `lay.segments[].heads` 逐段计算，得到回退卡片 61 张（根事件 20 张，子事件 41 张），连续回退 11 段。段的时间范围有 5 处重叠，这是两个口径相差很大的原因。“已知取舍”里“224 张回退卡片”（`plan.md:82`）也要一并改。
   修正：RM-E4 期望改为 61，或者改为“与同一数据上 `alignedRailMarks` 纯函数的计数一致，且该计数为 61”，并把计数脚本放进 `588/` 证据目录。另外，真实数据的 61 张回退卡片都与当前年徽章年份不同，1049/1061 是 year 精度，所以复位时可见的标签基本只有 `↺ X年`。RM-E3 需要先找到一个可见标签再悬停，写明找法。

6. **切换按钮会盖住分组标题栏的“…”菜单，“已知取舍”低估了遮挡范围。**
   按 R4，每个父卡片都占满框宽。框的右缘在 `.cards` 内距右 24px（`worldline.module.css:190,195`），切换按钮也在滚动区内距右 24px、距顶 8px（`plan.md:33`），两者右缘相同。所以只要有分组标题栏滚到视口顶部（真实数据有 61 个分组），它右端约 160px 就被按钮盖住，“▸ N”计数和“…”菜单都在这一段（`EventCard.tsx:187-205`）。框宽上限 940px，只有滚动区很宽时才露得出来。这不只是“窄面板上的宽卡片”。
   修正：(a) 照设计稿给表格顶部留出空间（设计稿 `.table { margin-top: 32px }`，`index.html:34`），保证 `scrollTop = 0` 时首个卡片不被遮住；(b) 在“已知取舍”中如实写明，滚动中任何顶到视口顶的标题栏都会被遮住右端，可以滚动避开。另一个做法是把按钮的右边距加到菜单宽度以外；这需要用户确认，因为位置是审核第 1 轮定的。RM-B1 增加断言：`scrollTop = 0` 时按钮与任何卡片不相交。

7. **回退卡片的圆点没有按设计稿画成空心。**
   设计稿给回退圆点加了 `.dot.back { background: var(--bg) }`（`index.html:39,276`），标签悬停时用 `.lab.hot { font-style: normal }` 取消斜体（`index.html:43`）。方案 §3 的渲染部分（`plan.md:60`）只写了标签的 `s.back` 和虚线轴。AGENTS.md 要求桌面差异逐条按批准设计实现。
   修正：`RailDot` 增加 `back`，渲染 `s.back` 空心样式，`data-rail-back-dot` 或类似属性供 RM-B6 断言；写明 `.railLabel.back.hot` 恢复正体。

## 建议修改

8. **RM-04 的数据违反领域约束。** 例中子事件 1338-11、1339-08-14 早于父事件 1340-04-01，`validatePlanning` 会拒收（`domain.ts:503-507`：`resolved.start >= bound.start`）。真实数据里 child-before-parent 为 0，回退都来自“前一个家族的子事件晚于下一个根事件”。纯函数不做校验，用例能跑，但测的不是会出现的形态。建议改成：根 A 1340-04-01，A 的子事件 1340-12-20；根 B 1340-06-01，B 的子事件 1340-06-05 与 1341-01-03。这样 B 和 B 的第一个子事件是回退，第二个子事件不是，同时还能覆盖第 4 条的徽章位置。

9. **窄栏下去重键会丢月份。** 方案用的 `railText(…, compact)` 在窄栏时省略月份（`worldline-layout.ts:382`，例如 `5日 21:00`）。§3 的键是“文字去掉约与↺”（`plan.md:52`），会把不同月份同日同时刻的两张卡判为同键。现有 `railMarks` 去重时用非 compact 文字（`worldline-layout.ts:966`）。建议写明：去重键与回退时补年份的判断都用非 compact 文字。增加用例：compact 下 3 月 5 日 21:00 与 4 月 5 日 21:00 相邻，两个都可见。

10. **补年份前缀改按精度判断，并带上纪元。** “文字不含年份”的判断（`plan.md:49`）要靠字符串查找；era 精度（`第四纪`）、`cap` 文本和 `railLabel` 路径都不含“年”，会被错误补上 `yearKey`。建议只对 day、hour 精度补前缀（month 文字已含年份，year 本身就是年份，era 不补）。年份比较和前缀改用 `yearText`（含纪元）：`yearKey` 不含纪元（`worldline-layout.ts:387-391`），跨纪元同年号时既不补前缀，也不产生年徽章。真实数据中这种情况是 0，用 ERA_CAL 各加一个用例即可。

11. **era 精度卡片会产生“第N纪1年”的年徽章。** era 精度的值落在纪元起点，非回退时按 §3 会以 `yearText(t)` 加徽章，显示成精确到年份，与记录精度不符。建议 era 精度卡片不触发年徽章，或只触发纪元徽章。RM-03 的 era 例补一条徽章断言。

12. **对齐模式的缩放值要用夹紧后的 e。** `tableZoom` 状态可以超出当前树的边界，实际使用的 `e` 是 `clamp(tableZoom)`（`PlanningWorkspace.tsx:302`）。§2 的 `exp(e)` 应从 `tableView` 返回夹紧后的 e，否则切换世界线后百分比与实际缩放不符。Ctrl + 滚轮一步是 1.15（`EventTable.tsx:216`），RM-B3 可以再加一条 `115%`。

13. **标签悬停的残留状态。**
    - 标签用索引作 key（`EventTable.tsx:322`，`lb${i}`）。在标签上 Ctrl + 滚轮，或者切换模式后，指针下的同一个 DOM 节点换成了另一组 `ids`，但不会触发 `pointerenter`，`hover` 仍是旧事件，新标签也不高亮。只靠 `pointerleave` 时，被虚拟化或 `hot` 条件卸载的节点也不会再派发离开事件。
    - 建议：标签 key 改为 `ids.join(",")`；或者像卡片区那样在 `.rail` 上用 `onPointerOver` 委托，用 `closest("[data-rail-label],[data-rail-dot]")` 求 ids（`EventTable.tsx:338-341`）；同时在切换模式时清空 `hover`。RM-B4 增加一步：悬停标签时切换模式，旧卡片的高亮随即消失。
    - 方案说 `.railLabel` 改成 `pointer-events: auto` 不会挡住滚动，这没有问题：滚轮事件冒泡到滚动区，Ctrl + 滚轮也由滚动区原生监听（`EventTable.tsx:223`）。

14. **参考线的起点和触发来源写清楚。** “从标签左缘”需要知道标签宽度，而标签是 `right: 66px` 右对齐（`worldline.module.css:179`），布局中没有这个宽度。设计稿从 x = 0 画到卡片左缘（`index.html:284`），触发条件是 `hot(id)`，也就是悬停卡片、圆点或标签都会出现。建议照设计稿：起点 x = 0（窄栏同样），任意来源的悬停都显示，选中是否显示另行写明；x 终点计入第 2 条的边框修正。

15. **标题栏的 CSS 特异度。** `.slot:not(.slotOpen) > .card { width: fit-content; max-width: 100% }` 的特异度是 (0,3,0)，`.slot.slotOpen { max-width: 920px }` 是 (0,2,0)（`worldline.module.css:193-194`）。单独的 `.groupHead { width: 100% }` 和 `.slotHead { max-width: none }` 会输给它们，收起时标题栏仍按内容收窄，展开时被限制在 920px（框宽上限 940px）。建议方案直接给出选择器，例如 `.slot.slotHead`、`.slot.slotHead > .card.groupHead`。另外，“左侧类型色竖条由框的类型色边框衔接”与现状不符：框四边都是 `ec 22%` 的同一种边框（`worldline.module.css:195`），没有类型色左边框。请写明是否给框加 3px 类型色左边框（设计稿 `.group` 有 `border-left: 3px solid var(--ec)`，`index.html:53`）。

16. **窄栏下切换按钮与吸顶年份可能重叠。** 吸顶年份在左 14px、上 8px（`worldline.module.css:198`），切换按钮在右 10px、上 8px，高度相同。窄栏时目录改为浮层（`worldline.module.css:274`），滚动区约等于面板宽度。面板宽度小于约 300px 时，“第五纪1349年”这类较长的年份与约 160px 宽的按钮会相交。建议写明最小面板宽度，或在窄栏去掉“时间轴”前缀文字；RM-B7 增加断言：两者的矩形不相交。

17. **z-index 的结论成立，建议写明依据。** `.slot`、`.groupBox`、`.cards` 都没有 z-index，不形成层叠上下文，打开菜单的卡片 `z-index: 9`（`worldline.module.css:109`）与吸顶容器的 7 在同一层叠上下文中比较，菜单在上；目录浮层 15 也在上面。方案可以加一句这个理由，并在 RM-B 中覆盖一次“顶部卡片打开菜单时，菜单在按钮之上”。

18. **用例迁移要预先列出，不要“按实际失败清单”。** 默认改为对齐后，下列现有用例的前提会变化，建议在方案中逐条写出处理方式和不算放宽的理由：
    - 单元：WU-19j（`worldline-layout.test.ts:161-182`），RL-02 的分组框高 134 → 124、`qTop(1)` 140 → 130（`:759-760`，不是“只按 head 更新”）。
    - 浏览器：WU-30 前 20 张卡全为 34px（`planning-worldline-table.test.ts:20`，F60 的父卡片在其中）；WU-44 需要“一个没有可见标签的圆点”（`planning-worldline-table-scale.test.ts:53-58`），对齐模式下 F60 多数卡片都有可见标签；WU-45 断言缩放值为“日”“上下午”（`:83,99`）；RL-B1～B6 断言 `data-rail-level` 与档位名（`planning-worldline-table-rail.test.ts`）；WU-46 的吸顶年份读的是徽章位置，模式变了，徽章也变了。
    - 建议：断言等距几何的用例显式切到“等距”；WU-44、WU-44b 的悬停联动在两种模式各跑一次，不能只切走。

19. **缺少的用例。**
    - 键盘与无障碍：Tab 能聚焦切换按钮，Enter / Space 切换模式，`aria-pressed` 随之改变，焦点样式可见。
    - 虚拟化：F885（>300 个事件，`VIRTUAL_MIN`，`EventTable.tsx:352`）在对齐模式下滚动到中部，视口内圆点与卡片头对齐（RM-B2 只用 F60，不虚拟化）。
    - 定位（WU-62）：对齐模式下从目录定位标题栏和孙级卡片，仍落在上三分之一处（`PlanningWorkspace.tsx:2378-2381`），分组框标题栏改版后至少回归一次。
    - 展开父卡片：展开后标题栏仍占满框宽，`head` 与 RM-B2 的口径一致（第 3 条）。
    - 单元：深度 2 的分组（孙级本身也是父事件）布局手算，包括“父 head → 子标题栏 head = 40”、“折叠的子组 → 下一兄弟 = 41”，以证明 §3 的“≥ 39px”。我按方案常量逐类核算过：父 head → 叶子 39，父 head → 子组标题栏 40，叶子 → 叶子 40，叶子 → 组 41，折叠组 → 下一个 41，内层组末尾 → 外层下一个 50，展开卡片只会更大。前提是第 1 条修正后首个子卡位于 +40。结论成立，但应写成用例。
    - 时期条的端点：方案用闭区间 `[start, end]`，设计稿用 `< end`（`index.html:201`），工具栏计数用 `<= end`（`PlanningWorkspace.tsx:2530`）。建议与工具栏保持一致并写明，RM-06 加一张恰好落在 `end` 上的卡。

20. **小处。**
    - 对齐模式下 `RailLabel.level` 写明取 `null`（`data-rail-level=""`），避免 RL 用例误读。
    - 对齐模式中卡片头至少相隔 39px，18px 间隔规则永远满足。§3 可以注明这一点，并写明回退标签是否更新“上一个可见标签 y”。
    - 虚线回退段画在实线轴上，两者颜色接近（`.railLine` 用 `--input`）。建议 `railBack` 先用背景色盖住实线再画虚线，否则看不出虚线。
    - 调研写的是“切换时取 `firstVisible` 恢复”（`research.md:81`），方案改为不需要锚点（`plan.md:35`）。理由成立（`tableLayout` 不接收模式参数，`EventTable.tsx:60-63`），建议在方案里注明与调研的差异。

### 手算核对

- **RM-01**（k = 0）：p 位于 0..36，head 18。y = 36 − 2 = 34，c1 的 block 加 6，c1.top = 40，head 57。c2.top = 74 + 6 = 80，差 40。框底 = 114 + 10 = 124，`g.bottom − c2.top = 44`，框高 124。q.top = 130，`q.top − g.bottom = 6`。折叠时框底 = 36。展开 p（测得 120）：c1.top = 120 − 2 + 6 = 124，p.head = 21；展开 c1：head = top + 22。**全部正确。**
- **RM-01b**：c.top = 34 + 6 = 40（head 58）；g.top = 76 − 2 + 6 = 80（head 97）；c 框底 = 114 + 10 = 124；d.top = 130（head 147）；p 框底 = 164 + 10 = 174。差值 40 / 39 / 50。折叠 c：c 框底 76，d.top = 82，head 99，c → d 为 41。**全部正确。**数据也合法：FIXED24 下持续时间为 0 的父事件可以容纳 24 小时内的子事件（`domain.ts:496-501`）。
- **RM-04**：A、B 两根相隔 61 天，只有一个间隔，limit = max(720, 61 天 × 20)，所以是一段。顺序 A、A1、B、B1、B2；max = A1（12-20），B、B1 是回退，B2 不是。同在 1340 年，不补年份。`backs = [A1.head, B1.head]`；B2 是 1341 年，徽章位于 `(B1.head + B2.head)/2`。**规则推导正确。**
- **RM-B3**：`exp(ln 1.25 + ln 1.15) × 100 = 143.75`，四舍五入为 `144%`。**正确**，前提是 F60 在 125% 时 `canZoomIn` 仍为真（上限是 60 px/h 对应的倍数，远大于 1.44）。
- **RL-02 迁移**：`qTop(k) = max(130, min(240, 72k))`。k = 1 时为 130（原 140）；k = 3 时为 216，k = 4 时为 240，都与原值相同。

### 建议（新）

A. **RM-04 的数据还缺持续时间，否则不合法。** 持续时间为 0 的父事件只容纳 24 小时（`domain.ts:496-507`），A1、B1、B2 都超出了这个范围。单元用例的 `plan()` 只调用 `planningSchema.parse`，不调用 `validatePlanning`，所以用例照样能跑，但写着“合法数据”就应当真的合法。建议给 A 加 `dur ≥ 263 天`，给 B 加 `dur ≥ 216 天`，并写进用例。“补年例”也请给出具体数据。根事件按时间排序，所以只能让前一个家族的子事件跨到下一年，例如：父 E 1339-06-01（dur 覆盖子事件），子事件 E1 1340-02-01，然后根 F 1339-08-14，都是 day 精度。F 早于 E1，是回退，年份 1339 又与当前徽章年 1340 不同，所以显示 `↺ 第五纪1339年8月14日`。

B. **标题栏盖住了框的 3px 类型色左边。** 标题栏背景不透明，位于框的内阴影之上，所以框左边的 `inset 3px` 在标题栏这一段会被盖住，只露出卡片自带 `::before` 那一段（`worldline.module.css:101`，top 7 到 bottom 7）。左边条因此在标题栏上下各断开 7px。设计稿的标题栏自带 `border-left: 3px solid var(--ec)`（`index.html:56`），左边条是连续的。建议标题栏的各个 box-shadow（常态、hot、selected、hit）都加 `inset 3px 0 0 var(--ec)`，同时隐藏它的 `::before`；RM-B5 截图时目视确认。框的上边被标题栏盖住，这与设计稿相同，不用改。

C. **RL-02 迁移直接写出值。** `qTop(3) = 216`、`qTop(4) = 240` 不变，与其写“重算”，不如把两个值写进迁移表，作为不放宽的证据。

D. **补年份时“约”的位置。** 正文对 window 事件以“约”开头，若在正文前补 `yearText`，会得到 `↺ 第五纪1339年约8月14日`。建议规定顺序为 `↺ ` + `约` + 年份 + 月日，并在 RM-03 或 RM-04 加一个 window 回退例。

E. **段内全是 era 精度卡片时的段首徽章。** 段首徽章取“第一张非回退、非 era 精度卡片”，如果没有这样的卡片（远古段全是 era 精度），规则没有定义。建议写明此时不加年徽章（`hasEras && hasYears` 的日历也不补纪元徽章），并加一个单元断言。

F. **`data-ids` 是新属性。** 委托读的是 `data-ids`，但现在标签用的是 `data-label-for`（以空格分隔），圆点只有 `data-event-id`（只含主事件，`EventTable.tsx:302,325`）。建议写明圆点和标签都新增 `data-ids`（以空格分隔），并保留 `data-label-for`，因为 WU-44 等用例在用它。

G. **展开标题栏的估算高度应为 −2。** 收起时标题栏比叶子卡高 2（36 对 34），展开时却少 2：标题栏没有边框（0 + 42 + 正文），叶子卡是 1 + 42 + 正文 + 1。§1 写的“`estimateCardHeight` + 2”方向反了。实测高度会覆盖估算值，锚点也会修正，影响只有 4px，但方案应写对。

H. **WU-44 在对齐模式下的前提。** WU-44 需要“一个没有可见标签的圆点”（`planning-worldline-table-scale.test.ts:53-58`）。对齐模式下只有同键相邻的第二张卡隐藏标签，F60 中是否存在这种卡要先确认。如果不存在，在对齐模式下改为悬停一个有可见标签的卡片，断言高亮；不要让前提断言失败后跳过这个用例。
