# 单项候选与定点反馈用例

1. 真实 JSON/SDK 桥业务 RED：旧 occurrence 有 1 个已证及多个未证同 literal；context 有旧窗口、错误 label 窗口及有据新窗口。确认新展示恰为原完整目录上原单项 predicate 的集合、顺序不变，所有全局选项/keep/CF/原窗口仍完整。模型明确选展示 CF 后可过所有原门；不将模拟称为真实供应商表现。
2. 原接受门负控逐一保留：选 old mention（窄/宽 quote 同 occurrence）、其它旧 owner、同次 newMembers 重复、label 不在 quote、old context、基底重复、联合 link/owner 桥接仍拒；空列表不自动 reject、不增 canReject。静态候选不能决定多 claim 联合分配，不按首项修好非法结果。
3. actual guard 安全反馈：已声明 repairRef/claimRef+固定 reason/字段下标，定位 old/new mention 与 label/context 窗口错误；replace 的 CF 真但 literal 0 次/多次仍原严格拒绝。未知 ref/key/私密值不得进入反馈或普通日志，任意伪造 Error 不得借定点反馈回显；kind/finish/四代/业务标签保持。合法 prior 数据块不误算成反馈泄漏。
4. 完整目录建立后才计算展示，覆盖后加入的 whole-unit/其它行窗口；正反例包含 CRLF/astral、同 literal 多 occurrence、重复字面但不同 source/owner、冻结副本及旧 CF/Map/resolve 不变。old replace 未选展示但原本合法的选项仍可通过，不暗缩接受集。
5. 实际全量新增 metadata/反馈+原来源/草稿/当前回复/choices/keep/native schema 的二至四 prompt N/N-1；保留原 CI 两个 16K 正控与原 budget 负控，不抬夹具容量/常量或裁文本。原过大请求仍拒绝，不因空候选/反馈多而加代次。
6. 首轮/root/generic/旧 replace 相关回归保持；新字段仅当前有资格的 patch 展示范围，raw 未知/legacy/无法分解仍原 fallback。离线检查实际 130 planner/77 capture 的新 prompt 上界，0 provider、不冒旧 input hash 相同或供应商新结果。
7. 先真实功能 RED 再实现 GREEN，独立 code review 后由 root 组合/类型/构建/正常全文。公开证据仅固定 guard、计数、哈希；真实资料和模型输出只留 0600 私有目录。
