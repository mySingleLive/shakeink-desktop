# 588 · 世界线事件表视图：两种时间轴模式 调研

来源：用户 2026-11-18 修改要求（附截图：事件表左侧时间轴圆点与右侧卡片上下错开）。基于 `7b89b23`（docs/587）。本文只做调研与方案方向；UI 设计稿审核通过后再写技术方案与测试用例，按 AGENTS.md 流程审核。

## 用户要求

| # | 内容 |
|---|---|
| R1 | 事件表视图支持两种时间轴模式：**等距**（现有：相同长度代表相同时间间隔）与 **对齐**（时间轴上事件日期与卡片上边界处于同一屏幕 y；相同长度不一定代表相同间隔） |
| R2 | 两种模式同时支持，提供切换按钮，随时切换 |
| R3 | 默认改为对齐模式 |

说明：事件表是纵向布局，“同一屏幕 x 轴上”理解为同一条水平线（同一 y）。“卡片上边界”按现有引线的落点理解为**收起卡片头部中线**（卡片顶 + 17px，`CARD_HEAD`）：收起卡片高 34px，圆点画在卡片顶边会落在两张卡之间的缝里。设计稿中两种落点都可看，由用户确认。

## 现状（源文件）

- 卡片位置：`tableLayout()`（`src/lib/planning/worldline-layout.ts:683-771`）按事件树深度优先排列：根事件按开始时间排序，每个父事件后紧跟它的子事件（分组框），再到下一个根。相邻根之间按 `min(240, Δt × k)` 拉开（docs/586 §1）。
- 圆点位置：`segmentY()`（`:864-866`）在每段内按最早、最晚卡片头**线性插值**。圆点 y 只由时间决定，与卡片位置无关；卡片 y 由堆叠决定。两者只在段首、段尾重合，中间靠贝塞尔引线（`EventTable.tsx:278-293`）连接。
- 依赖圆点 y 的元素（`railMarks()`，`:868-992`）：圆点与聚合（4px 内合并）、标签（18px 间隔、去重）、年徽章（年边界的插值 y）、月刻度、时期条、吸顶年份（读年徽章）。
- 缩放：`k` 控制根之间的拉伸，也决定标签档位（`railLevel`）。

结论：

1. 截图中的错位不是个别现象：复位时一半事件的圆点与卡片相距超过一屏的 1/5，读者难以把日期和卡片对上。
2. 卡片顺序按家族分组，时间**不单调**（224 张卡早于前面已出现的时间）。对齐模式下时间轴会出现“回退”，等距模式没有这个问题（它按时间画，靠引线交叉表达）。这是对齐模式必须正面处理的点。
3. 复位时等距模式没有可见的时间标签，只有年徽章。对齐模式每张卡都有自己的位置，标签可以按事件记录精度显示。

## 方案方向

### 模式状态

- `PlanningWorkspace` 新增界面状态 `tableRail: "aligned" | "linear"`，默认 `"aligned"`。与 `tableZoom` 一样只存在界面状态里，不写入作品（WU-09e 原则）。切换世界线、切换视图不重置。
- 切换按钮“时间轴 对齐 / 等距”放在事件表区域右上角（浮于表格之上，不随滚动移动），只在事件表视图显示（设计稿审核第 1 轮）。

### 父事件卡片（设计稿审核第 1 轮）

- 父事件卡片占满分组框的整个宽度并贴住框顶，作为框的标题栏（高 36px，类型色浅底，下边一条分隔线）；不再在框内缩进 10px 放一张收起卡片。
- 布局：分组框顶 = 父卡片顶；子事件从父卡片下方 4px 开始；框底仍留 10px。
- 父卡片的头部中线为卡片顶 + 18px，圆点与引线对齐到这里。

### 对齐模式（新）

- 卡片布局不变（仍用 `tableLayout`，`k` 仍拉开相邻根）。
- 每个已定位事件的圆点 y = 它的卡片头 y（`card.top + CARD_HEAD`）。引线变成水平直线。
- 聚合：卡片头至少相隔 40px，不会落进 4px，聚合自然消失；规则保留不改。
- 标签：每个圆点一个标签，文字按**记录精度**（沿用 `railLabel` 路径，`level = null`），因为位置不再表示时间密度，按缩放选档位没有意义。同段内与上一个可见标签文字相同时隐藏（例如同一天的多张卡只在第一张显示日期）。
- 年徽章：同段内相邻两张卡跨越年份时，在两张卡头的中点放年徽章，文字为新年份。吸顶年份照旧读年徽章。
- 月刻度：不画。刻度表示均匀的时间位置，在对齐模式下没有对应含义；月份由标签给出。
- 时期条：在每段内，取时间落在时期内的**连续**卡片，从第一张卡头画到最后一张卡头；中间被时期外的卡打断就分成多条。
- 时间回退：同段内一张卡的时间早于上一张卡时，它的标签加 `↺` 前缀并改用弱色，title 写“早于上一事件”。轴线在此处画一段虚线。这样读者知道这里不是时间顺延，而是回到一个家族内部的更早事件。
- 缩放：+ / − / Ctrl + 滚轮仍改变 `k`，即根之间的间距；缩放值显示为相对复位的倍数（如 `100%`、`156%`），不显示档位名。

### 悬停联动（设计稿审核第 2 轮）

- 鼠标悬停在时间轴左侧的日期标签上时，该标签、对应圆点、引线和事件卡片一起高亮（与悬停圆点、悬停卡片相同，两种模式都适用）。
- 等距模式下一个标签可能属于聚合圆点，悬停时聚合内所有事件的卡片都高亮。
- 标签目前 `pointer-events: none`（`.rail`），需要像圆点一样单独开启；只开在可见标签上，不挡住滚动。
- 对齐模式下，高亮时从标签到卡片左缘画一条虚线水平参考线，不穿过卡片文字。

### 等距模式（现有）

行为与 docs/586 完全相同，只是不再是默认值。

### 切换时的滚动位置

切换前取视口顶部第一张可见卡（`firstVisible`）及其屏幕偏移，切换后恢复。卡片布局在两种模式下相同，所以卡片不会跳动，只有时间轴重画。

## 备选与取舍

| 方案 | 做法 | 取舍 |
|---|---|---|
| A（采用） | 对齐模式圆点贴卡片头，卡片顺序不变，回退用 `↺` 标记 | 分组不受影响；时间轴可能不单调，需要标记 |
| B | 对齐模式改为按时间排列所有卡片（拆开分组） | 时间单调；但分组框没法画，等于两套表格，违背“只换时间轴” |
| C | 对齐模式下按卡片序列做分段线性映射，只对单调的部分对齐 | 回退处仍错位，规则复杂，读者难以理解 |

## 不改

- 时间线视图。
- 事件目录、卡片、分组框、待定位区、段间断开。
- 等距模式的全部规则（docs/586）。
