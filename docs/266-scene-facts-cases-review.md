## 结论

**SF-01—04设计通过，可先编写RED再实施。** 覆盖实际内层完整指导、未知键净化、有界外层、完整合法字段与缺省元数据保留、非法结果拒绝和其它阶段隔离。以下为实现测试时的具体边界。

- **SF-01**：检查实际第二次生成的新增纠错部分（或最终StructuredGenerationError.feedback），不要仅在原本就列字段的完整prompt中搜索字段名。固定指导不超过250 UTF-16 code units，实际传递后13字段名完整；首轮未知键和值的哨兵不得进入新增feedback或公开错误。持续非法与不同错误轮次仍须据最终轮次分类。
- **SF-02**：通过真实controller→service生成桥链路分别记录请求与generateText次数，恢复恰好2/3、持续失败恰好2/4；第二请求instruction包含同一固定完整指导。成功逐值保留本来合法的内容，失败目标无artifact且无skip，不能将“模型确实重新生成”与本地删键混为一谈。
- **SF-03**：合法例包含全部13字段，非客观reliability配有效attribution、三引用使用正确类型目录ID；父级、原生四字段、text、证据和来源逐值比较。覆盖有父级/无父级及控制元数据省略的正例，明确错误类型、父级、facts整体缺失/非法形状、非字符串/非法Unicode、无效引用和坏证据继续拒绝。输入request及合法原值不得被原地改写。
- 未知键值为`undefined`的反例应直接送入schema或runImportAi的受控raw返回值；`JSON.stringify`会删除该键，不能用序列化后的样本声称测到了它。对其它阶段使用本来合法的请求构造，证明新指导范围只在scene entity，不以请求先行非法的失败冒充隔离验证。
- SF-04只运行受影响定向组；失败目标只读成功不能替代全文全部场景、零失败跳过、正常保存及重开逐项比较。保持R14和旧轮次原失败结论，不累计重复测试或部分进度为整书成功。

本审核未执行新增用例或认证真实导入结果。通过设计后仍须RED/GREEN、独立代码审核及实际验收。
