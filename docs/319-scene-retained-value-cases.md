## RV01：保留现值省规划，完整review仍必经

构造正常wizard1/semantic1、targets仅scene、verify待作者冲突的inferred schema2场景，当前字段/完整hash/证据匹配，无uncommitted repairs、unfinished omissions或blocked状态。通过原resolve action保留source并给合法解释；用透明计数原semanticRelated/semanticRepairs证明该受限分支未调用，而不是直接注入“通过”结果。

断言资料的完整text/facts与全部身份不变，原证据/sourceUnitIds完整合并，原resolution/解释/decisions及作者锁定值记录。先留另一pending冲突，证明只解决所选项、不发布；最后一项后通过原workflow，确实重新发送全部body/source与冻结facts，完整新解释和locks进入原review请求，最终coverage与原任务全序一致。无reconcile生成不意味着无review模型调用。

只有完整新review无冲突/遗漏且原检查全部通过后，正常wizard-next才到publish mock。不得直接设置checks/coverage/ready或跳过保存按钮。旧代码的RED应在确实到达无变化决定后，观察旧generative规划发生；setup失败、无效source版本或被草案保守限制排除的样本不算该目标RED。

## RV02：保守范围及旧工作不被跳过

小型独立反例覆盖真实field变化、inferred/b/merge（即使候选字符串碰巧相等也不扩大action白名单）、非scene/legacy/schema缺省、非inferred origin、body-body或正文修改、非wizard/组合targets及失败/未完成verify状态。每项其它前置条件合法，透明计数证明仍到原规划/拒绝路径，不在测试里替换原方法为成功结果。

source-source/a按318最终独审选择：若纳入，正控必须无另一活跃独立candidate；另active candidate明确走旧路径。若保守排除a，则只测其保持旧路径，不靠修改冲突type制造命中。

已有uncommitted repair、unfinished omission、persistent/blocked各一例保持原路径；不清任务、改done标志或通过重发现假装保留。至少一个带真实未完成repair目标的样本，证明旧目标仍传入原规划，失败时owner/磁盘不获成功credit。旧scope的完整回归复用，不复制全部兼容矩阵。

## RV03：解释、拒绝与原子性

字节/版本相同只允许省规划，不赋予解释“已消除矛盾”的结论：在后续完整review预定返回仍真实冲突或有据遗漏，确认原处理及保存阻断执行。解释中提到其它实体/关系/正文的更改不能被记录为已经实施；仍需原显式修改流程。不能以锁定现值为由禁止报告矛盾，或为了保持零生成丢弃后续修订任务。

原source版本变动、坏证据/field/native引用、缺解释、模型快照撤权、候选保存前/后失败各由已有代表性组或最小用例证明；决定的原clone/epoch/持久化边界保留。无变化分支遇失败时，原资料/决定/locks/coverage与磁盘保持原子，不发生owner未落盘credit，后rename阻断沿原门。

验证完整长text/facts、空白/CRLF/非BMP以精确值判等，不以trim、长度或hash替代资料比较；仅选中字段相同而其它业务字段变化不得命中。完整review的payload/预算/实际role模型/cap/重试/finish门照旧，场景7分钟与最终全范围验收标准不放宽。
