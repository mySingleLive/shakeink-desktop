# 503 · 识别世界观把国家、纪元、人物、概念误建为独立世界的修复方案

日期：2026-11-04。来源：用户截图（第15步“识别世界观”，已选 575/575）。顶层世界节点含国家（如某王国、某共和国）、纪元（第五纪、第四纪、第一纪）、人物（老尼尔、邓恩·史密斯、弗莱、瑞尔·比伯、安娜等）、概念（灵视、扮演）、组织（某安保公司、某修会）。同一设定（如某组织）在多个“世界”下重复出现。

用户给出的定义（以本节为准）：世界观是作品中一大群角色、国家、势力共同遵守的一整套法则、力量与等级体系、历史与基础设定构成的宇宙。区域或势力可有独有设定，但不与共有设定冲突。国家、组织属于该世界的势力；人物不是世界；概念是该世界的设定。世界可有子世界（自动继承父世界全部设定，可有独有设定）和平行世界（另一套基础法则）。约束：提示词与通用规则不得出现任何具体小说的设定或概念。

## 1. 已证原因

| 位置 | 事实 |
| --- | --- |
| `desktop/core/novel-import-ai-payload.ts:138` | 世界清单契约只有 `roster:[{name,aliases,parent?,settings:[{settingType,name}]}]` 与 settingType 取值，没有说明什么是世界、什么不是。 |
| `desktop/main/novel-import.ts:563-590` | 正文按批（第一卷 760 个单元）并发识别；每批只见一段原文，模型以本批最显眼的国家、人物、纪元或概念为 `name`，把本批设定挂在其下。 |
| `desktop/core/novel-import-wizard-roster.ts:63-74` `buildWorlds` | 每个不同的 `name` 都建一个 WORLD 候选；设定按“所属世界 + 名称”去重，因此同一设定在不同“世界”下重复。没有与已选角色比对。 |

## 2. 修改

### 2.1 清单契约给出世界定义与层级（主修复，只改世界清单提示）

`rosterEntries.world` 改为：

- 形状 `roster:[{name,aliases,relation:"main"|"sub"|"parallel",parent?,settings:[{settingType,name}]}]`。
- 定义：世界是被其中所有人物、国家、势力共同遵守的一整套法则、力量与等级体系、历史与基础设定构成的宇宙；区域或势力可有独有设定，但不与共有设定冲突。
- 一部作品通常只有一个主世界。本批内容属于它时 `relation` 为 `main`，`name` 用原文对整个世界的称呼，原文未称呼时用“主世界”。
- 国家、组织、势力、纪元、历史事件、能力、职业、概念、体系、人物、地点都不是世界。属于世界设定的内容作为所属世界的 settings 列出（势力用 FACTION，历史用 WORLD_HISTORY 等）；人物不列。
- `sub`：位于另一世界内部、继承其全部设定并另有独有设定的子世界，`parent` 填上级世界名称。`parallel`：与主世界平行、另有一套基础法则的独立世界，不填 parent。只有原文明确存在时才用 sub/parallel。
- 不含任何具体作品的名称或设定（测试逐字检查截图中的词不出现）。

角色、场景、物品清单提示字节不变；世界 entity/review/reconcile 提示不变。

### 2.2 服务端 schema

`rosterEntrySchemas.world`（`desktop/service/novel-import-ai.ts:369`）增加 `relation:z.enum(['main','sub','parallel']).optional()`。非法值仍被严格 schema 拒绝并走现有纠错；缺省不使整批失败（与 490 物品 `category` 同理）。

`relation` 作为可选字段进入 `ImportRosterEntry`、`WizardRosterEntry`、暂存拷贝（`main/novel-import.ts:575`）与草稿 strict schema 的 `rosterStash`（`core/novel-import-wizard-state.ts:33,65`）。旧草稿可直接读取。

### 2.3 本地合并（`buildWorlds`）

正文条目：

1. `relation` 缺省时：有 `parent` 视为 `sub`，否则视为 `main`（旧暂存与旧模型回复也按此解释）。
2. 名称与已选角色名称/别名（规范化后）相同的条目一律视为 `main`，其名称不参与主世界命名（防线：人物不是世界）。新增参数 `taken`，主进程传入已选角色的名称与别名。
3. 所有 `main` 条目合并为**一个**主世界候选：名称取 main 条目中出现次数最多的名称（排除第 2 条的名称；并列取先出现者），无可用名称时为“主世界”。其余 main 名称作为别名（上限 `WIZARD_ALIAS_LIMIT`）。全部 main 条目的设定和引用单元归入主世界。
4. `sub` 条目按名称成为子世界；`parent` 能解析到某世界（含主世界的任一名称或别名）时挂在其下，否则挂在主世界下（必要时创建主世界）。`parallel` 条目为顶层世界。
5. 同一世界下同名设定只保留一项，`settingType` 取各批出现次数最多者（并列取先出现者）。

资料文件中的世界（`splitWizardSourceWorlds`）不变；主世界与资料世界同名时照旧合并为同一候选。

### 2.4 不改

- 世界清单 UI、选择树逻辑、世界 entity 导入流程与并发。
- 角色、场景、物品识别与导入。

## 2R. 第一轮独立审核后的修订（以本节为准，覆盖 2.1–2.4 冲突部分）

审核见 `503-world-roster-definition-plan-review.md`，10 条全部采纳，并采用其第 5 节的简化形状。

1. **形状（覆盖 2.1/2.2 的 relation）。** `roster:[{name,aliases,parent?,parallel?,settings}]`。无 parent 且非 parallel 即属于主世界；`parent` 只用于原文明确的子世界；`parallel:true` 只用于原文明确的平行世界。schema 加 `parallel:z.boolean().optional()`；暂存、草稿 strict schema、`ImportRosterEntry`/`WizardRosterEntry` 加可选 `parallel`。契约定义文字同 2.1；主世界在原文无称呼时 `name` 写“主世界”。
2. **定位（审核 1/2，阻断）。** 服务端 `locatedRoster` 对 world 条目在名称/别名找不到时，再按各 settings 名称在本批原文中查找，命中即以该设定名为引文；都找不到才丢弃。其它类别不变。主世界由此获得 `evidenceUnitIds`，`importEntity` 能按引用单元取正文。
3. **主世界 id 固定（审核 3）。** 主世界 id 为 `wizardCandidateId('world','主世界','main')`，不随票选名称变化；世界设定 id 改为由所属世界 id 与设定名派生（`owner.id+'\0'+name`）。重试或重新识别后勾选按 id 保留。
4. **本地判定（审核 4/6/7/10）。** `taken` 只含已选角色名称与别名（新函数 `worldRosterTaken`，不含地点）。按以下顺序：
   - 名称与 `taken` 相同的条目视为主世界条目，其名称和别名都不进入主世界名称或别名；设定照常归入主世界。
   - 有 parent 的条目，名称与任一条目的任一设定同名，视为主世界条目（国家、组织被误标为子世界时回到设定）。
   - parallel 条目名称与主世界任一名称相同，视为主世界条目。
   - 主世界名称：主世界条目名称中出现次数最多者（“主世界”不参加计票，只在无其它名称时使用；并列取先出现者）。其余名称为别名，截断前的完整名称集合用于 parent 解析。
   - 子世界 parent：各批 parent 按出现次数投票；能解析到任一世界的完整名称集合（含“主世界”）则挂到该世界，否则挂主世界。成环节点（复用 `sceneParentCycleIds`）改挂主世界。
   - 没有任何主世界条目时不建主世界；需要挂主世界的子世界成为顶层。
   - 同一世界下同名设定只一项，`settingType` 按出现次数投票，并列取先出现者。
5. **资料世界（审核 8）。** 资料只产生一个顶层世界时，正文主世界并入它：用资料世界的 id；名称用资料世界名，资料世界为中性容器“世界”时用正文主世界名称。资料有多个顶层世界时，正文主世界按名称与之匹配，匹配不到则单独存在。
6. **旧草稿（审核 9）。** 已停在第 15 步的旧草稿需“返回修改选择”后重新识别才采用新规则；不做自动迁移。设定 id 改由世界 id 派生后，资料设定的 id 也变一次，旧草稿重新识别后资料设定的勾选恢复默认（第二轮审核 6，可接受）。
7. **兼容（审核 10）。** 现有 fixture（北城世界 + 子世界南巷梦境）与 `NIW-C26/C27` 会话测试行为不变，列为兼容验收。
8. **提示中的作品专有词（审核第 3 节，用户约束）。** 物品清单契约中“封印物”“途径、序列”属具体作品设定，改为通用说法：物件举例“器物、武器、文书、药剂、信物等”，itemType 举例“如武器、药剂”，概念举例“修炼路线、等级、能力、职业、体系、种族等”。新增测试：全部导入提示（各清单与 entity 提示）不含黑名单词（截图与本方案出现的作品专有词，黑名单只在测试文件中）。物品提示哈希随之改变，物品 E2E 重新验证。
9. **哈希基线。** 角色、场景清单提示保持 b26975f 基线；世界、物品提示移出该断言，另立新基线并注明提交。

## 2R2. 第二轮审核后的修订

审核见 `503-world-roster-definition-plan-review-2.md`，全部采纳：

1. 任一名称若同时是某条目的设定名或已选角色名，不参与主世界命名，也不进入主世界别名（覆盖降回的子世界与无 parent 的国家/纪元名）。
2. 资料世界合并用候选 id（只按名称派生）；多个资料文件同名中性容器按候选计为一个；正文无主世界条目而资料只有一个顶层世界时，它就是主世界，子世界挂其下；改名时原名“世界”保留为别名；`wizardCandidateBlock` 按所属世界的名称与别名查找资料世界块。
3. 子世界 parent 先解析为世界再按世界计票。
4. 识别批次的回复未完整结束、无法解析或结构不完整时，按场景识别的做法二分重发，单个单元最多 3 次（第 4 次 E2E 证实该类失败会使整步失败）；服务商、授权、来源、停止类错误仍立即结束。
5. 世界 entity 导入在接受前校验原生内容结构，不符时走既有一轮纠错（第 3 次 E2E 中“力量体系”设定内容结构不符而失败）。
