# 441 独立方案审核

结论：通过，当前仅准入 PRIVATE 合成兼容性诊断 TDD；产品须实际静态前提全部满足后才可开始 TDD，不能把本地概念验证当供应商支持。审核版本 SHA256：`8b21295a3aa8ad762f59994f5b06c08c8ea297ebffcba32edfcb1f6f462b7838`。

逐键 required 的 1..N 可以表达每个原任务的类型/局部域；typed refs 共享完整严格三分支能避免逐任务复制大 record。严格 data-property 精确键集合按冻结号反投 array，再调用原 decoder，不补值或猜号，且保留显式旧 array/repairs，程序接受门没有因新优选 wire 而放宽。键对象检查不是原 JSON 重复键扫描；保留现 parser 的边界正确。

两份静态 schema 仅编码差异、同五任务/见证/prompt/strict=true，原字段/选择/0及三 record 限制完整；真实 SDK wire、独立 tuple 与原 decoder、见证、两次硬门及现 R62 保护均为必要证据。所有 properties required 的新结构可恢复原 true 默认；不得沿用旧 optional-superset/false 的真实结论，实际条件未过不动产品。其它模型/阶段/四代/权限不改。

原来源诊断存在两种不同映射。`claim-patch.ts` 的 apply 会 flatMap 压缩内层，外层原 slot/reject 集合不能证明其内层 index；最终文已限**唯一 replacement 且内层直接对应**才精确定位，patch/多任务/歧义只旧指导。外层仍须 apply 成功、显式已验证拒绝集和完整 roster 诊断 path，不可用过滤后的行号冒原 slot。可信 resolve 的 replacement mention 索引可独立定位，未知 ref/其它失败不猜。

“可显式0”只复用原 hasSource 的保守完整包/同 file 连续跨 unit 无源事实，并限原 claimed literal、row.canReject 和当前 boundCanReject 均真；新增称呼、可能跨边界存在、入链/不可拒及非该拒因不输出。该窄补避免无据建议诱导丢来源，不改变原 reject 资格或替模型选值。全部原 source/retention/owner/关系/版本/作者门、最多六项隐私与首门顺序保持。

独立概念只测 R62 的实际32 bound/schema预算，未含未来新指令或全部历史。产品仍需130首轮+256历史代新完整预算、原92/25本地回归、独立 code review/构建与 fresh 全文/发布/重开；不抬额度、不裁材料。审核未改产品/测试、未调用 App/API。
