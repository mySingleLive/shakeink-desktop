# 564 · 保存开始后仍可停止/删除导入 总结

需求：用户 2026-11-12（附截图）。第 22 步「完成」已暂停：无法完成导入、无法保存作品，也无法停止或删除。任何条件和进度下都应允许停止并删除这次导入。

用户决定：作品已写入时，删除只删导入草稿、保留作品；保存未完成时，清理本次导入在目标目录写入的半成品。

产物顺序：方案 `560` 及审核 → 用例 `561` 及审核 `562` → TDD 实现及 code review `563` → 全量与真实目标系统验证 → 本文。

## 原因（对照用户真实草稿只读核对，未改动）

1. 目标目录只有 Finder 生成的 `.DS_Store`，建书却把它算作目录内容，保存在写入任何文件之前就失败了。
2. 第 22 步「允许并继续导入」先要求重新授权发送正文，然后运行向导；向导走到「完成」只会回到等待，从不调用保存。重启后目录还要重新授权，第 22 步也没有入口。
3. 保存一旦开始，主进程和界面都拒绝删除（截图中的「保存已开始，不能删除这次导入」）。

## 结果

- 任何阶段都能停止并删除。保存在途时，删除先等它结束；等待期间可以收起窗口，删除在后台继续。
  - 保存已完成：保留作品，只删除导入草稿，并提示作品已保留。
  - 保存未完成：服务端清理半成品。只删除预留记录所绑定目录中、清单的 requestId 与 requestHash 都相符的已知条目，作品清单最后删除，之后释放目录预留。陌生文件（含 `.DS_Store`）保留。目录中有符号链接、新旧两种清单、来源不明的作品数据或无法确认的目录锁时，整个目录不动。
  - 清理失败或被拒：导入仍然删除，并提示「导入已删除；目标目录 … 留有未完成的文件：原因」。原因只显示中文。
- 关闭窗口时，已开始保存的导入只收起，任务栏按钮保留；删除必须点「停止导入」并确认。
- 第 22 步改为「保存作品」页：显示保存目录，有「选择目录」「继续保存」「停止导入」，不再显示发送模型的说明。继续保存前校验保存计划哈希；哈希不符时提示删除后重新导入。
- 选择目录时，目录中除 `.DS_Store` 外有内容就立即拒绝。保存时目录如果已有其他文件，提示「保存目录已不是空目录…」；服务端的其他错误提示「保存作品失败，请检查保存目录是否可写后继续保存」，不再显示「核对来源、模型配置」。
- 服务端新增 `novel-import-discard`：受停止/关闭准入控制，计入在途任务统计，`stop-tasks` 和 `close` 会等待它结束。
