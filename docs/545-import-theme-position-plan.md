# 545 · 导入主题定位：精简简介、频道/题材/卖点/受众必填

日期：2026-11-11。用户要求（导入作品的主题面板）：

1. 简介要精简、概括：讲世界观、主角是什么样的人、开篇作为引子的剧情；不写中段和后续剧情；最多 15 行。
2. 频道不应为“不限”，要推断出男频或女频。
3. 题材不应为“全部”，要从导入内容推断。
4. 核心卖点、目标受众不能为空。
5. 用《诡秘之主》第一卷做真实导入测试；只导入主题即可。

在 542（未提交）的主题定位请求之上修改。

## 1. 现状与根因

- 定位请求（`importThemeProfile`，`desktop/main/novel-import.ts:1065`）失败时，主题任务仍完成，发布退回旧行为：频道、题材、卖点、受众留空，简介写入全部推断主题正文的拼接（`novel-import-publish.ts:129`，截到 5000 字）。用户截图就是这种结果。
  - 证据：q-r7/q-r8/q-r9、demo-4 四次真实运行中定位失败（`theme-profile-fail`：`模型证据无法定位（no-match）` 或 `模型返回结构不完整（artifacts.0.facts）`），读回简介 2898–3193 字、频道为空。q-r10、demo-6 成功。失败后只重跑 1 次。
- 定位回复内容合法也会被丢弃：定位请求的 artifacts 是各主题批次结果的原始并集（`found`，:1059/:1070），不同批次常返回相同短 id（`theme-1`、`theme-2`…）而名称不同。`validateSemanticLinks`（`novel-import-ai.ts:943-947`）把 request.artifacts 逐个加入实体目录，同 id 不同名即抛“模型实体标识与原类型或父级身份冲突”，修复函数因此丢弃定位项（`settingsItemValid`），回复最终失败为“模型返回结构不完整（artifacts.0.facts）”。
  - 证据：542/545 全部运行的 `theme-profile-shape` 共 10 行，4 行 reason 为 `links:模型实体标识与原类型或父级身份冲突`（含本次基线 th-base1 的两次尝试）。
  - 同一原因也让批次间同 id 的主题在采纳时互相覆盖（:940 按 id 替换）；th-base1 会话只剩 18 个主题。这一项不在本次范围，只记录。
- 定位成功时，契约允许“不限”和“全部”（`novel-import-ai-payload.ts:193`）；修复函数遇到不合法时依次删除 tags、genre、channel（`novel-import-ai.ts:1343`），删除后仍算成功，没有纠错轮。卖点、受众、简介可以缺省。
- 简介契约是“讲清主角、处境、核心冲突与看点，不剧透结局”，上限 500 字。demo-6 的简介写到了邓恩牺牲、死而复生、前往贝克兰德，属于第一卷后段剧情。
- 定位请求的正文样本只取主题引文所在单元（:1073），不保证包含开篇，模型写开篇引子缺少依据。
- 题材没有判别说明：q-r10 判为玄幻并给出“东方玄幻”子类，demo-6 判为奇幻，同一作品两次结论不同。

## 2. 推断方法的选择

调研来源：
- 百度百科“男频”：男频/女频按目标读者性别划分，起点 2005 年设女生频道后形成；男频偏成长、升级、事业，女频偏情感。
- 维基百科“诡秘之主”：起点将其归类为“玄幻”（真实标注，可作为 LOTM 对照）。
- CARP（arXiv 2305.08377）：大模型文本分类先列线索、再推理、最后给标签，零样本平均准确率比直接给标签高 1.78 个点（90.04→91.82）。

候选方案：

| 方案 | 频道 | 题材 | 优点 | 缺点 |
|---|---|---|---|---|
| A 本地规则 | 主角性别；“他/她”出现比例 | 关键词计分 | 确定、零成本 | 女频男主（纯爱）、群像会误判；题材关键词脆弱，跨题材混搭（蒸汽+克苏鲁）无法处理 |
| B 大模型直接给标签（542 现状） | 模型 | 模型 | 理解全书 | 无判别标准，结果漂移；允许“不限/全部” |
| C 大模型 + 标签定义 + 先线索后结论 + 强制必填与纠错，本地规则兜底 | 模型；失败时主角性别、代词比例 | 模型，按定义区分相近题材 | 准确且稳定；失败也不留空频道 | prompt 变长，约多 1 千 token |

采用 C。

## 3. 修改

### 3.1 定位契约（`novel-import-ai-payload.ts` themeProfileContract）

- 先写线索：`text`（≤300 字）依次写判定线索：主角性别与叙事视角、感情线比重、世界背景与力量体系、主线类型。再据此填 facts。
- channel 只能是“男频”或“女频”，不得为“不限”。附判定标准：
  - 男频：面向男性读者，多为男主视角，主线是成长、升级、冒险、事业、争霸、解谜，感情线为辅；
  - 女频：面向女性读者，多为女主视角，或以情感关系为主线（言情、宅斗宫斗、甜宠、纯爱）。
  - 主角性别与主线冲突时按主线和读者期待判断。
- genre 必须是所选频道的一个具体题材，不得为“全部”。附男频相近题材的区分：玄幻（东方或架空世界的力量体系、等级升级）、奇幻（西方式魔法或神秘学、异世界、蒸汽朋克、克苏鲁式神秘）、仙侠（修真成仙、门派）、武侠（江湖武学、无超自然体系）、悬疑（以解谜推理为主线、现实或弱超自然）、灵异（鬼怪恐怖）、科幻、都市、历史等；女频题材按名称。多种元素混合时取主线依赖的力量体系或世界观。
- sellingPoints、targetAudience、synopsis 必填。
- synopsis 新规则：3–6 句，分行，最多 15 行、不超过 300 字。内容依次是：世界观（时代、地域、力量体系）、主角（身份、处境、性格或特点）、开篇引子（故事如何开始、主角被卷入什么）。不写中段和后续剧情，不写结局、人物死亡和反转。只依据开篇正文与主题资料。

### 3.2 必填校验与纠错（`novel-import-ai.ts`）

- 定位请求的严格 schema（:560 superRefine）新增完整性检查，只作用于定位请求，不影响发布时对旧会话的解码：channel ∈ {男频, 女频}，genre 非空且不是“全部”，sellingPoints、targetAudience、synopsis 去空白后非空，synopsis 不超过 15 行。不满足时进入既有纠错轮，反馈文案指出缺哪个字段。
- `repairThemePosition` 新增两项机械修复，计入 `clearedPosition`：
  - channel 为“不限”或缺失、genre 只属于一个频道时（如“玄幻”只在男频），channel 取该频道；genre 两个频道都有（现实、轻小说）时不猜。
  - synopsis 超过 15 行时保留前 15 个非空行。
- 上限：新增请求阶段上限 `IMPORT_THEME_PROFILE_REQUEST_SYNOPSIS=300`，修复时超长按字符截断（q-r8 修订）。`importNativeProfile` 解码仍接受到 500 字（`IMPORT_THEME_PROFILE_LIMITS.synopsis` 不变），在途会话中 300–500 字的定位产物照常发布。

### 3.3 定位请求的样本与重试（`desktop/main/novel-import.ts` importThemeProfile）

- 样本 = 正文开头连续单元（按预算，最多 6 个，约 6000 字，覆盖第一章开头）∪ 主题引文所在单元，按书序。开头单元先放，预算不够时先减主题，再减开头单元（至少保留 1 个）。
- 上下文去重：context 主题按 id 去重（保留先出现的一项），再按预算加入。去重后同 id 只出现一次，`validateSemanticLinks` 不再因上下文自身冲突而拒绝定位项。
- 失败重跑：模型输出类失败（`worldEntryRerunnable`）由 1 次改为 2 次，共 3 次尝试；授权、中止、跳过仍立即结束。

### 3.4 发布（`novel-import-publish.ts`）

- 向导会话（wizardVersion 1）不再把推断主题正文拼接写入简介。定位简介存在时写定位简介；否则简介留空（原资料复制的主题仍原样写入，IQ-11b 不变）。非向导旧会话维持原拼接行为。
- 频道兜底：定位缺频道（请求三次失败，或修复后仍无频道）时，本地推断：
  1. 推断角色中 roleType 为 PROTAGONIST 的角色，gender 以“男”开头记男、以“女”开头记女；只有一种性别时取对应频道；
  2. 否则统计已导入章节正文中“他”和“她”的出现次数，一方不少于另一方 2 倍时取对应频道；
  3. 都不满足时保持原值（空，主题面板显示“不限”）。
  兜底只写 channel；genre 保持“全部”，tags 为空（genre 不做本地猜测）。dropped 记录仍提示“主题定位未能推断”。

## 6. 按审核（545-…-plan-review.md）修订

本节与前文不一致处，以本节为准。

证据路径（L5）：`/private/tmp/shakeink-quality-542/evidence/{q-r7,q-r8,q-r9,q-r10,demo-4,demo-6}/`（`quality-readback.json` 读回、`app-stderr.log` 中的 `theme-profile-fail`/`theme-profile-shape`）；545 基线 `/private/tmp/shakeink-theme-545/evidence/th-base1/`（只导入主题：定位两次都因 `links:模型实体标识与原类型或父级身份冲突` 失败，简介 1526 字 18 行，频道为空）。

- **H1 修复与纠错的衔接**：
  - 完整性检查单独成函数 `themeProfileGaps(facts)`，返回缺失项的固定文案（缺频道、缺题材、缺卖点、缺受众、缺简介）。严格 schema 的定位分支在其它检查通过后调用它，失败时 issue 文案以“主题定位缺少”开头。
  - `settingsItemValid` 对定位请求忽略这类完整性 issue（只看结构、引文、解码、链接），条目因此不会因缺字段被丢弃；`repairSettingsReply` 对定位请求总是返回修复后的文本。严格 schema 随后只报完整性问题，进入纠错轮。
  - `repairThemePosition` 的逐级清除只保留“清 tags”这一步，不再清 genre、channel。
- **H2 纠错文案**：`IMPORT_THEME_PROFILE_GUIDANCE` 改为：channel 只能为男频/女频，genre 必须是该频道的具体题材，sellingPoints/targetAudience/synopsis 必填，简介规则同契约。反馈把具体缺失项放在最前面（250 字截断）。
- **H3 失败路径**：
  - 第 3 次尝试使用精简请求：样本只含开篇单元，artifacts 为空（不带主题上下文），因此不会有链接冲突，输入最小。
  - 3 次都失败时，主进程生成本地兜底定位产物（schema 2，同一 id/name，进入会话、计划哈希和导入记录）：只有 channel，按下列顺序判定：已导入角色中唯一主角的 gender 以“男/女”开头；否则正文中单字“他”“她”计数（先去掉“其他”“其它”“他们”“她们”），一方不少于另一方 2 倍。都不满足时不生成。引文取第一个正文单元开头 20 字。
  - dropped 文案按实际结果：“主题定位未能推断，频道已按正文推断，题材、卖点与受众已留空”或原文案。
  - 真实运行统计定位成功率（每次运行记录尝试次数）。
- **H4 无定位时的简介**：不留空。推断主题正文拼接后截到 15 个非空行、300 字，截断点取范围内最后一个句末标点（。！？!?），没有句末时按字符截断。共享函数 `importThemeSynopsisFallback` 放在 core，发布与审核脚本共用。所有会话统一（替代 IQ-42 的 5000 字拼接）；原资料复制主题仍原样写入（IQ-11b）。前文 §3.4 的“简介留空”和发布时频道兜底作废。
- **M1 审核脚本**：`scripts/audit-real-novel-import.ts` 的 theme 检查改用定位简介或 `importThemeSynopsisFallback`。`scripts/audit-lotm-local-import.ts` 及 `tests/unit/lotm-local-import-audit.test.ts` 用于非向导本地导入（不发定位请求），只把期望简介改为 `importThemeSynopsisFallback(joined('theme'))`，频道等字段仍为空。
- **M2 样本算法**：`units=workingImportUnits(s)`。开篇 `head=units.slice(0,k)`，k 从 3 开始。上下文主题按 id 去重后，在 `sample=书序(head ∪ cited(themes))` 能放进预算时逐个加入（IQ-37 约束不变）。k 个开篇加零个主题都放不下时 k 减 1，直到 1；仍放不下则不发请求。
- **M3 简介截断**：修复时对超过 15 个非空行或 300 字的简介按 H4 的句末规则截断，并计入 clearedPosition。“行”指按换行切分后的非空行。
- **M4 题材定义与 LOTM 期望值**：按起点的实际归类定义：玄幻为架空或异世界中、以成体系的力量等级晋升为主线的作品（不限东西方背景）；奇幻为以西方神话、剑与魔法、魔法种族为核心而非等级晋升的作品；悬疑为以解谜推理为主线、超自然只作氛围的作品。LOTM 期望值为“玄幻”（起点归类，见维基百科“诡秘之主”）；两次真实运行都应为玄幻。
