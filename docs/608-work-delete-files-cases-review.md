## 二、问题

### 高1：WD-03 没有测试作品目录内指向外部的符号链接

永久删除最主要的误删途径，是跟随目录内的链接删到作品以外的内容。方案依赖 `removeTree` 不跟随链接，但现在没有用例能防止实现改用 `rm({recursive})` 之类的写法后出现退化。

要求：在 WD-03 的目录中加入三样东西：一个指向外部目录 X 的符号链接（X 中有文件），一个指向外部文件的符号链接，一个硬链接。断言删除后 X 的 `digest()` 不变，外部文件内容不变，链接本身已被删除。

### 高2：没有“作品根本身是挂载点”的用例

方案 §6.2 规定“不是挂载点（父目录 dev 相同）”，评审问题 2 指出这是删除整个卷的情形。WDU-01 只测了子目录 dev 不同。

要求：增加 WDU-04。注入的 `lstat` 让作品根的 dev 与父目录不同，断言预检抛出 `WORK_FILES_UNSAFE`，没有任何删除调用。WDU-01 也要分成两条：预检的全树扫描拒绝（返回 409，catalog 不变），以及删除递归中遇到 dev 不同的目录（停止，结果为 `kept`）。

### 高3：没有“锁的 pid 等于本进程，但不属于本实例的连接”的用例

评审问题 3 和方案 §6.2 第 4 步规定，关闭连接后锁仍存在且 pid 为 `process.pid` 时，一律视为正在使用，因为 Worker 与主进程共用同一个 pid。WD-14 用的是子进程 pid，所以只凭 pid 判断“本进程即放行”的错误实现也能通过所有用例。

要求：增加 WD-14b。在同一进程中创建第二个 `Workspaces`（使用另一个数据根），用它 `open` 并 `run` 同一目录，或者直接写入 `staleLock(path, process.pid)`。然后对第一个实例执行 `deleteFiles:true`，断言返回 409“作品正在使用，文件未删除”，目录摘要和锁都不变。另外补两种锁：锁目录是符号链接；锁目录内的 `owner.json` 无法解析。两者都应返回 409。

### 高4：WD-21 的构造会因为别的检查而失败，而且 `/`、主目录、引导目录的检查不能用真实路径测试

- 数据根的父目录就是 `h.base`，其中还放着其他作品的目录。伪造的这一行即使边界检查失效，也会被嵌套检查（WD-10）或身份检查（`record.identity` 不符）拒绝，所以 WD-21 无法证明边界检查有效。
- 用例中没有覆盖 `/`、用户主目录、卷根、引导目录（方案 §6.2、评审问题 10）。如果有人用伪造的 catalog 行在集成测试里对 `homedir()` 执行 `deleteFiles:true`，一旦检查失效就会删掉开发者的主目录。

要求：
- 把边界与禁止路径的判断写成纯函数，用单元测试 WDU-05 逐项覆盖：作品包含数据根、作品位于数据根内、作品包含引导目录、`/`、`homedir()`、卷根。任何测试都不能对这些真实路径执行删除。
- WD-21 改为只让边界检查失败：使用专门的 `base/outer`，数据根在 `outer/data`；在 `outer` 中写入身份一致的清单和 catalog 行，并确保 `outer` 中没有其他作品。用例中写明这个构造。

### 中1：拒绝类用例对“不变”的定义不精确

WD-07 到 WD-14、WD-16、WD-21 都只写了“409；不变”。

要求：统一写成“HTTP 409，`code` 为 `WORK_FILES_UNSAFE`（WD-16 写明对应文案）；catalog 字节不变；作品目录 `digest()` 不变；作品仍在 `/api/novels` 中；关联会话的位置不变”。至少在一条用例中预先放一个关联会话（用 `addConversation`），证明 `beforeCommit` 没有执行。WD-16 中会话已经在回滚路径上，也要断言会话不变。

### 中2：WD-17 没有锁定“提交后的异常不回滚”

评审问题 4 的缺陷是：`forgotten` 被撤销，或者返回 500。WD-17 只检查了 200 和 catalog。

要求：
- 补充断言：`run(id)` 仍报“作品不在本地目录索引中”；响应体是 `{ok:true,workId,novelId,files:'kept'}`，不含路径；`chmod 555` 的子目录之外，已被删除的条目确实被删除了，清单和锁仍在。
- `finally` 中先恢复权限，再执行 `finish`。
- 增加 WD-17b：删除过程中 guard 失败（例如在删除过程中把作品根改名，再在原位置建一个新目录），结果为 `kept`，新目录不受影响。这一条可以用单元注入实现。

### 中3：WDU 用例依赖的注入接口在方案中不存在

方案 §6.2 没有导出的删除函数，也没有定义可以注入 `lstat`、guard 的接口。WDU-01 到 WDU-03 目前无法按文档编写。

要求：用例中写明被测函数的名称和签名（例如 `removeWorkTree(root, {lstat, readdir, guard})`，返回或抛出什么），并同步写进方案。WDU-02 要给出期望的调用序列：除清单和锁以外的顶层条目，然后是锁目录、清单，最后 `rmdir` 根。WDU-03 要写明在哪一步注入失败（例如删除锁目录之前），期望哪些条目还在、哪些已经删除，以及最终 `files='kept'`。

### 中4：缺少 `lstat` 返回 `EACCES` 时的用例，`ENOTDIR` 也没有用例

方案 §6.2 规定 `ENOENT`、`ENOTDIR` 记为 `missing`，其他错误一律返回 409。

要求：增加 WD-06b，把作品父目录 `chmod 000`，断言返回 409，catalog 不变（`finally` 中恢复权限）。增加 WD-06c，把父目录换成普通文件，断言结果为 `missing`。

### 中5：集成测试没有检查服务端响应中不含路径

方案 §6.1 规定只有 `location` 返回路径。WDB-11 只检查了前端。

要求：WD-04 到 WD-18 的所有响应都断言 `text` 中不含 `record.path` 或其中任何一段目录名。WD-17 的 `kept` 响应也要检查。

### 中6：缺少竞争用例

要求：
- WD-22：同时发出两个 `deleteFiles:true`，结果是 `[200 removed, 404]`，不会出现 `kept` 或 500。
- WD-23：在 `deleteFiles:true` 的进行期间调用 `open(directoryIdentity(path))`，以及在作品目录的子目录中调用 `create`。因为有 `serialize` 队列，结果要么是 `open` 或 `create` 失败，要么是删除被拒绝；绝不能出现“catalog 中有作品，目录却已被删除”。
- WDB-13：先为作品 A 打开对话框，让 location 请求挂起，然后取消，再为 B 打开对话框。之后 A 的响应才返回。断言对话框只显示 B 的路径，DELETE 请求体中的 `path` 也是 B 的。

### 中7：浏览器夹具需要扩展，真实目标缺少不可用作品

- 当前的 `window.fetch` 只记录 `{path,method}`，不记录请求体；没有处理 `GET /api/works/location`；DELETE 只会从 `unavailableWorks` 中移除作品，健康作品不会被移除。用例要写明夹具的改动：记录 `init.body`；为 location 提供可配置的响应和闸门；DELETE 也移除健康作品。WDB-03、04 的断言用解析后的请求体做 `deepEqual`。
- 原有的 WN-49 断言了 stale-lease 提示“建议先使用‘修复作品锁’”。新对话框是否保留这条提示，方案没有说明。要先确定，再改写 WN-48'/49。
- 集成测试中 WN-10..13 对响应体做了 `deepEqual({ok,workId,novelId})`，加上 `files` 后会失败。用例的“改写既有”中要列出这一条。
- 真实目标中增加 WDR-04：用 Finder 移走作品目录，让它成为不可用作品，删除时选“是”，看到 `missing` 文案，并检查原目录（已移走）完好。WDR-02 用 shell 检查目录确实不存在、同级目录不变，并保存命令输出作为证据。

### 低1：请求体与路由的细节

- WD-04 补充以下请求体：`{}`、`null`、`{deleteFiles:false,path}`、`path` 不是字符串、请求体为空字符串但带 `content-type`。前端发送什么 `content-type`，要在用例中写明。
- WD-19 补充：`DELETE /api/works/location` 返回 400 `INVALID_WORK_ID`；`workId` 为大写 UUID 时返回 400；200 的响应体键恰好是 `workId`、`novelId`、`path`。

### 低2：拆分子用例，补充台账

- WD-09 拆成 `id` 不符和 `novelId` 不符两条。WD-11 拆成未登记的 `shakeink` 清单、`xuanxiang` 清单、应用标记三条。WD-12 写明 pending 预留用哪个夹具建立（可参考 `tests/unit/reused-import-target.test.ts` 的 RT-07）。
- 用例表要为每一条标注 `docs/requirements-traceability.json` 中的 WD-608 子项。浏览器用例已经标为“非真实目标”，这一点正确。集成测试写的“真实 PGlite”也不要被记成真实目标通过。

## 三、结论

**修改后通过。** 高1 到高4 必须在编写测试前补上：外部链接不被跟随、作品根是挂载点、同 pid 的锁、禁止路径的安全测法。这些都是方案中防止误删的依据，目前没有能区分正确与错误实现的用例。中1 到中7 应在实现前改完。低1、低2 可以和实现一起处理。
