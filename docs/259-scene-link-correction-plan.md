日期：2026-10-31。用户已明确授权当前DeepSeek接口测试。R12使用原加密身份对应的LotmVerification.app、冻结产品构建和新session：1402章、5589/5589全文识别、976场景默认全选；记录时810done、1failed，其余仍待处理，随后正常停止。失败为“场景身份与上级关系”，**本轮不通过**。

## 定位与范围

`generateImportAiJson` 对`validateIdentityLinks`的所有异常使用同一根级固定纠错信息。这一检查同时包含确认的parentId、类型身份以及characterId/sceneId/itemId类型引用。现有公开错误不能确定R12是哪一个字段，因此不宣称已确认具体坏值；也不读取或保存供应商原始响应。

当前两轮生成及一次外层纠错均可能反复得到同一句泛化提示，无法明确要求模型修复具体字段。补充仅改善**单场景entity**的固定字段反馈，不变更严格接受集合、模型参数、候选、正文/资料字段、证据或重试次数。

## 实施

在原身份/引用校验已经拒绝结果之后，比较本次唯一目标的确认父级及三个可选关联字段与完整可信目录。仅为确实不匹配的parentId或无效类型引用给出固定路径`artifacts.0.facts.<已知字段>`和固定纠错说明；不回显值、实际ID、场景名称、未知键或异常原文。父级必须等于已确认目录值（含无父级），关联外键只能为对应类型的目录ID；未知可选关联应由模型省略，相关有据内容继续完整保留于text或attribution。

若不能在这些字段确认原因，保留现有通用严格错误。模型显式错误仍拒绝，不用可信值覆盖错误值，不删除字段通过校验。不改角色、普通scene分析、review/reconcile、item/world行为。

公开诊断增加静态“关联角色引用/关联地点引用/关联物品引用”类别；父级仍使用现有身份与上级类别。主进程仅将这些完整固定消息纳入原有一次纠错白名单，保留最多2请求/4生成；网络、授权、取消、预算和保存失败不增加重试。

实现复用原`validateSemanticLinks`的实际完整目录与原失败分支：仅给已经抛出的单场景父级/三关联字段错误附固定字段枚举，原Error.message和失败条件不变；生成桥再把枚举映射为固定Zod路径/说明。不会为诊断重建另一份可能不完整的目录。静态说明由`desktop/shared/novel-import-scene-links.ts`统一供生成桥和外层纠错使用。
