# 594 · 世界线时间点悬停显示完整标题：方案与测试用例审核

审核对象：`docs/594-worldline-point-hover-title-plan.md`（下称"方案"）。只读审核，未改源码和测试。

## 实测依据

我写了一个临时 Playwright 脚本（已删除），在 zoomView 夹具和 `zoomLevels: true` 下运行。它用 `addStyleTag` 注入与方案 §1 等价的两条规则（选择器改写为 `[data-timeline-plane] > div:has(> [data-event-point][data-hot])`，因为 CSS module 类名经过了哈希），然后依次缩放到 d≈32、26、16、9.4，逐个悬停长标题时间点，记录下面这些数据：

- 悬停前后标题框的 x 与宽度：x 不变，宽度从 94 变为 288–325。说明 P1、P3 成立。
- 悬停后，沿标题水平中线每 8px 调用一次 `elementFromPoint`，结果全部落在被悬停的时间点内。
- 伸长后的标题自然压住了其他事件：d≈26 时 r3 压住卡片 r16，r15 压住卡片 r23；d≈16 时 r3 同时压住卡片 r20 和时间点 r21。这些位置的 `elementFromPoint` 都返回 r3，说明 P2 成立。
- 标题背景为 `rgb(13, 11, 10)`，即 ink 主题的 `--background`。
- 鼠标停在伸长部分的末端时，`[data-hot]` 仍然是被悬停的时间点（见 P2-1）。
- 鼠标移开后标题宽度回到 94，`data-fade` 恢复。

结论：方案的 CSS 能满足 P1–P3，z-index 的取值结果也正确。但方案对层叠关系的说明有误，有两处视觉缺口，C1 中"点击不变"的说法不准确，ZB-35 可以改用自然位置。

## P2

**P2-1 伸长后的标题会接收鼠标，C1 的"点击/双击不变"不成立，需要写明并加用例。**
悬停后整个 `span[data-point-title]` 随 `.tcard` 提到 z-index 8，被它压住的卡片区域在命中测试中归属这个时间点：
- `hoverAt` 取 `closest("[data-event-card],[data-event-point]")`（`EventTimeline.tsx:345-349`），所以鼠标在伸长部分里移动时，悬停一直留在原时间点，下面那张卡片拿不到悬停。实测鼠标停在标题末端时 `[data-hot]` 为 r3。
- 这时按下鼠标，`closest("[data-event-point]")` 命中原时间点（`EventTimeline.tsx:663`），选中的是它，不是下面的卡片，双击同理（`:664-669`）。
- 这种行为不会闪烁。标题只向右伸长（`.tpoint` 是 flex 行，`worldline.module.css:394-399`），鼠标进入时位于原来 94px 的范围内，伸长不会让鼠标离开这个时间点。离开后标题收回，下面的卡片恢复可悬停。
- 框选不受影响。框选用布局坐标 `c.left/c.width` 判断命中（`EventTimeline.tsx:690-692`），宽度来自 `pointWidth`，标题上限仍是 94（`worldline-layout.ts:64, 1309`）。

处理办法有两种：
- 把它当作"标题在最上层"的自然结果。方案需要改写 C1 的描述，并在 ZB-35 中加断言：在压住卡片的区域按下，选中的是时间点；移到空白处后再移到同一点，悬停的是卡片。
- 如果不希望伸长部分拦截鼠标，要把文字拆成两层：前 94px 照常接收鼠标，其余部分用 `pointer-events: none` 的覆盖层显示。这样就要改 TSX，超出了方案"只改 CSS"的范围。

我建议采用第一种，并写进方案。

**P2-2 被淡化的时间点悬停后，不透明衬底失效。**
`.tpoint.dim { opacity: 0.3 }`（`worldline.module.css:402`）作用在整个时间点上，衬底 `background: var(--background)` 也只剩 30% 不透明，下面卡片的文字会以 70% 透出，P2 的"不透出"不成立。`dimmed` 来自搜索等过滤（`EventTimeline.tsx:735`），用户可以悬停一个被淡化的时间点。建议二选一：
- 加 `.tpoint.hot.dim { opacity: 1 }`，悬停时恢复不透明。
- 或者明确接受"淡化的点悬停时仍是淡的"，并把它写进方案。

无论选哪种，都要加一条用例：搜索使 r3 被淡化后悬停 r3，在压住卡片的位置检查标题的实际不透明度，或比较截图像素。

**P2-3 "▸ N" 子事件数没有衬底，会叠在卡片文字上。**
`EventPoint.tsx:35` 中，`<b>▸ {kids}</b>` 排在标题之后。标题伸长后，它被推到右边很远的位置，也落在别的卡片上方，但它没有背景（`worldline.module.css:401`），会和下面卡片的文字重叠。建议把衬底规则同时写给 `.tpoint.hot > b`，或者改为给 `.tpoint.hot` 整体加衬底，两种都要注意不要移动圆点和日期。ZB-34 也应该覆盖一个带子事件数的时间点。如果 zoomView 在某一级缩放下有父事件成为时间点，就用它；没有的话说明用哪一级、哪个事件。

**P2-4 方案 §1 第 29 行对 z-index 层级的说明有误。**
`.plane` 设置了 `will-change: transform`（`worldline.module.css:286`），本身构成一个层叠上下文，`z-index: 8` 只在画布内部比较。
- 与它比较的只有家族框（0）、轨道和时长条（1）、卡片和时间点（2）、`laneItem` 2、`laneHead` 3、展开的卡片（5）和打开了菜单的卡片（9）（`:287-293, 310-311`）。
- `.selectRect`（11）、`.emptyView`（11）和 `.hoverGuide`（1）都是 `.lane` 下与 `.plane` 并列的元素（`EventTimeline.tsx:780-781`），整体画在画布之上。小地图在 `.lane` 之外（`:304`）。
- 因此"低于选择框（11）和小地图（12）"的结果是对的，但原因不是 8 < 11。悬停竖线（z 1）实际也在悬停标题之上。竖线位于圆点的 x，在标题左边，不会穿过标题，所以没有可见问题。

请把这一句改成按层叠上下文说明，避免以后有人按数字调整层级出错。

## P3

**P3-1 ZB-35 不必手动移动 DOM，可以用夹具的自然位置。**
实测 zoomView 在 d∈[20,26) 时，r3 的完整标题会压住卡片 r16；在 d∈[12,16) 时会压住卡片 r20 和时间点 r21。手动改 `.tcard` 的 top/left 有三个问题：
- React 下次渲染会把 style 写回去，悬停本身就会触发一次重渲染。
- 构造出的位置在真实布局中不一定出现。
- 无法同时证明"压住时间点"这种情况。

建议这样写 ZB-35：缩放到其中一个区间，从 DOM 中找出"被悬停时间点的完整标题框与之相交"的卡片和时间点，断言至少各有一个（或至少一张卡片），然后在相交区域用 `elementFromPoint` 比较悬停前（落在下面的元素）和悬停后（落在时间点）。另外，ZB-34 第一次 `zoomTo(12, 39)` 停在 d≈32，r3 的标题下面没有任何元素，那里每 8px 一次的 `elementFromPoint` 本来就都会命中 r3，证明不了 P2。P2 的证明应该放在 ZB-35 这种有自然遮挡的位置上做。

**P3-2 叠放卡片的 `::before/::after` 和家族框，不用另写构造用例。**
`.stackWrap` 设置了 `isolation: isolate`，它的两个伪元素 z-index 为 -1 和 -2（`worldline.module.css:374-377`），只在所在 `.tcard`（z 2）内部排序；家族框是 0（`:287`）。所以 z 8 的悬停时间点在结构上就高于它们。如果在 2.5 ≤ d < 10 的某个位置能自然出现"时间点标题压住叠放卡片"，可以在 ZB-35 中顺带验证；找不到时在方案中注明理由即可。

**P3-3 衬底在家族框内会显出一块方形。**
家族框带有 7% 类型色的渐变背景（`worldline.module.css:287-288`）。子事件时间点（例如 r2c0、r8c0）在框内悬停时，`--background` 衬底比周围略深，会显出一个圆角矩形。这不违背需求，可以接受，但真实目标截图时请看一下效果。

**P3-4 靠近画布右边缘时标题仍会被截断。**
`.lane { overflow: clip }`（`worldline.module.css:278`）会截掉超出画布的部分，标题也可能伸到小地图下面（z 12）。方案保留了原生 `title` 提示，可以兜底这种情况，建议在方案中写明保留它是为了这个场景。测试选点时也要确认标题右端在画布内。

**P3-5 鼠标移开后的那一帧。**
悬停时 ResizeObserver 会移除 `data-fade`（实测悬停期间该属性不存在），移开后要等下一次 RO 回调才加回来，中间约有一帧是截断但不渐隐。这是可以接受的。ZB-34 中检查"遮罩恢复"要用轮询（`expect(...).toHaveAttribute` 或 `expect.poll`），不要只读一次。

**P3-6 其他确认无问题的项。**
- `:has()` 从 Chromium 105 开始支持，项目的 Electron 44.6.0（`package.json:82`）满足；同文件已在用 `.tcard:has(...)`（`worldline.module.css:292-293`）。
- 选择器优先级没有冲突：时间点所在的 `.tcard` 里没有 `[aria-expanded]` 或 `details`。
- `.cardZoom` 只设置了 `position: relative`，没有 z-index，不构成层叠上下文（`:392`）。
- 被选中的时间点没有单独样式，衬底不会与选中态冲突。
- 时间拖动时 `shownHover` 为 null（`EventTimeline.tsx:553`），标题会收回，符合 C1。

## 建议补充的用例

1. 在伸长部分压住卡片的位置：按下时选中的是时间点；鼠标先移到空白处再回到该点时，悬停的是卡片（P2-1）。
2. 搜索使时间点被淡化后再悬停：压住卡片处标题可读，或按方案的决定断言不透明度（P2-2）。
3. 带 "▸ N" 的时间点悬停：子事件数不与下面卡片的文字重叠（P2-3）。
4. 某张卡片的菜单（`details[open]`）打开时悬停一个压在它上面的时间点：菜单仍在最上层，即 9 > 8。
5. paper 主题下衬底等于该主题的 `--background`（可以并入 ZB-34，传 `theme: "paper"`）。
6. 悬停后滚轮缩放：缩放锚点 `elementFromPoint`（`EventTimeline.tsx:416`）命中悬停时间点的伸长部分时，锚定该时间点，不出错。这一条可选。
