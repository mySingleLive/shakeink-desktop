# 581 · 世界线界面改版 测试用例 独立审核

审核对象：`docs/581-worldline-ui-cases.md`（对应方案修订 7）。依据：`580-worldline-ui-plan.md` 修订 7、`580-worldline-ui-plan-review.md`、`577-worldline-ui-product-design.md` §1–§15、`575-worldline-ui-research.md` §需求、设计稿 `design/worldline-redesign/`、`AGENTS.md`、`docs/implementation-boundaries.md`。另查看了现有测试 `tests/browser/planning-card-menu.test.ts`（CM-01..10）、`planning-worldline-time.test.ts`（WT-55、EC-73、EC-74）以及 `src/lib/desktop/command-scope.ts`。本次只读，没有修改任何源文件或用例。

**结论：不通过。** 大部分方案条目都有用例，单元层的排布用例（WU-15–WU-19g）写得具体。但有一处与方案直接矛盾（WU-08），有几条用例所在的测试层级观察不到它声称要测的内容（React Profiler、原生菜单点击、真实应用中的渲染计数），有若干方案条目和设计约束没有用例，真实目标系统一节也缺少新导入作品的保存位置约束。下文“必须修改”逐条列出。

## 必须修改

### F1 WU-08 与方案 §3 矛盾：非法值的计数位置
WU-08 写的是非法值“记入 `mappingWarnings`”。方案 §3 `normalizeWorldlineGrade` 一行明确写着：删除个数计入 `ImportLinesRepairs`（新增 `droppedGrades`），**不写入 `mappingWarnings`**。请改为断言 `droppedGrades` 等于删除个数，`mappingWarnings` 不增加。两条路径（`normalizeLinesReply`、`generateText` 包装器）各断言一次。

### F2 React Profiler 计数在现有浏览器测试环境中观察不到（WU-56c、WU-56h、WU-82）
现有浏览器测试的打包方式是 `define: { "process.env.NODE_ENV": '"production"' }`（`planning-card-menu.test.ts` 第 76 行）。React 生产构建默认关闭 Profiler，`onRender` 不会被调用，计数永远是 0，“渲染 0 次”会恒定通过。请在用例中写明测量手段，二选一：
- 测试包把 `react-dom/client` 别名为 `react-dom/profiling`（或使用开发构建），并先做一次正向对照（例如触发一次已知会渲染的操作，确认计数 > 0）；
- 或者改为在组件中注入测试专用的渲染计数器。

WU-82 标为“浏览器测试 + 真实应用”。安装版是生产构建，同样拿不到 Profiler 计数。请拆分：“`PlanningWorkspace` 渲染 0 次”只在浏览器的 profiling 构建中验证；真实应用只测每帧时间和长任务（用 Performance trace 或 `PerformanceObserver('longtask')`），台账分别记录。

### F3 WU-66 一条用例包含十多项检查，期望只写“均符合”
WU-66 的期望栏只有“均符合”，没有可以判断的结果。它把作用域判断的 7 个步骤、启用命令过滤、`overlapping`、改绑 `input.*` 和 `text.*`、校验脚本、⌘F 派发、原生菜单点击改派、录制和多绑定、原子转移、三组旧测试的更新都放在一条里，层级又写成“单元 / 浏览器”。这相当于用一条用例覆盖整组业务，不符合 AGENTS.md。请拆成独立用例，每条写明输入、层级和期望，至少包括：
- **WU-66a（单元）`commandScope` 七个判断步骤**：每一步给一个 DOM 结构和期望返回值。对话框内的世界线元素返回原规则的结果，不能是 `worldline`。
- **WU-66d（单元）启用命令**：`configurationFor('worldline')` 只含 `worldline`、`global`；`worldline-search` 含 `worldline`、`input`、`text`、`global`。
- **WU-66e（单元）冲突检查**：`overlapping('worldline', x)` 在 x 为 `global`、`text`、`input` 时为 true，在 `markdown`、`composer` 时为 false。`worldline.search` 与 `md.find` 共用 ⌘F 时不报冲突；改成与某个 `input.*` 或全局命令相同的按键时，原绑定原子转移，旧命令失去这个键。
- **WU-66f（浏览器）改绑后键盘仍可用**：把一个 `input.*` 和一个 `text.*` 命令改绑后，在画布上按 ←/→ 时视窗起点变化 ±1/4 视窗；目录 ↑↓ 移动当前行；小地图 ← → 生效。`DesktopCommandController` 不返回 `blocked`。
- **WU-66g（单元）菜单点击改派**：`DesktopCommandController` 的 `:51` 收到 `md.find`，当前目标作用域为 `worldline` 或 `worldline-search` 时执行 `worldline.search`；为 `markdown` 时执行 `md.find`；其它 `md.*` 照旧丢弃。真正的鼠标点击原生菜单只能由 WU-92 在真实 Electron 中验证，浏览器层不能标为通过。
- **WU-66h（单元）命令目录**：`commands.json` 中新增条目的字段值与方案 §7.5 一致；运行 `generate-command-catalogs.mjs` 后，`verify-command-catalogs.mjs` 退出码为 0；`command-catalog.test.ts`、`shortcut-settings.test.ts`、`native-command-priority.test.ts` 的新增断言写明名称。
