# 602 · 世界线事件表：缩放时卡片尺寸微调 调研

来源：用户 2026-11-24 修改要求：事件表视图缩放时，若没有触发事件卡片展开 / 收起 / 折叠等效果，看不出任何变化。约束：缩放时卡片尺寸与字体应微微变化，设最小、最大尺寸；当前尺寸为最小尺寸，最大尺寸不宜过大。基于 docs/601（工作区未提交改动，`052627a` 之上）。

用户确认（2026-11-24）：

| 问题 | 选择 |
|---|---|
| 尺寸区间放在哪里 | 复位在中间：复位视图卡片约 1.1×；缩小约 6 步到当前尺寸（最小），放大约 6 步到最大 |
| 最大尺寸 | 1.2×（标题 13 → 15.6px，单行卡高 34 → 40.8px） |
| 对齐模式放大上限 | 放大到“卡片已最大且再放大也无可见变化”处即停止（+ 按钮置灰、滚轮无效）；等距模式缩放范围不变 |
| 适用范围 | 对齐与等距两种模式；展开 / 编辑中的卡片始终原尺寸 |

## 1 现状（源码）

- 事件表缩放状态：`PlanningWorkspace.tsx:197` `tableZoom`（对数值 e，复位为 0），`tableView`（`:336`）算 k = fit × exp(e)，e 夹在 `tableZoomBounds` 的 [lo, hi]。Ctrl + 滚轮一步 ±ln 1.15（`EventTable.tsx:517`），工具栏 − / + 一步 ±ln 1.25（`PlanningWorkspace.tsx:2421`）。对齐模式读数为 `exp(e) × 100%`（`:2417`）。
- docs/601 Q1 起事件表收起卡在所有级别 `zScale = 1`（`EventTable.tsx:111`），卡片尺寸与缩放无关。
- 对齐模式（默认）`layoutK = 0`（`EventTable.tsx:129`），卡片间距恒为 `CARD_GAP` 6px，不随 k 拉伸；也不自动展开（docs/601 Q6）。所以对齐模式下一个缩放步只有在跨过分级阈值（时间点、自动折叠、隐藏，docs/600）时才有可见变化，这就是本次问题。
- 等距模式按时间拉伸根块（上限 `tableGapFor(d)`），缩放时间距会变，但卡片本身同样不变。
- 卡片缩放的机制已存在：`zoomPlan(..., scale)` → `layoutPlan.scale` → `tableLayout` 的 `zc`（`worldline-layout.ts:806`）。布局以缩放后坐标计算卡宽（`widths.slot(depth) / z`）、行数、卡高（`collapsedCardHeight × z`）与卡头（`cardHeadOffset × z`），渲染时 `z ≠ 1` 的收起卡包一层 `.tableZoom`（CSS `zoom: z`，`EventTable.tsx:423`）。docs/600 用它把卡片缩到 0.75，只要取消 `z < 1` 的限制即可放大。时间线视图有自己的 `cardScale`（`EventTimeline.tsx:202`），不受影响。

## 2 真实数据下的步数（LOTM-587-wg-r1，docs/600 r3 实测）

复位 d = 21.657（级别 2）；地板 d = 0.12（级别 6）。按 `zoomLevel`（放大离开某级需 d ≥ 阈值 × 1.15）与 ln 1.15 每步：

| 位置 | 滚轮步（相对复位） | d | 级别 | 现在可见变化 |
|---|---|---|---|---|
| 地板 | 约 −37 | 0.12 | 6 | 重要事件隐藏 |
| | −25 | ≈ 0.6 | 5 | 重要 → 时间点 |
| | −16 | ≈ 2.5 | 4 | 一般隐藏 |
| | −6 | ≈ 9.4 | 3 | 父事件自动折叠 |
| 复位 | 0 | 21.657 | 2 | — |
| | +6 | ≈ 50.1 | 1 | 一般时间点变回卡片（d ≥ 46） |
| 现上限 | 约 +53 | ≫ 160 | 0 | 对齐模式：与级别 1 外观相同 |

对齐模式下，复位以上第 1–5 步、+6 到 +53 步之间都没有任何可见变化；缩小方向 −1 到 −5、−7 到 −15 等区间同样没有。

## 3 方案选择

### 3.1 尺寸按什么变

| 方案 | 说明 | 结论 |
|---|---|---|
| 按拥挤度 d（如时间线 `cardScale`） | d 与数据密度相关，复位处尺寸随作品不同；稀疏作品复位已是最大，缩放仍无变化 | 不采用 |
| 按缩放位置 e（相对复位） | 每个作品复位都是 1.1×，每一步变化相同，与数据无关 | 采用 |

### 3.2 尺寸曲线

s(e) = clamp(1.1 + 0.1 × e / E, 1.0, 1.2)，E = 6 × ln 1.15 ≈ 0.8386（6 个滚轮步），结果取 3 位小数。

| e | 滚轮步 | s | 标题字号 | 单行收起卡高 | 组头高 |
|---|---|---|---|---|---|
| ≤ −E | ≤ −6 | 1.000 | 13px | 34px | 36px |
| 0 | 复位 | 1.100 | 14.3px | 37.4px | 39.6px |
| ≥ +E | ≥ +6 | 1.200 | 15.6px | 40.8px | 43.2px |

- 滚轮每步约 ±1.67%（字号 ±0.22px，卡高 ±0.57px），工具栏每步 ±ln 1.25 约 ±2.66%。变化细微但连续可见（卡片变宽、变高，整列位置随之移动）。
- e 为对数值，曲线在对数缩放上线性，放大与缩小每步变化一致。

### 3.3 哪些元素跟着变

| 元素 | 是否缩放 | 原因 |
|---|---|---|
| 收起卡、组头（父事件头）、层叠父事件 | 是（CSS `zoom: s`，含头像、子事件数、按钮） | 用户要求的“卡片尺寸和字体” |
| 展开卡、编辑中的卡 | 否 | 高度靠实测（ResizeObserver），编辑器、时间拖动、Markdown 都按原尺寸设计；缩放会让测高与输入错位 |
| 时间点（一行：光点 + 日期 + 标题） | 否 | 它本就是“缩小后的形态”，放大时会变回卡片 |
| 卡片间距 `CARD_GAP` 6、组头间距 4、组框内距 10 | 否 | docs/601 的等间距要求 |
| 时间轴列（日期标签、年份徽章、断档文字、圆点） | 否 | 只有卡头 y 随卡高变化，圆点与日期仍对齐卡头（布局已按 `cardHeadOffset × z`） |
| 时间线视图 | 否 | 不在本次范围 |

### 3.4 对齐模式放大上限

对齐模式下级别 0 与级别 1 外观相同（不自动展开，事件表不再缩卡），所以“再放大也无可见变化”的起点是：卡片到最大（e ≥ E）且级别 ≤ 1。

- 上限 hiAligned = min(hi, max(E, eLevel1))，eLevel1 = ln(`ZOOM_POINTS` × `ZOOM_HYSTERESIS` / d复位) = ln(46 / (gap × fit))；分级关或无中位间隔时 eLevel1 = −∞（上限为 E）。
- 真实数据：eLevel1 = ln(46 / 21.657) ≈ 0.753 < E，上限 = E，即复位以上 6 步（读数 231%）。
- 稀疏作品（复位已是级别 0 或 1）：上限 = E（6 步）。
- 密集作品（复位级别 3 以下）：上限 = eLevel1，放大到一般事件全部变回卡片为止。
- 切到等距模式恢复原上限；从等距切回对齐时，e 超出新上限的部分按现有 `tableView.clamp` 处理（显示夹住后的值，下一步从夹住的值算起）。

## 4 已知限制（需用户知悉）

- 对齐模式缩小方向：s 在 −6 步已到最小，之后仍只有跨过分级阈值时才有变化（真实数据约 −7 到 −15、−17 到 −24、−26 到 −36 步之间无可见变化）。用户的约束“当前尺寸为最小”决定了这一点；若要消除，可后续考虑让对齐模式缩小时直接跳到下一个分级阈值（每步必有变化），本次不做。
- 等距模式的拉伸量仍按 k 计算，与卡片尺寸无关；卡片变大时同一时间间隔下卡片之间的空白相应变少（拉伸上限内）。

## 6 修订 1（用户审核设计稿后，2026-11-24）

用户修改：① 缩小到最小程度（再无任何变化）后不再继续缩小，滚轮继续滚动缩放程度不变，此时开始放大应马上呈现放大效果；放大到最大同理。② 放大到一定程度时，所有事件卡片自动展开。

用户确认：

| 问题 | 选择 |
|---|---|
| 全部展开的位置 | 卡片到最大尺寸后再放大一步即全部展开，并且这是放大上限；从上限缩小一步即收起 |
| 等距模式 | 也全部展开（替换 docs/600 “不推挤才展开”的判定）；展开后继续放大仍拉开间距，直到间距不再增长才停止 |
| 缩小方向的无变化步 | 卡片已最小后，每个缩小步直接跳到下一处分级变化；放大反向逐级回来 |

以下规则替换 §3.4 与 §4 的对应内容。

### 6.1 每一步都有变化（“有效步”）

- 视觉状态 V(e) = (卡片尺寸 s，分级 level，全部展开 open，等距模式的拉伸间距是否仍在变)。一个缩放步（滚轮 ±ln 1.15、工具栏 ±ln 1.25）沿方向前进；若 V 不变，继续按同样步长前进，直到 V 变化或到达边界。到边界 V 仍不变，e 不动（这一步无效果）。
- 结果：两端到头后，滚轮继续滚不再累计 e；反方向第一步立即有变化。− / + 按钮在该方向没有有效步时置灰。
- 缩小下限 floor 落在滚轮步网格上（向复位方向取整），保证从下限放大一步就离开下限。
- 真实数据（设计稿档位表按 `zoomLevel` 回差复算）：放大方向 17 档，缩小方向 16 档；缩小经过 −6（父事件折叠）→ −16（一般隐藏）→ −26（重要 → 时间点）→ −36（重要隐藏，下限），各跳过 9 步。

### 6.2 全部展开

- 位置 eOpen = max(E, eLevel1) + 一个滚轮步，其中 eLevel1 为级别降到 ≤ 1 的位置（取到网格上）。真实数据：+7 步（读数 266%）。
- 全部展开 = 所有已定位事件、包括有子事件的父事件头；用户折叠的父事件仍为层叠卡（只展开它自己）；待定位块不展开。docs/600 §9.2 “分组头不参与”与 §9 `tableAutoOpenFits` 判定在本功能中不再使用。
- 展开中单击某张卡在本地收起（docs/600 §8.1 的 `autoClosed` 行为保留）；离开全部展开位置后清空。
- 对齐模式：eOpen 即放大上限。等距模式：eOpen 之后继续放大，间距按 k 拉伸，上限为拉伸量不再增长处（所有相邻块的拉伸都已达 `OPEN_STRETCH_MAX` 或 k 到 `tableZoomBounds.max`），具体在技术方案中定义。

### 6.3 已知限制（替换 §4 第一条）

- 被跳过的位置不能通过滚轮停留（例如真实数据 −7 到 −15 步）；这些位置本来与相邻档位外观相同，只有读数不同。
- 读数（%）在跳步时会一次变化很多（例如 43% → 11%）。
