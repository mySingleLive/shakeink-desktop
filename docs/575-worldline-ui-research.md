## 问题归纳

1. **信息密度低**：卡片必然展示全文，一屏 5–11 个事件；885 个事件无法浏览。
2. **时间不可读**：时间线视图的时间靠顶部刻度和卡片小字；事件表没有任何时间轴，只有灰色小字「第五纪 · 时点」。
3. **无导航**：事件表无法按年/月跳转；仅「待定位/延续事件」弹层可定位。
4. **时间极度不均**：96% 事件集中在 3 年内，另有 34 个散布 47 万年。线性刻度要么把远古事件挤成一点，要么把近期事件压扁 → 竖向时间带必须按「分组/分段」而非纯线性比例。
5. **工具栏杂乱**：两行 10+ 个同权重按钮，复选框与按钮混排（截图 `时期`、`时期 5`）。

## 可行方向（供头脑风暴）

- **收起态卡片**：单行「● 时间 · 标题」胶囊（高约 28–32px）；展开态复用现有卡片内容。展开状态是界面状态，不写入作品数据。
- **事件表 = 三栏**：左侧树（纪元 → 年 → 月 → 事件，可折叠，带计数）｜中间竖向时间带（刻度 + 每个事件一个圆点 + 时间标签）｜右侧卡片列。树点选 → 滚动定位 + 高亮；滚动时树同步当前位置。
- **竖向时间带刻度**：两种选择——①按事件顺序等距（每个事件一行，刻度标出年/月分界，可读性最好）；②分段线性（同组内按时间比例，跨大间隔处断轴「≈ 47 万年」）。
- **时间线视图**：保留横向画布与缩放/平移/拖拽，卡片改为收起胶囊，行高恒定，一屏可容纳数十个；点击展开为浮层或就地展开。
- **视觉**：沿用现有暖色深色主题 token（`--primary #e07a5f`、`--chart-1..5`），时期色带、发光时间点、细线刻度。
- **性能**：885 个事件全部展开时每张都渲染 `MarkdownPreview`；收起态不渲染正文即可降低成本。若仍卡顿再做虚拟列表。

## 约束与风险

- AGENTS.md：业务面板必须复用 Web 真实 React 组件（本面板本身就是 Web 组件，改的就是它）；设计稿只作审核，不进入产品；示例内容不进入正式产品。
- 不能破坏现有交互：拖拽改时间、双击编辑、「…」菜单、子事件层级、分叉冻结、时间基准切换、角色变化泳道。
- 依赖：若以 `fix/worldline-chronology` 为基础，需等它提交；否则在当前 `872303d` 上实现，纪元标签以现有 `formatTime` 输出为准。
- 树形菜单的层级需要从历法得到年/月；`years` 历法与没有年月的 `fixed` 历法要退化（如按时期或按刻度分组）。
