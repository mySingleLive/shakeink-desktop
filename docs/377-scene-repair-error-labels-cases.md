# 固定业务标签用例

1. 实际场景 JSON bridge：首答可定位坏草稿，后续持续无据 context.label 四代仍失败，错误只含预置“原文限定”；原错误 kind、finish、feedback、invalidFields 保留，次数与结果不变。
2. 来源 quote/literal、保留证明和 CF/事务坏结果各自仍拒绝，映射只用预置业务标签，不部分采用、不修改输入、原草稿或接受门。
3. 未知 feedback/任意字段与秘密哨兵不能进入 UI 文案；未知 repairs 错误保持原“响应结构”，错误根、旧 name/aliases/evidence、generic 与非 scene 路径保持原边界。
4. 先真实功能 RED，再 GREEN，独立审核后定向必要回归、tsc、build；新全文实际失败分类与原四代生成一致，不以标签改进代替全部场景验收。
