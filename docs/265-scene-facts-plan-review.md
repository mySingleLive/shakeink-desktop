# 场景资料字段集合纠错方案独立审核

日期：2026-10-31。审核者：独立子代理 `scene_hierarchy_review`。只读265方案、生成桥的facts/缺省元数据流程、原生字段表及最终语义门、controller纠错白名单；未读取真实小说、模型响应、私有journal、配置或Key，未调用模型。

## 结论

**方案可执行，可继续用例审核及RED。** 原严格最终门已经拒绝scene schema2未支持的facts键和值类型；在唯一scene entity阶段把相同集合提前表达为strictObject，只改善拒绝位置和有限纠错说明，不需要扩大或缩小最终合法集合。R14固定路径只能证明facts原生字段门失败，不能据此断言具体未知键或实际坏值；265保留该不确定性是正确的。

## 实施必须保持的边界

- 形状应覆盖`importFactFields('scene',2)`完整13字段：控制字段、coordinates、三项知识归属、三个关联引用及四个原生资料字段。不能只列四业务字段或复制一份遗漏引用/归属的短表。字段仍为可选字符串，facts对象整体仍必需；不coerce、trim、default、strip或过滤未知键，不改变合法原字符串。
- 保留原reliability/attribution检查、字符串well-formed检查、PLACE与非空parent门、完整目录及目标父级一致性、有效引用、证据和原生schema2最终校验。提前字段表不能替代这些门，也不能把非法有值内容变成缺省值后接受。
- 缺省元数据顺序保持：先允许模型省略entityType/parentId，再从可信目标目录补全；模型显式值仍在最后并经过原严格门。根场景不新增parent，缺整体facts/null/数组/数字仍拒绝。未知业务字段应由模型纠正，并将其它有据内容保留在text；应用层不得为通过校验删键或丢资料。
- 精确限定`semanticVersion=1 / analyze / entity / scene`。普通scene分析、scene roster、sceneParents父级纠错、角色/item/world、review/reconcile保持现有契约；尤其不能影响此前已修正的统一末端授权复核。
- 未知键必须使用静态strictObject错误说明，不能让默认unrecognized-keys消息带出任意键名；不输出模型值、ID、名称或异常原文。内层生成与外层纠错复用固定完整字段指导，外层仍按完整固定公开消息匹配，不扩大任意前缀或未知标签。
- `generateJSON`把每条issue.message截断到250个code unit。固定完整指导应控制在此限制内，或证明实际截断后的反馈仍保留完整字段要求；不能只验证未经过生成器的常量。最多2请求/4生成及网络/授权/取消/预算/保存错误边界不变。

## 后续用例检查点

合法例逐值保留全部13字段、完整text、有效引用与证据；分别覆盖有父级/无父级、控制字段省略补全，以及明确错误值继续拒绝。未知键和非法值放合成敏感哨兵，核对实际内层第二轮反馈及最终公开错误不含哨兵，完整合法字段说明未被截断；分别测试恢复及持续失败的精确请求/生成上限。

应保留缺facts、非法形状、非法Unicode、错误PLACE/parent、非法reliability或缺attribution、无效关联和坏证据负例，确保strictObject没有成为唯一门。最终轮次换成其它错误、网络或取消时不得误沿用旧facts分类。其它阶段用合法构造的负控验证范围，不以本来就非法的请求代替隔离证明。

本审核没有执行新增测试或认证真实导入成功。只读单目标复测可验证针对性，但不能替代新session全文全部场景、正常保存及重开逐项验收；R14和更早失败继续按原结论保留。
