# 586 · 世界线事件表视图：时间轴标签精度随缩放变化 技术方案与测试用例

来源：用户 2026-11-18 修改要求一条（附截图：事件表左侧时间轴每个点都显示 `1349年`），以及同日对缩放模型的答复。基于 docs/585（已提交 `dfff003`）与 `a8adfaf`。本文同一处给出方案与用例，按 AGENTS.md 先审核再实现。

## 用户要求与答复

| # | 内容 |
|---|---|
| R1 | 事件表视图中时间轴刻度不应只显示到年，应根据时间轴的缩放程度决定显示到年、月、日，以及一日中的上午/下午，或小时分钟 |

- 真实数据（隔离根 `~/shakeink-test-roots/worldline-ui-583`，两份诡秘之主第 1 卷导入，只读取时间字段，见 `…-evidence/rail-586/times.json`）：

## 方案（修订 3）

### 1 缩放模型：时间拉伸，单个间隔封顶

- 定义 `k`：事件表每小时（世界线单位）对应的像素数。
- 布局：每段内按根事件的**块起点** `y_i` 计算（叶子根是卡片顶，有子事件的根是分组框顶 `group.top`）：
  `y_i = max(堆叠 y, y_{i−1} + min(GAP_MAX, (t_i − t_{i−1}) × k))`。
  - 堆叠 y 即现有 `block()` 中加完 `CARD_GAP` 后的 y，包含上一块的分组、子事件、展开高度。上一块越高，堆叠 y 越大，拉伸项只在它之外起作用。
  - `GAP_MAX = 240` px（沿用原 `ZOOM_GAP_MAX` 的值）。没有封顶时，复位状态下真实数据会出现单个 9,055px（作品 A）、1,276px（作品 B）的空白（审核第 2 轮 #1）。
  - 段间断开（`railSegments`）、待定位区、子事件的排列不变。
  - 取消 `zoomGap()`、`ZOOM_GAP_PER_DAY`、`ZOOM_MIN`、`ZOOM_MAX`。
- 复位基准 `k_fit`：主段（根事件最多、且跨度 > 0 的段；根数相同时取靠前的段）的平均堆叠斜率 `(根数 − 1) × 40 / (t1 − t0)`（世界线单位）。没有这样的段时（所有段都是单点），拉伸对布局没有作用：有档位的日历取 `k_fit = 18 × scale / 月长`（世界线单位，复位为月档），只用来选档位；没有档位的日历 `k_fit = 0`，`e` 的范围为 `[0, 0]`，+ / − 都禁用。
  - 这不等于“复位时与纯堆叠相同”：间隔大于平均值的相邻根会被拉开（不超过 240px）。真实数据中整张表的 `layout.height`（含单点段与断开，两份数据的根都是叶子）：作品 A 纯堆叠 47,514px，复位 50,457px，最大缩放 100,867px；作品 B 依次为 36,234、45,048、208,834px。计算脚本与结果：`~/shakeink-test-roots/worldline-ui-583-evidence/rail-586/heights-586.ts`、`heights-586.json`。
  - 编辑事件会改变 `k_fit`，同一缩放值对应的布局会随之变化，属可接受。
- 缩放状态：`PlanningWorkspace` 的 `tableZoom` 改为对数 `e`（不取整的浮点数，复位 `e = 0`），`k = k_fit × exp(e)`。
  - 工具栏 + / −：`e ± ln 1.25`；Ctrl + 滚轮：`e ± ln 1.15`。不再四舍五入到 0.01（审核第 2 轮 #3）。
  - 夹紧到 `[ln(k_min / k_fit), ln(k_max / k_fit)]`：
    - `k_max = 60` px/小时（标签日历单位，1 分钟 = 1px），换算到世界线单位为 `60 × scale`。
    - `k_min = 18 / (8 × 年长)`（标签日历单位）；年长：公历取常量 8784（366 天），固定历取 `hoursPerDay × daysPerMonth × monthsPerYear`。没有年的日历用 `18 / (8 × 月长)`。
    - 没有档位的日历（含未映射时间基准）：`k_min = k_fit / 8`，`k_max = k_fit × 8`；`k_fit = 0` 时见上条。
    - 若 `k_fit` 落在区间外，区间扩展到包含它。
  - 封顶后总高不超过 `根数 × (240 + 块高)`，不再需要单独的高度预算。
  - 纯函数 `tableZoomBounds(tree, adapter)` 返回 `{ fit, min, max }`（都是 k）。按钮在 `e` 距边界小于 1e-9 时禁用。
- 滚轮接口（审核第 2 轮 #4、第 3 轮 #3）：`EventTable` 的 `onZoom(next, anchor)` 改为 `onZoom(stepLog, anchor)`，只报告方向（`±ln 1.15`），由 `PlanningWorkspace` 加到 `e` 并夹紧。
  - 父组件另传 `canZoomIn`、`canZoomOut`（`e` 距边界 ≥ 1e-9）。滚轮方向已到边界时，`EventTable` 像现在 `next === z` 一样直接返回，不设 `zoomAnchor`、不调用 `anchorNow`，所以不会留下过期锚点。
  - 指针锚定逻辑其余不变。
  - `EventTable` 的 `zoom` prop 改为 `scale`（即 k）。

### 2 标签档位：只由缩放决定

档位 `RailLevel = "year" | "month" | "day" | "half" | "minute"`，按以下规则选（`k' = k / scale`，标签日历单位）：从细到粗，取第一个满足 `单位长 × k' ≥ 18 − 1e-9`（`LABEL_MIN_GAP`，留浮点容差）的档位；都不满足时取最粗档。

| 档位 | 单位长（公历，有无纪年） | 单位长（固定历） |
|---|---|---|
| minute | 1 小时 | 1 小时 |
| half | 12 小时 | `hoursPerDay / 2` |
| day | 24 小时 | `hoursPerDay` |
| month | 744 小时（31 天） | `hoursPerDay × daysPerMonth` |
| year（最粗档） | — | — |

- 最粗档：有年的日历为 year；没有年（固定历 `monthsPerYear = null`）为 month。
- 没有月的日历（`years` 历、固定历缺 `daysPerMonth` 或 `hoursPerDay`）、未映射时间基准：档位为 null，标签沿用 `railLabel()`（审核第 2 轮 #6）。
- 档位整张表统一，在工具栏显示，不随段、滚动、展开变化。
- 封顶后，跨越长间隔的两个圆点在轴上相距比 `Δt × k` 近，但它们之间时间差大，文字本就不同，不影响档位。

### 3 标签文字与去重

| 档位 | 宽栏文字 | 窄栏（面板 ≤ 640px）文字 |
|---|---|---|
| year | `1349年` | 同左 |
| month | `1349年6月` | 同左 |
| day | `6月12日` | 同左 |
| half | `6月12日上午` / `6月12日下午` | `12日上午` / `12日下午` |
| minute（记录 hour） | `6月12日 14:30` | `12日 14:30` |

窄栏只在文字含上午 / 下午或时:分时省略月份；只到日的文字（如 0 点的 `约6月12日`）不变。

- **上午 / 下午**：以半天为界，公历 12 小时，固定历 `hoursPerDay / 2`。
- **时刻**：minute 档只对 hour 精度的记录显示时:分。更粗的记录在 minute 档显示 half 档的文字，不编造分钟。
  - 在 half 或 minute 档，粗精度记录的值正好在当天 0 点时，只显示到日（例如 `6月12日`），不编造上午。
- **“约”**：规则与 docs/585 相同。
  - 实际显示到的精度比记录精度细时，加前缀 `约`。精度序为 era < year < month < day < hour，上午 / 下午计为 hour。
  - `window` 事件一律加 `约`。
  - 例：年精度记录、0 点、half 档 → `约6月12日`。月精度记录、+15 小时、half 档 → `约6月12日下午`。
- **纪元精度**：纪元精度的事件仍显示纪元名（WU-19i）。
- **数值去噪**：与 docs/585 §3 相同，做法是把 `stamp()` 中求日、分钟和量化值的一段抽成 adapter 内部函数，`stamp()` 输出逐字不变。
  - 触控板在一次渲染前连续送来多次 Ctrl + 滚轮、且第一次已到缩放边界时，可能留下一个滚动锚点，之后展开卡片会跳回该卡（改前已存在，code review 第 1 次建议 1）。
- 第五纪年份超过 `ERA_MAX_YEAR` 时，沿用 `eraLabel(…, "year")`。
- **去重**（新增，可见性规则；审核第 2 轮 #5）：在同一段内按 y 顺序处理标签，维护“上一个文字” `prev`（段首为空）。
  - 比较用**宽栏文字**（`compact = false`）去掉前缀“约”后的结果（下称“键”）；`compact` 只影响显示文字，不影响键，以免窄栏省略月份后把 6/12 下午与 7/12 下午当成重复。
  - 年徽章：经过一个年徽章（`badges` 中 `kind = "year"`，`y ≤` 当前标签 y）时，`prev` 设为该徽章年份的 `adapter.yearKey(t)`，即 `${年}年`，不含纪元名（`yearText()` 含纪元名，如 `第五纪1349年`，不能直接比较）。这样 year 档在徽章旁不重复年份，取代原 `yearShown` 规则。
  - 一个标签可见，当且仅当：键 ≠ `prev`，且与上一个可见标签相距 ≥ 18px（WU-14 原规则）。可见时 `prev` 更新为它的键。
  - 因 18px 被隐藏的标签不更新 `prev`。所以紧跟其后、与它同键的标签可能显示，这是期望的：它补上了被挤掉的那个时间。
  - 选中的事件：标签总可见（原规则），并把 `prev` 更新为它的键。
  - 悬停时显示的标签只在渲染层强制显示（`EventTable.tsx:302` 原逻辑），不参与计算。
  - 键为空串的标签不可见。
- **窄栏**：`railMarks` 增加选项 `compact`，由 `EventTable` 现有的 `narrow` 判断传入，并加入 memo 依赖。
  - 宽度按 11px 字号估算（每个汉字 11px，每个数字或符号约 6.2px，另加 14px 内边距）：
    - 宽栏最长文字为 `约12月12日 23:59`（`window` 事件、hour 记录、minute 档），约 109px，可用宽度约 144px。
    - 窄栏最长文字为 `约1349年12月`，约 84px，可用宽度 82px。
  - 窄栏下 `.railLabel` 左右内边距从 7px 改为 4px，最长文字约 80px（`约12日 23:59` 与 `约1349年12月`）。面板内不使用省略号（WU-35）。

### 已知取舍

- 档位按整张表统一，不随局部密度变化。
- 圆点仍按段内首尾线性插值。拉伸后各间隔不均（有的封顶、有的被堆叠撑开），所以相邻圆点的距离与 `Δt × k` 不严格一致：
  - 比 `Δt × k` 近时，18px 规则可能隐藏个别不同的标签；
  - 比它远时，标签只是更稀疏。
- 圆点聚合（cluster）沿用主事件的时间与精度。
- 选中事件的标签不受去重限制，可能与相邻标签文字相同。
- 吸顶年份、年徽章、月刻度不随档位变化。
- 复位不再等于“纯堆叠”：间隔大于平均值的相邻根会被拉开，单个间隔不超过 240px。真实数据复位时，作品 A 与作品 B 都是上下午档（见 E 层）。
- 编辑事件会改变 `k_fit`，同一缩放值对应的布局与档位可能变化。
- 档位按 `k` 选，但圆点按段内首尾线性插值，封顶与堆叠使实际密度与 `k` 不同。真实数据主段的实际 px/小时（`heights-586.json`）：作品 A 复位 15.84（`k` 14.51）、最大 38.67（`k` 60）；作品 B 复位 2.57（`k` 2.18）、最大 13.1（`k` 60）。作品 B 在时分档时实际密度低于 18 px/小时，部分相邻标签会被 18px 规则隐藏，可见标签仍各不相同。
- 第五纪年份超过 `ERA_MAX_YEAR` 时，标签显示 `eraLabel` 文字（`…年后`），与年徽章键不同，不会因徽章去重。
- 窄栏、5 位以上年份的 month 档文字（如 `约12345年12月`，约 86px）会超出 82px 的可用宽度约 4px，不处理。

### 不改

- 时间线视图。
- 圆点位置的算法（仍按段内线性插值）、聚合、18px 可见间隔。
- `railLabel()`、`short()`、`label()`、`stamp()` 的输出。
- 目录、详情、编辑器。

## 测试用例

数据与期望值均为手算后写死。FIXED24 指固定历：一天 24 小时、一月 30 天、一年 12 个月。ERA 指有纪年公历，以第五纪为例。“块距”指相邻两个根块起点之差。

### 单元用例（`tests/unit/worldline-layout.test.ts`，新增 `RL-` 前缀）

**RL-01 `railLevel` 边界**
- ERA：
  - `k = 18/744` → month，减 1e-9 → year；
  - `k = 0.75` → day，0.7499 → month；
  - `k = 1.5` → half，1.4999 → day；
  - `k = 18` → minute，17.99 → half。
- FIXED24：`18/720` → month，`0.75` → day。
- 固定历 `monthsPerYear = null`：`0.75` → day，`1e-6` → month（最粗档）。
- 固定历 `daysPerMonth = null`、`years` 历、未映射时间基准 → null。
- 时间基准 `scale = 3`：`railLevel(k)` 等于在基准日历上取 `k/3` 得到的档位；`k = 18/744 × 3` → month（浮点结果 17.999999999999996 由容差接住）。

**RL-02 时间拉伸布局**
- 等间隔：FIXED24，20 个叶子根 `r0…r19`，每隔 48 小时一个。
  - `k = 0`：块距全为 40（与改前 zoom = 1 逐字段相同）。
  - `k = 40/48`：块距 40。`k = 80/48`：块距 80。`k = 6`：`48 × 6 = 288`，封顶后块距 240。
  - `k = 20/48`：块距 40。
- 不等间隔：`r0…r18` 每隔 48 小时一个，`r19 = r18 + 480`（`railSegments` 阈值为 `max(720, 48 × 20 = 960)`，所以不断开）。
  - `k_fit = 19 × 40 / 1344 = 0.5655`。
  - `k = k_fit`：`r0…r18` 块距 40（`48 × 0.5655 = 27.1 < 40`）；`r18 → r19` 块距 240（`480 × 0.5655 = 271`，封顶）。
- 分组根：FIXED24，`p` 在 0 小时，有子事件 `c1`（6 小时）、`c2`（12 小时）；叶子根 `q` 在 72 小时。
  - `p` 分组高 `10 + 34 + 6 + 34 + 6 + 34 + 10 = 134`，堆叠 y = 140。
  - `k = 1`：`q` 块起点 140（72 < 140）。`k = 3`：216。`k = 4`：`min(240, 288) = 240`，而 240 > 140，所以为 240。
- 展开卡：叶子根 `a` 在 0 小时，`b` 在 48 小时，`a` 展开且测得高度 120。
  - `k = 1`：`b` 在 126（堆叠 `120 + 6` 大于 48）。`k = 4`：192（`48 × 4 = 192 > 126`）。

**RL-03 `tableZoomBounds`**
- RL-02 等间隔数据：`fit = 40/48 = 0.8333`，`max = 60`，`min = 18/(8 × 8640) = 2.604e-4`。
- 时间基准 `scale = 3`：`max = 180`，`min = 7.813e-4`，`fit` 不变。
