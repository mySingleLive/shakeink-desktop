# 518 · 世界线/叙事线导入提速用例

依据 `517-lines-import-performance-plan.md`（以其审核修订为准）。合成数据，不含真实正文或 Key。单元测试文件：`tests/unit/novel-import-lines-performance.test.ts`；界面：`tests/browser/novel-import-wizard.test.ts`。

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| LP-01 | 向导世界线/叙事线请求 | 带 `executionLane:'wizard-lines-v1'`；服务层车道判定为真；`runImportGenerationLane` 进入导入通道（不占聊天长任务名额）；模型选项不变（不走轻量策略）。 |
| LP-02 | 非向导导入的世界线/叙事线、细纲(outline)、review、伏笔触点 | 无该车道；服务层带该车道但 kind/phase/intent 不符时报“导入调度通道无效”。 |
| LP-03 | 按章分批 | 每批单元整章连续（批边界只落在章边界，单章超上限除外）；所有批单元并集等于待处理单元且不重；每批字数 ≤ `ceil(总字数/31)` 与 profile 上限中较小者（单章超上限时章内切分）。 |
| LP-04 | 并行 | 64 章合成正文：世界线请求在途峰值 >1 且 ≤31；叙事线同；叙事线首个请求晚于世界线全部结算。 |
| LP-05 | 结果提交 | 全部批次完成后 coverage 覆盖全部单元，进度 `lineProgress.done===total`；artifacts 数等于各批返回之和；步骤 done。 |
| LP-06 | 跨批 id 冲突 | 两批模型都返回 id `ev-1`（不同事件）：两条均保留，id 被确定性改写为 `wl-…`/`nr-…` 且互不相同；同批 parentId/eventId 指向本批 id 时同步改写；叙事 refs 指向目录已有事件 id 时不改。重跑同一输入得到同样 id。 |
| LP-07 | lineId 规范化 | 两批 lineName 相同（含空白/全角差异）而 lineId 不同 → 规范化后 lineId 相同；不同 lineName → 不同 lineId。 |
| LP-08 | 单批模型输出类失败 | 一批首次抛“模型返回结构不完整（…）”、第二次成功 → 步骤 done，该批只多发一次。 |
| LP-09 | 证据定位失败 | 一批两次都抛“模型证据无法定位（no-match）”且单元 ≥2 → 对半拆分重做，最终 done；第二次请求带“上一次引文未通过定位校验”提示。 |
| LP-10 | 非可重跑失败/重跑仍失败 | 一批持续失败：不再发送尚未开始的批；在途批结算后成功批 coverage 保留；步骤 failed，stepError 为该错误；作者“重试”只发送未覆盖单元。 |
| LP-11 | 暂停 | 在途时暂停：在途请求被取消，步骤不标 failed；恢复后只发送未覆盖单元。 |
| LP-12 | 提示词 | 车道请求的提示含 lineName 故事线规则（worldline）/refs 必填规则（narrative）；非车道请求不含。 |
| LP-13 | 面包屑 | 向导进入世界线步骤时阶段列表第5项与当前阶段文本为“剧情”，不含“线索”。 |
| LP-14 | 回归 | NIW-C05/C11（世界线→叙事线→细纲顺序与章节范围）、C64a（伏笔引用事件/讲述）、发布映射测试全部仍通过。 |
| LP-15 | 并行合并不丢（3R-1） | 31 批几乎同时返回，各自不同事件：最终 artifacts 含全部事件，无一被后写覆盖。 |
| LP-16 | 跨批同名（3R-2/3R-3） | 两批返回同名事件、people 不同：合并为一条，沿用先提交者 id，people 为并集，无冲突；同名而 text 以外的其它字段（如 timeKind）不同：产生推迟冲突，不中断步骤。 |
| LP-17 | 同批重复模型 id | 一批内两条同 id：该批失败（服务层“模型实体标识重复”），不重命名放行。 |
| LP-18 | 不拆章（3R-4） | 每批单元的章节集合两两不交；章节从不跨批（除单章超 profile 上限）。 |
| LP-19 | 车道模型选项（3R-5） | `importGenerationModel` 对剧情车道请求返回原 `resolved`（不加 thinking disabled）；`runImportGenerationLane` 在长任务上下文内执行。 |
| LP-20 | 暂停结算（3R-7） | 暂停时有在途请求：`runLine` 在全部在途请求结算后才返回；未结算批次不计 coverage。 |
| LP-21 | 来源复核节奏（3R-6） | 40 批时来源校验次数 ≥ ceil(40/16) 且远小于 40。 |
| LP-22 | 细纲回归（3R3-7 修订） | 向导细纲（outline）仍逐批串行（在途峰值 1），请求不带车道字段。 |
| LP-07b | 来源副本 lineId（518 审核中4） | 来源复制的 worldline 保留原 lineId；推断条目 lineId 精确等于 `line-`+`importHash(NFKC 去空白 lineName).slice(0,16)`；NFKC 不折叠大小写。 |
| LP-08（3R3-1 修订） | 失败即拆分 | 多单元批次首次模型输出类失败后，紧接着的两份请求恰为按章两半，覆盖原批单元各一次，不整批重发。 |
| LP-08b | 拆分与预算上限 | 某批每次都失败：步骤失败；与该批单元相关的请求 ≤11 次。 |
| LP-09b | 结构失败拆分 | 重跑后仍“结构不完整”的批次被拆分，最终全部单元覆盖。 |
| LP-15b | 单批合并失败（518 审核高2） | 一批的合并在检查点内抛错：步骤失败；该批单元不计 coverage；其它批次 coverage 保留；无半合并条目。 |
| LP-16b/16c/16d | 跨批调和范围（518 审核高3） | 同名推断事件 people 并集、同章同名叙事点 refs 并集且 order 取较小值，均无冲突；来源副本与推断、锁定字段、narrator 不同仍为冲突；time 按包含合并。 |
| LP-17b | 同批重复 id（3R3-2） | 规范化不改 id，重复 id 留给严格校验。 |
| LP-23/23b/23c | 回复规范化（3R2-2、3R3-3、review-2 高1） | 只改形状：时间值迁入 time 标签、补 people/refs/chapterIndex/order（order 接在本章显式最大值后）、唯一角色名改为 id、未知链接与不可定位引文去掉并计数；不写 attribution，非客观且无归属的条目规范化后仍无归属（由严格规则拒绝）；有效回复原样通过。 |
| LP-24 | 批次均衡（3R4） | 最大批不大于必要值（最长章或均分值），按字数降序发送，单元集合不变。 |
| LP-25 | id 避让（3R3-4） | 生成 id 已被会话中其它条目占用时改用新 hash。 |
| LP-26 | 计数护栏（review-2 低6、低8） | 非剧情车道带 linesRepairs 报“越权内容”；全零计数报结构无效；重名角色名不改写并计丢弃。 |
| LP-27 | 慢批提前拆分（3R5） | 一批明显慢于同步其它批次时两半被发出；两半先完成则采用两半、慢请求被取消；单元全部覆盖、无重复条目。 |
| LP-28 | 原批先完成（3R5-2） | 两半已发出但原批先完成：采用原批，两半结果不写入。 |
| LP-13b | 剧情修正提示 | 第21步在 `dropped.kind==='lines'` 时显示“部分剧情关联已修正”及“标签：原因”，不显示设定修正提示。 |

真实 E2E（不计入单元）：`launch-lines.mjs`，两步合计 ≤120 s 且 done；质量对比基线 lines-r1：事件数 ≥52、不同 lineId 数 < 事件数、叙事 refs >0 且悬空 0、coverage 两步均 760/760。
