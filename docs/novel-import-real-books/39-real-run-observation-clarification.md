# 真实运行观测口径补充（待独立审核）

日期：2026-10-26。仅澄清03的辅助调用/用量观测与RB-LIFE01，不修改小说基线、十二目标、正文保真、自然冲突、实际落盘或重开要求。新的正式M02/L02生命周期运行尚未开始；旧S01失败和用量未知记录保持。

## 依据与边界

用户要求真实小说全流程和当前模型，没有要求费用核算或修改模型/重试设置。03曾额外要求逐调用用量、供应商请求身份及暂停前“用量落库”。当前生产`generateJSON`可包含一次格式纠正，`generateText`在供应商返回usage时等待`recordUsage`；取消时供应商可能不返回usage。导入适配器返回其data，未把供应商request ID、内部尝试数、tokens或cost写入本次私有检查点。因此阶段/coverage不能反推出精确调用数、账单或零费用。

此前按时间/action查全局UsageRecord已被自动审批拒绝，因为无法严格隔离到本次会话。此补充不重新查询、不绕过、不新增遥测/SQL/模型调用，不修改用户全局设置。独立审计仍只打开正常关闭后的本次作品，读取receipt绑定的novel业务表。

## 拟采用的限定修订

- 核心验收不变：实际当前模型执行全部目标与全量已选正文/事实复核；独立语义基线与实际业务数据正确；正文原字、source SHA、引用、决定传播、发布与重开均须通过。合成测试、模型自评、coverage或completed不能替代它们。
- 实际可观测的模型角色、会话/epoch、阶段、前后检查点、覆盖集合、自然冲突和时间如实记录。应用层批次标识与供应商request ID明确区分；未暴露的身份/内部尝试数/usage/cost标为不可观测，不填零或推算为真实数据。
- RB-LIFE01仍必须取得真正的在途调用窗口：运行时须定位本session/epoch的一次AI调用已经进入执行、且在暂停请求时尚未settle。阶段、spinner、检查点、编译身份和静态await顺序即使合并，也不能单独证明在途；拿不到调用级运行时证据则记未执行，不能用空闲暂停替代。暂停确认还须有本次实际停机屏障已完成、对应本地调用/工作已归零的运行时证据，不从“已暂停”文字倒推。成功产物/覆盖不得被迟到结果推进；正常退出、同session重开恢复、最终完整发布/重开和独立质量验收仍是必须项。
- 将“精确用量/账单已独立查库”从本轮功能完成的必要条件中移出，单列为**未验证的辅助观测**。源码的await顺序只是调用路径证据，不称为独立数据库用量核验，也不称供应商远端已停止计费。取消时usage缺失同样保持未知。
- 对同一可恢复错误的手工重试仍最多两次并留记录；结构/证据/语义缺陷必须保留失败、窄修复、独立审核和真实重测，不能无限随机重抽。SDK内建`maxRetries`固定为0；应用网关另有最多一次格式纠正及遵循当前配置的外层网络重试。实际内部尝试数仅在可观测时记录，不为了测试计数而改用户全局设置，不将未知次数说成符合某个上限。

这项修订仅取消原计划自行添加、当前无法安全归属且非用户目标的辅助统计前提。它不把任何未知项标通过，不减少任何小说内容、格式、篇幅、角色/设定或生命周期功能用例。待独立代理确认后，03引用本补充作为最新观测口径；审核前不据此改写任何真实结果。
