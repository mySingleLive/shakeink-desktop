## L01可复现阻断与输入字形结论

L01仍是原始178页PDF，首物理页为单张栅格封面；其余177页有独立文字台账。生产解析器在 `desktop/main/novel-import-files.ts:283` 从第一页顺序处理，在285行发现任意栅格绘制操作即抛 `PDF含无法核对全文的图像内容，请转为纯文本/OCR后重新导入`。本次实际错误与此一致；第一页拒绝位置来自错误、首图片页台账和顺序控制流的联合定位，没有注入追踪替身。第2–178页的生产解析在此执行中**未执行**，不能用独立pypdf台账代替。

独立渲染的方框问题已查明：五种中文字体都为 `GBK-EUC-H` / Adobe-GB1 supplement 2，均未嵌入字体程序、没有 `/ToUnicode`，依赖环境映射及替代字体。PDF.js中相关字体名还出现乱码。对同一原PDF、同一PDF.js6.3.289、同一CMap与渲染参数，仅把已有Arial Unicode或Songti注册到字体别名，物理页89及178的缺字方框即消失、中文可读；三种模式提取文本SHA相同，两页PDF.js与pypdf文字仅忽略空白后分别700、223字符完全一致。原PDF没有被重写。

这是环境默认字体fallback缺覆盖造成的缺字；原文件仍有字体未嵌入的可移植性限制。替代渲染不能认证原版字体外观/度量，也只对上述两页完成了视觉核验，没有宣称178页逐字视觉验收。独立字库与渲染元数据见本地 `输入核验/L01-font-render-verification.json`，对照PNG及各模式参数见 `输入核验/pdf-preview/L01-*-fontcheck-*`。

注册字体恢复独立预览，不改变生产解析器首图像封面的拒绝行为。RB-L01完整导入仍被格式入口阻断。本次5项格式组件通过、1项失败，不等于五部真实AI全流程通过，也不证明安装包资源、原生选择授权、十二目标语义、实表发布或重开验证。
