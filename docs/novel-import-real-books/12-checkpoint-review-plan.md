# 检查点恢复与有界复核请求合并方案

S01真实AI现已完成多类推断并产生实际设定。执行前检查发现两处与本轮用例直接相关的风险：

1. `ConfirmScreen`在重开/目录重新授权后发送`start`；控制器`start(...,retry=false)`会清空已有coverage/artifacts。RB-LIFE01要求已完成批次不重做，因此需先用真实持久化控制器的窄回归复现并修复。不能让恢复授权成为重做整书的触发器。
2. 当前`review`为每条设定文本分片、每个facts字段及每个证据批次分别发AI请求。完整覆盖仍须保留，但逐字段独立网络请求会使六书尤其长篇耗时极大。可合并多个待复核任务为有界请求，不减少或摘要替代任何原文/设定/事实。

限定实现范围：`desktop/main/novel-import.ts`与`tests/unit/novel-import-session.test.ts`。新增NI-S10先红：完成一个目标/批次后暂停/正常关闭、恢复同journal、原目录重新授权、通过实际`start`动作确认发送，再验证已完成目标不再次调用，源/目标改变仍按既有invalidate重算，旧授权不直接重用；最终真实发布回执仍归原session。不改用户模型/网关/源文件，不直接注入或改真实journal。

复核保留现有确定性任务键（设定ID、完整文本/facts、分片序号、证据单元hash），保留每份原始片段和字段的实际提交。合并时仅去重共享证据单元，累计源文字不超过既有budget；序列化units+artifacts设置更保守的2×budget上限，为章节/实体目录预留空间；无法装入的单任务明确失败，不能截断。所有待合并任务必须经同一次真实响应及既有证据/引用校验成功后，才原子写入各自coverage键；失败/暂停不得标覆盖，恢复只提交未完成键。不同字段仍以各自事实保留，不压成摘要，不绕过全书正文review。

新增NI-S11先红：多个文本/字段任务共享证据时实际AI调用数合并（断言一个可控小样本的明确上限），输出请求中逐项可见全部字段/首末原文、引用及末尾哨兵；所有包预算与单元不重复，失败后恢复只补未覆盖任务；不因合并漏掉大文档末字段或同实体替代值。现有NI-S02（全文/末设定覆盖）、NI-S07（在途暂停）、NI-S08（持久化恢复）为直接相关回归。只运行明确`NI-S(?:02|07|08|10|11):`名称，不运行整个测试文件或全仓。

方案/用例独立审核→红→窄实现→上述限定用例绿→独立code review→暂停当前真实会话并正常退出→构建→重新授权并继续同S01检查点→用真实检查点与模型阶段覆盖确认没有重复已完成分析。合成回归不算真实RB-LIFE01通过；正式M02/L02生命周期实测仍须执行。当前实际结果留证，不能为优化覆盖或掩盖失败而清除记录。
