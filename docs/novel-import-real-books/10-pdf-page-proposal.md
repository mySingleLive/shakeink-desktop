# 原PDF图像封面阻断的补充UI提案（未批准、未实现）

RB-FMT01实际原PDF在图像封面被保守拒绝；177页可提取正文因此无法进入完整导入。本提案保留原件与来源强校验，不删封面、不代换格式、不自动OCR，不将独立提取假作产品成功。

交互稿：`design/novel-import/pdf-pages.html`，沿用核对来源步骤。含图像页逐页显示真实原页预览、页码/文字字符数，默认不确认；用户明确勾选“图像不含需要导入的正文或设定”后才能继续。已提取的该页文字保留，图像内容明确排除并记入审计；如果图像包含正文/设定或用户不确定，继续阻断并保留草稿。全扫描/没有任何可提取正文仍提示OCR。确认和撤销与当前文件hash/身份绑定，文件变化即失效；新增来源不能继承旧确认。

拟实现边界：解析器返回完整文字页与未确认图像页台账，不静默跳过。主进程按当前fileId/页码/会话revision验证源身份并渲染单页限量PNG，renderer只获得该页位图，不能拿任意路径或整个PDF字节。使用项目已有PDF.js/@napi-rs/canvas与本地字体/CMap，保持离线，无HTTP监听，不引入视觉模型或第三方OCR。页确认作为独立来源决定存入私有journal/最终导入审计；sourceReady及每次发送/发布前均验证全部相关图像页已明确确认。预览失败/页面变化/未确认不能继续。

此为对已批准导入UI新增的状态，按原任务“HTML + 子代理审核 + 需要我审核”的门槛，须独立设计审核后请用户审核具体稿，再进入技术方案/定向用例审核及TDD；目前不改生产PDF行为。S01等无关实测继续。
