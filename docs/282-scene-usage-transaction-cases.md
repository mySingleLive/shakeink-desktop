# 场景用量事务定向用例

最终收窄：只验证导入maxWait60000，其它action省略options，timeout仍原默认。真实SQL延迟5.2s在旧导入/普通调用均成功，不证明活动超时，因此撤销UT07准入及30000要求，不计产品覆盖。UT02已增强为真实连接占用2400ms期间31并发写入，旧代码31次P2028，新代码须31次真实提交且计数准确。以下为提议历史，以本段为准。

当前按281实测修订：四个精确导入action仍为原交互事务，只显式设置maxWait60000/timeout30000。数组试验失败保留记录；不再要求数组形式。UT-01/05改为检查精确action的有界选项，其它action不传选项。UT-02沿用原条件；追加UT-07，以正式schema真实SQL延迟>5秒验证活动事务预算，并验证其它action默认仍P2028。关键提交/回滚仍以真实数据库结果判定。

- UT-01：真实 PGlite、正式 Prisma schema/适配器/recordUsage，31 个同时到达的精确导入 action，各记录一次完整用量，累计 token 和成本准确，无 P2028。
- UT-02：真实数据库被另一事务占用超过默认交互启动等待 2 秒，导入写入仍等待后原子成功；RED 必须捕获原始 P2028 并清理旧适配器遗留的等待事务，避免挂死。
- UT-03：用量中非法 novel 外键引发失败，模型引用/用量/计数全部回滚；再以合成库 tokenUsed BIGINT 溢出触发第三步失败，确认前两步也回滚。后续正常记录成功。
- UT-04：不同请求工作区记录不会串库；同一 authority 下懒事务构造不提前执行，失效 authority 拒绝写入。
- UT-05：四个精确导入 action 均覆盖，近似前缀/普通生成保留原行为；无上下文/作者与模型不匹配仍拒绝。
- UT-06：快照、action、token、cost、turn/attempt 等原有字段保真；无配置价格成本为零；失败不能伪报记录成功。

不使用 provider 或真实书稿，不用 mock 成功代替数据库提交。单元测试可补充代理/路径选择断言，关键并发、等待、回滚必须真实数据库执行。全量小说仅在定向测试/审核/构建通过后执行。
