# 597 · 放大后自动展开事件卡片 技术方案与测试用例审核

审核对象：`docs/597-worldline-auto-open-plan.md`（下称“方案”）。基于 `13f41a3` 工作区（方案文件未提交）。只读审核，未改源码和测试。

已执行：`node --import tsx --test tests/browser/planning-worldline-card-zoom.test.ts`，38 项全部通过（基线）。另用 /tmp 临时脚本直接调用 `buildFamilies` / `packFamilies` 量了几组数，脚本已删除。结果如下：

- 两个展开的叶子根，起点相距 432–439px 时，打包把第二个放到下一行（y 28 → 136）；相距 ≥ 440px 时两个在同一行。原因是家族盒左边多 6px、右边多 14px，见下文 P2-1。
- 一个时长 2000px 的叶子 a，后面 600px 处有叶子 b。收起时 b 的 y 为 96，两者都展开后 b 的 y 为 140。卡片水平间隔 180px，能通过方案的判定，但 b 被压在 a 的时长条下面一行，展开后还会再往下移。
- 父事件家族在 scale = 500/48 时，三个展开的子事件起点相距 500px，排在同一行，家族头宽 2000px。

## 结论

需求理解正确，判定放在纯函数里、状态留在 EventTimeline 本地，这两个方向可行。但方案有两处不成立，要先改再进入实现。

1. §1 说明的前提是“展开不会让视图内的卡片互相移动”，这一点不成立。判定依据的是展开前的纵向位置，而展开会改变排版，排版变了视图内的卡片也跟着变。效果每次提交后都会重算，于是可能形成循环，最终触发 React 的 “Maximum update depth exceeded”。
2. A4 的“退出”用 `auto` 是否为空来判断，有两种情况会误判为退出：视图里没有卡片，或者视图里的卡片都已手动展开。

不重叠（A2）其实由 `packFamilies` 保证，与判定无关。判定真正保证的是“视图内每张卡片各占一段时间”。测试应按这个含义写。AO-07 的边界数值有一处算错。

## P1

### P1-1 判定看的是展开前的排版，自身引起的排版变化会再次触发判定，可能无限循环

- 方案 §1 说明第 1 条写“展开只让它们向下变高，打包（增量，`home` 不变）不会让视图内的卡片互相移动”。这句话在两种情况下不成立。
  - **每个缩放帧都是全量打包，不是增量。** scale 一变，`timelineStep` 就走 `full`（`worldline-layout.ts:1679`），`packFamilies` 用 `full = prev.scale !== options.scale` 从 `PLANE_TOP` 重新逐个放置并记下新的 home（`:1479`、`:1487-1491`）。自动展开期间每一步缩放，都是按 420px 宽度和展开高度整体重新分行。只有“缩放结束、`auto` 改变”的那一次提交是增量打包。
  - **视图内的家族可以因为卡片以外的部件上下叠放。** 打包判断冲突用的是家族盒（`collides`，`:1451-1453`；`settle`，`:1464-1466`），家族盒包括时长条、家族框以及左右 6/14px 的边距（`:1385-1387`、`:1422-1423`）。实测：a 有长时长条、b 在其后 600px，卡片水平间隔 180px，能通过判定；但 b 本来就在 a 下一行，a 展开变高后，b 从 y 96 被推到 140。
- 判定第 2 步取 `family.y + piece.top`，`family.y` 是当前 `packed` 里的值（方案第 37 行）。展开以后 y 会变，原来视图内的集合 V 也就不再是判定时的那个集合。方案 §2 的“输入未变时跳过”把 `packed` 和 `open` 列为输入，`auto` 一变这两个都会换引用，所以每次提交后必然重算。
- 可以构造出循环。下面四步都发生在 `useLayoutEffect` 里的 setState 中，同步完成，不经过绘制：
  1. 收起状态下 V = {a, b}，通过判定，`auto = {a, b}`。
  2. 展开后 b 被 a 推出视图底部，按 §2“不在视图内的从 auto 移除”，`auto = {a}`，b 收起。
  3. b 收起变矮，b 下面的 d（与 b 水平相交，与 a 挤在一起）回到 home，进入视图。判定返回 null，`auto = ∅`。
  4. a 收起，b 回到 y 96，又回到第 1 步。

  每一轮都是同步的嵌套更新，超过 50 次后 React 抛出 “Maximum update depth exceeded”，整个面板进入错误边界。这种情况只在特定几何条件下出现，但真实作品有约 995 个事件、长时长事件很多，不能当作不会发生。
- 量测高度也会引起同样的反馈。第一次展开时高度用 `estimateCardHeight` 估算，`ResizeObserver` 测量后 `setHeights` 再触发一次重排（`EventTimeline.tsx:318-331`、`:287-288`）。y 又变一次，V 又可能变一次。
- 建议，两条都要做：
  - **按展开后的排版判定。** `autoOpenCards` 内部用候选集合跑一次试排：调用 `timelineStep(state.current, { ...input, expanded: open ∪ 候选, relayout: true })`，它是纯函数。V 从试排结果里取，并要求不动点成立：试排后的 V 就是候选集合（或是它的子集，且子集同样通过判定）。不成立就返回 null。这样判定的就是实际会画出来的排版，不再依赖“不会移动”的假设。
  - **只在视图或数据变化时判定，不因自身引起的变化重算。** 判定的触发键取 `(view.start, view.span, view.y, width, laneH, tree, expanded, editing, folded)`，不包含 `packed`、`heights` 和 `auto` 本身。由 `auto` 引起的重排和量测引起的重排都不触发判定。另加一道保险：同一个触发键最多改变 `auto` 一次，超过时保持当前值，并在开发构建里 `console.warn`。
  - §2“不在视图内的从 auto 移除”应改为只在触发键变化（平移、缩放）时执行。
- 测试：
  - 单元：用 a（长时长条）+ b + d 的夹具复现上面的循环，断言连续调用“判定 → 应用 → 判定”3 次后结果稳定。
  - 浏览器：同一夹具，在页面上监听 `pageerror` 和 `console.error`，缩放、平移各 20 步，断言没有 “Maximum update depth” 错误，并且 `auto` 稳定（以 `aria-expanded=true` 的数量计）。

### P1-2 A4 的“退出”用 `auto.size === 0` 判断，会误清 `autoClosed`

- 方案 §2：“`auto` 变为空集时清空 `autoClosed`”。按第 5 步，`auto` 只包含尚未展开的 id，而且 V 为空时判定返回 null（第 3 步）。下面两种情况都会让 `auto` 变成空集，但都不属于用户说的“缩小或平移到拥挤处”：
  - **视图里只剩手动展开的卡片。** 例如用户手动展开了 r5，又收起了自动展开的 r6；平移到视图里只有 r5 时，判定通过，但返回值为空，`autoClosed` 被清空；再平移回来，r6 又自动展开。这违反 A4。
  - **视图里没有卡片。** 放大到 d 远大于 lane 宽度，或者作品本身有长段空白，平移经过空白处时 V 为空，判定返回 null，同样清空。
- 建议：判定返回三态 `{ on: boolean; ids: string[] }`。`on` 表示视图内全部卡片满足间隔，这种情况即使 `ids` 为空也算“在自动展开中”。V 为空时保持上一次的 `on`，既不进入也不退出。只有 `on` 从 true 变为 false（拥挤，或者 `level ≠ 0`、`!zoomOn`、d 小于进入阈值）时才清空 `autoClosed`。
- 测试：ZB-40 补两步：手动展开 r5、收起 r6，平移到只剩 r5 后再回来，r6 仍然收起；平移到空白处后再回来，r6 仍然收起。

## P2

### P2-1 回差 12px 小于打包器的同行间距 20px，保持阶段卡片会换行跳动

- 家族盒左边减 `FAMILY_PAD_LEFT = 6`，右边加 `FAMILY_H_GAP = 14`（`worldline-layout.ts:1422-1423`，常量见 `:51`、`:1185`）。两个展开的叶子要在同一行，起点至少相距 420 + 20 = 440px（实测 439px 时换行到 y 136，440px 时同行）。
- 进入阈值 24px 对应 444px，大于 440px，进入时排版不跳。保持阈值 12px 对应 432px：在 432–439px 之间仍保持展开，但每一步缩放都是全量打包（P1-1），相邻卡片会交替落到上下两行，看起来像卡片在跳。这不算重叠，但不符合“安全间隔”的观感，也让 ZB-37 的“两两水平间隔 ≥ 24”在保持阶段不成立（方案 §4.3 已把它放宽到 ≥ 12）。
- 建议：`AUTO_OPEN_KEEP = FAMILY_PAD_LEFT + FAMILY_H_GAP = 20`，写成由这两个常量推出的值，而不是写死的数字。回差区间为 440–444px，约合缩放 0.9%。触控板捏合的小步长足以落在这个区间里，鼠标滚轮一格（×1.2）会直接跨过，能起到防抖作用。若认为区间太窄，可以把进入阈值提到 32px，而不是降低保持阈值。
- 单元测试补一条：保持阈值下两张卡片起点相距 `420 + AUTO_OPEN_KEEP`，打包后它们的 y 相同。

### P2-2 用户收起自动展开的卡片时没有设置 pinned，被点的卡片会在指针下跳开

- 工作区的 `expand` 先 `setPinnedCard(id)` 再切换（`PlanningWorkspace.tsx:2312-2315`）。pinned 的家族在增量打包时保持 home，并且最先放置（`worldline-layout.ts:1498-1506`），这是 §5.2 为了让被点的卡片不动而设计的。
- 方案的 `onExpand` 在 `id ∈ auto` 时只切换本地的 `autoClosed`，不经过工作区，pinned 仍是上一次点击的卡片。收起后增量重排，被点卡片所在家族会按 home 顺序重新 settle，可能上移；而 pinned 的那个家族（可能在别处）原地不动。
- 建议：EventTimeline 增加本地的 `pinnedLocal`，在 `autoClosed` 切换时设为 id，传给 `timelineStep` 的 `pinned` 时用 `pinnedLocal ?? pinned`。下一次工作区的 pinned 变化（任意点击）时清掉 `pinnedLocal`。不要调用工作区的 `setPinnedCard`：点击会让工作区渲染，这本身允许（不在平移、缩放帧里），但会把一个本地状态变成工作区状态，没有必要。
- 测试：ZB-40 断言点“收起”前后，r6 卡片的 `getBoundingClientRect().top` 不变（±1px）。

### P2-3 `onExpand` 的上下文覆盖必须读 ref，方案没写

- EventCard 是 `memo`，读 `WorldlineCardContext`（`EventCard.tsx:135-136`），按钮调用 `ctx.onExpand(e.id)`（`:216-218`）。方案要求覆盖值“依赖只有 `ctx`，身份稳定”，这一点正确。但 `onExpand` 要判断 `id ∈ auto` 和 `id ∉ expanded`，这两个值都会变，闭包里拿到的是旧值。
- 建议：照 `foldLive` / `foldClick` 的写法（`EventTimeline.tsx:358-363`），用 `autoLive = useRef({ auto, expanded, ctx })`，每次渲染时赋值，`onExpand` 只读 `autoLive.current`。覆盖值 `useMemo(() => ({ ...ctx, onExpand }), [ctx])`，其中 `onExpand` 取自 `useRef(...).current`。工作区的 `ctx` 只在数据、只读、草稿、人物、搜索变化时换引用（`PlanningWorkspace.tsx:306-314`），与现在一样。Provider 放在 EventTimeline 返回的 JSX 内部、包住 plane 即可；EventTimeline 自己第 158 行读的仍是外层值。
- 测试：沿用 ZB-19 的思路，在 profiling 构建里统计自动展开期间一次平移帧的 `EventCard` 渲染次数，应为 0（或者只等于新进入 vband 的卡片数）。这样能证明覆盖值没有每帧换引用。

### P2-4 判定与缩放锚点的先后顺序

- 缩放锚点在第一次提交的 layout effect 里消费并置空（`EventTimeline.tsx:453-456`）。`auto` 改变引起的第二次提交没有锚点。进入或退出自动展开的那一帧，若量测高度或 P1-1 中的叠放让指针下的卡片移动，卡片会在指针下纵向跳动。这只发生在“进入或退出”的那一帧，之后的缩放帧都有锚点。
- 建议：判定的 layout effect 放在锚点 effect 之前声明，让锚点 effect 处理最终结果。或者在 `auto` 改变时保留一份锚点（id + 屏幕 y），在下一次提交中再应用一次。方案应写明选择哪种。
- 测试：ZB-37 进入展开的那一步，鼠标停在 r6 上，断言进入前后 r6 的屏幕 top 相差 ≤ 1px。退出那一步同样断言。

### P2-5 退出后留下展开时的行位

- 缩小退出的那一帧：先按旧的 `auto` 宽度在新 scale 下全量打包，home 记录的是展开时的排版；随后 `auto = ∅` 走增量打包，各家族从这个 home 出发，只会往下 settle（`worldline-layout.ts:1504-1506`）。用户若在退出那一步停住，画面上是收起的卡片排在展开时的稀疏行位上，直到下一次缩放才紧凑。
- 建议：`auto` 从非空变为空集时让 `timelineStep` 走一次全量打包。例如给 `TimelineInput` 加一个 `repack: true`，或者在这一次清空 `state.current.packed` 的 home。方案应写明。

## P3

### P3-1 A2 的“不重叠”由打包保证，测试应按这个含义写

- 只要家族盒水平相交，打包就保证上下至少 30px（`FAMILY_V_GAP`）；同一家族内，子事件行由 `CHILD_ROW_GAP` 和 `FAMILY_ROW_GAP` 分开（`worldline-layout.ts:1409`、`:1415`）。所以“矩形不相交”在任何缩放下都成立，ZB-37 的这条断言不能证明判定生效。判定真正保证的是“视图内任意两张非祖孙卡片水平间隔 ≥ gap”。
- 级别 0 下没有时间点（`zoomBars` 在 level 0 时 bar = 0，`:1887-1891`），也没有隐藏事件。堆叠卡片只来自用户折叠，展开后按 420px 的叶子处理，试排已经覆盖。这三项不需要额外处理，方案可以写明。
- 卡片上方的日期标签是卡片外的 `.stamp`（`worldline.module.css:299`，`bottom: 100%`）。纵向空间由 30px 和 `FAMILY_CHILD_TOP = 22` 留出，水平方向不超过卡片宽度。真实应用驱动判断“相交”时应把 stamp 的矩形算进去，否则会漏掉标签被压住的情况。
- 120px 的小地图（`worldline.module.css:304`，z-index 12）会盖住右下角展开的卡片。展开后卡片更高，盖住的机会更多。这不是卡片之间的重叠，记入“已知限制”即可。

### P3-2 “全部展开 / 收起”按钮的观感

- 按钮只看 `openCards`（`PlanningWorkspace.tsx:2578-2579`）。自动展开期间点“全部收起”，`openCards` 被清空，但视图内的卡片仍然展开，用户会以为按钮没起作用。C1 规定按钮不变，这样做没错，但应在 §3 写明，并加一条用例说明这是有意为之。

### P3-3 进行中事件的时长条宽度为 Infinity，不计入家族盒

- 进行中事件的时长条宽度是 `Infinity`（`:1385`），计算家族右边界时被 `finite` 过滤掉（`:1421`）。实测展开的进行中叶子 a 与 600px 后的 b 在同一行，a 的时长条从 a 底部（y + 78）一直画到 b 卡片底边附近。这是现有行为，与本方案无关，但展开后条的位置下移，与后面卡片贴得更近。可以记入已知限制。

### P3-4 测试用例

- **AO-07 数值错误。** gap 为 12、判定用 `≤` 时，起点相距 432px（420 + 12）已经满足，431px 返回 null。方案写的是“433 返回 id，432 返回 null”，与第 4 步的公式矛盾。若按 P2-1 改为 20，应写成 440 返回 id、439 返回 null。AO-01 的 443 / 444 正确。
- **ZB-37 的 d ≥ 900 没有覆盖阈值。** zoomView 中 r2、r8 的子事件相距 48 h（`tests/helpers/worldline-zoom.ts:25-27`），r4 的子事件相距 48 h（`:28-29`）。要让这些子事件在一行里展开，需要 48·s ≥ 444，即 s ≥ 9.25 px/h，d ≥ 6660。r4 展开后家族头右边界约为 `r4 + 96s + 434`。d = 500 时视图以 r6 为中心，左边界约为 r6 − 570，r4 家族已伸进视图，判定返回 null；d = 900 时不会。因此 d ≥ 900 且瞄准 r6，确实只剩 r5–r7 这几个叶子，ZB-37 能算出来；但它离阈值 444 很远，“两两间隔 ≥ 24”这条断言的余量是 480，测不出边界。建议：
  - 另加一个只有叶子根的小夹具（例如 `zoomView` 加 `{ leavesOnly: true }`，8 个叶子，间隔 720 h），在浏览器里验证：d ∈ [444, 460) 时展开；从这里缩小到 d ∈ [432, 440)（按最终的保持值）时仍展开；再到 d < 430 时收起。`zoomTo` 的细步长为 ×1.009（`planning-worldline-card-zoom.test.ts:37-52`），能落进这些区间。
  - 一个 d ≥ 6660、瞄准 r2 的用例：r2 家族头和三个子事件全部展开，子事件 k0、k1 的水平间隔为 24 ± 1px（k1 起点 = k0 起点 + 444，k0 右边界 + 10 = k0 起点 + 430，二者同行）。这一条对应 AO-05 的浏览器版。
- **ZB-39** 用 r2 当拥挤区可行：d = 900 时子事件相距 60px。但从 r6 平移到 r2 要水平滚动约 3600px，用例应写出平移步数或改用目录定位。注意定位会让工作区渲染，不能放在 ZB-41 的计数区间里。
- **ZB-42** 成立：旧用例默认 `zoomLevels: false`（`tests/helpers/worldline-browser-fixture.ts:108`），`zoomOn` 为 false。产品默认（不加 Provider）为开启，应加一条 `zoomLevels: "default"` 的用例确认会自动展开（参照 ZB-21）。
- **缺少的用例：**
  - P1-1：循环夹具，确认没有 “Maximum update depth” 错误。
  - P1-2：只剩手动展开的卡片，以及经过空白处，两种情况都保持 `autoClosed`。
  - P2-2：收起时卡片不动。
  - P2-3：平移帧中 EventCard 不重渲染。
  - P2-4：进入和退出时锚点卡片不动。
  - 编辑：自动展开期间双击进入编辑，保存后缩小退出，它仍展开（§3 的说明）；编辑中的卡片不受拥挤判定影响。
  - 选择：自动展开期间框选、单击选择不改变 `auto`。
  - 两个面板：各自独立判定，参照 ZB-24。
  - 事件表往返：切到事件表再切回时间线，`autoClosed` 丢失后的行为（EventTimeline 卸载时本地状态清空），要写明期望。
- **真实应用驱动 §4.3：** “无相交”应按 `.tcard` 加 `.stamp` 的合并矩形计算（P3-1）。另外要记录每一步 `aria-expanded=true` 的数量连续 3 帧是否稳定，用来发现 P1-1 那种循环。

## 简化建议

1. 判定直接在 `timelineStep` 的试排结果上做（P1-1），第 1 步的“候选家族 + `OPEN_CARD_WIDTH` 左扩”和第 2 步的“沿用当前 y”都可以删掉，范围就是试排后 kind = card 的元素。
2. 判定只由视图和数据变化触发，`auto` 和量测高度不进入触发键。
3. 回差取 `FAMILY_PAD_LEFT + FAMILY_H_GAP`，与打包器的同行条件一致。
4. 退出由三态的 `on` 决定（P1-2），不看 `auto` 是否为空。

## P1 摘要

- **P1-1**：判定依据的是展开前的纵向位置，而展开会改变排版：每个缩放帧都全量打包，时长条或家族盒也会让家族上下叠放。判定又在每次提交后重算，`auto` 可能在 layout effect 中无限切换，触发 React “Maximum update depth exceeded”。应在试排后的排版上判定并要求不动点，且只由视图和数据变化触发。
- **P1-2**：A4 用 `auto` 是否为空判断退出，视图里只有手动展开的卡片或经过空白处时会误清 `autoClosed`。应改为三态 `on`，V 为空时保持原状态。
