# 595 · 小地图分段方案 独立审核

审核对象：`docs/595-worldline-minimap-segments-plan.md`。只读源码和测试，没有改源码或测试。

依据：
- 重新运行 `node --import tsx /tmp/mini-calc.test.ts`，结果与方案表格一致：30 段，间距 406px，18 对重叠，371 个根事件中 109 个画在别的段里。
- 在 /tmp 写了原型脚本（已删除），按方案第 1–4 条实现，对 /tmp/mini-data.json 在 W = 420、200、54 下计算。另外用 `tests/helpers/worldline-f60.ts` 的 f60 复算了现有浏览器用例用到的分段。

## 结论

原因分析正确。原型验证了方案第 1–4 条：三种宽度下都没有标记画到别的段，toX 单调，宽度总和等于 W。但方案写的"`toT` 不变"会让拖动和点击小地图出错（P1）。另有两处需要改：时间范围仍按家族结束扩展，空白没去掉；MIN 循环有除零风险（P2）。两处都有更简单的写法。改完 P1、P2 后可以进入测试用例阶段。

## P1

### P1-1 `toT` 必须跟着改，否则点击、拖动视窗框会跳到别的段

`toT` 找段用的是固定常量（`src/lib/planning/worldline-layout.ts:1754`）：

```ts
const g = segments.find((g) => px <= g.x0 + g.width + MINIMAP_GAP / 2) ?? segments[segments.length - 1];
```

方案把间距改成 `min(14, 0.2W/(n−1))`，30 段、W = 420 时间距为 2.90px，而 `toT` 仍按每段右边多 7px 判断。后一段只有 4px 宽时，它的整段像素都被算进前一段，再夹到前一段的 `t1`。原型结果如下：

| W | 段中点经 `toT` 落到别的段 | `toT(toX(根事件开始))` 误差 > 1 小时 |
|---|---|---|
| 420 | 30 段中 21 段 | 371 个中 91 个 |
| 200 | 27 段 | 235 个 |
| 54 | 29 段 | 367 个 |

把 7 改成 `gap / 2`（实际间距的一半）后，三种宽度下这两项都是 0。

影响：`moveMini`（`EventTimeline.tsx:482-484`）用 `toT` 把指针位置换成视窗开始，`frameLeft/frameRight`（`EventTimeline.tsx:551`）用 `toX` 画框。两者不一致时，点击某段会跳到前一段的末尾，拖动时框也不跟着指针走。

现有用例都发现不了这个问题。WU-20（`tests/unit/worldline-layout.test.ts:489-505`）只有 2 段，间距仍是 14px。f60 的 5 段间距 `min(14, 84/4) = 14`，宽度 9.3/9.3/9.3/9.3/326.7，没有段触发 MIN，所以 WU-56、TL-R8 不受影响。MM-01 没有测 `toT`。MM-02 只有 3 段，间距 `min(14, 42) = 14`。

要求：方案第 4 条写明 `toT` 用实际 `gap / 2` 判断段界，并补 P2-3 中的用例。

## P2

### P2-1 时间范围仍按家族结束扩展，段内空白只去掉了一部分

方案第 3 条取 `e = min(段内家族结束, 后一段的 a)`。这样有长事件的段，显示范围会一直延伸到后一段开始，事件开始仍挤在段的左边。原型在 W = 420 下统计每段"首末标记距离 / 段宽"：

- 按方案：各段平均 35%，个别段只有 7%、10%、19%。
- 只用根事件开始（`t0 = a − pad`，`t1 = z + pad`，再按中点夹住）：所有多事件段都是 93%，2px 格子占用 137/210（按方案是 116/210）。

小地图只画根事件开始的标记（`EventTimeline.tsx:821-823`），段框也只代表这一段。家族尾部落在段间空档时，按方案第 4 条本来就映射到前一段的右端，不需要把它算进段的范围。只有一段时也一样：长事件会把这唯一一段压到左端。"段内只有长持续事件"的情况也属于这里：标记挤在段的左边。

建议：去掉 `e`，`t1 = min(z + pad, (z + 后一段 a) / 2)`，`pad = max(dayHours, (z − a) × 4%)`。这样更简单，也直接解决方案原因 3。`familyEnd` 在小地图里就不再需要。

### P2-2 MIN 循环可能除零，得到 NaN 宽度

方案第 2 条的循环在一般情况下会结束：每轮至少多固定一段，否则停止，最多 n 轮。原型在 420/200/54 下分别跑了 2/3/5 轮，总和都是 W。

但在窄面板或段数很多时，`MIN = usable / n`。剩下最后一段未固定时，它分到 `usable − (n−1)·MIN`。浮点误差可能让这个值略小于 MIN，于是这段也被固定，下一轮"剩余事件数"为 0，按比例分配变成 0/0 = NaN。NaN 会写进 `left/width` 样式和 `toX`。

建议用闭式写法代替循环：`width_i = MIN + (usable − n·MIN) × count_i / total`。它一步得到结果，总和精确等于 `usable`，每段至少 MIN，不会除零。代价是比例略被拉平：420 宽时多事件段每段少约 4px，可以接受。如果坚持用循环，必须在剩余事件数为 0 时停止，并用误差容限比较。

### P2-3 用例不足以覆盖 P1 和窄面板

需要补充：

- **MM-01 加 `toT`**：对每个根事件开始，`|toT(toX(t)) − t| < 1 小时`；每段中点 `toT(x0 + width/2)` 落在本段 `[t0, t1]` 内；`toT` 在 [0, W] 上单调。W 取 420 和一个窄宽度（例如 120，此时 30 × 4 > usable，MIN 生效），后者同时覆盖 P2-2。
- **新增 MM-04 边界情况**：0 段（`toX`/`toT` 返回 0，`segments` 为空）；1 段（间距 0，宽度 = W）；所有根事件同一时间（`t1 − t0 = 2 × dayHours > 0`）；W 很小，例如 30 段、W = 30（宽度都是有限值，总和等于 W）。
- **MM-02 改用多段**：要有 MIN 生效、间距小于 14 的分段，否则测不到 P1。"长事件跨到第三段之后"这个场景保留。
- **浏览器用例**（`tests/browser/planning-worldline-timeline.test.ts`）：现在没有多段的浏览器用例，f60 只有 5 段，测不到间距和 MIN 的变化。需要一个约 30 段的 fixture，检查以下几点：
  - 点击第 k 段段框中点后，`aria-valuenow` 落在该段时间内；
  - 从左到右拖动视窗框，`aria-valuenow` 不减，框的左边与指针相差不超过 2px（落在空档时允许贴到段边）；
  - 每个 `[data-minimap] i` 都在自己段的 `u` 内。
- **真实目标**：方案只读 DOM 标记，还应在构建版里点击、拖动小地图，检查视窗跟着移动，并在窄面板（容器 < 640px，`worldline.module.css:365`）下截图。"有标记的段框占 30/30"太弱：现在的实现标记也都在各段附近，只是段宽接近 0。应改成断言每个标记都在自己的段框内，并比较 2px 格子占用数（修改前 30，按 P2-1 修改后约 137）。

## P3

- **aria 值**（`EventTimeline.tsx:795-796`）：`aria-valuemin/max` 取首段 `t0`、末段 `t1`。按 P2-1 只用根事件开始后，`aria-valuemax` 会变小，视窗停在最后一个家族的尾部时 `aria-valuenow` 可能超过 `valuemax`。这个问题现在已经存在：`view.start` 本来就不受限制。WU-69（`tests/browser/planning-worldline-regression.test.ts:170-173`）只检查属性存在，不会失败。建议 `aria-valuemax` 取 `max(末段 t1, view.start)`，或者接受现状并在方案里写明。除此之外，没有其他代码读 `segments[].t0/t1`。用 grep 查 `src` 和 `tests`，`minimapModel` 只被 `EventTimeline.tsx:481` 和 WU-20 使用。
- **间距 2.9px 太窄**：段框圆角 4px（`worldline.module.css:307`），2.9px 的间距肉眼几乎分不出两段。可以考虑间距下限 2px，并在真实目标截图时确认。不影响正确性。
- **方案第 3 条"且 `t1 ≥ z`"多余**：中点一定大于 z（相邻段开始之差大于断开阈值，阈值 > 0），可以删掉以免误解。原型也确认每段 `t1 > t0`：`t0 ≤ 前一段 t1 ≤ 中点 < a ≤ z < t1`。
- **toX 单调性**：方案第 4 条正确。段与段不重叠，`t0` 不减，取最后一个 `t0 ≤ t` 的段并夹在段内，所以 toX 单调。原型在三种宽度下各采样 20001 点都单调。视窗开始或结束落在空档里，框贴到前一段右端；超出两端时贴到 0 或 W。拖动经过空档时视窗会跳过空档时间，这是预期行为。
- **其他原因**：除了 14px × 29 的间距和重叠，没有发现别的原因。修改前标记只占 30 个 2px 格子（每段一个），371 个中有 335 个在左半边。间距是主因，重叠和范围扩展是次因，与方案一致。如果以后仍嫌段太多，可以给小地图单独做更粗的分段（例如断开阈值取总跨度的固定比例），但不在本次范围内。
