## 专项方案

1. 从正式作品入口选择下载文件，经真实来源列表核对文本编码与整书范围；冻结原文件 hash 和独立章节基线。
2. 核对当前可用模型的公开状态，通过产品正常授权向已配置模型发起请求；不输出、复制或替换 Key，不以 mock 代替真实模型。先按实际正文长度核对批次和容量约束。
3. 选择正文，以及大纲、角色、物品、场景、世界观、伏笔、世界线、叙事线八类补全；保留完整正文，不能为缩短运行只导入开头。
4. 经复核及冲突决定到真实作品发布。对检查点、运行证据、业务落盘进行只读验收；关闭重开后核对同一作品。
5. 正文逐章逐字比较，缺失、重复、换序或未批准改写均失败。结构化结果逐条回查原文证据和实际业务映射，核对跨卷人物别名、关系、物品归属、场景层级、世界规则、伏笔埋设/回收、世界线事件与叙事线顺序/引用；各卷均须覆盖，非空计数不能代表正确。
6. 失败保留脱敏证据，区分来源问题、测试工具问题、产品缺陷、模型语义问题。产品修复依 AGENTS.md 执行方案独审 → 用例独审 → RED/GREEN → 代码独审，随后用同一完整输入重新走受影响流程，不绕过复核或直接改数据库强行通过。
