# 八卷结构丢失的定向修复方案与用例

日期：2026-10-27。状态：方案及定向用例待独立审核，尚未修改生产代码。属于 LOTM-BODY02 治愈，不扩大本任务到其它业务。

## 已见源码问题

`detectImportChapterCuts` 过滤卷标题且只返回 start/title；`importChapters`、手动卷章重新确认和 view 投影均不保留卷归属。`publishNovelImport` 统一创建单卷“导入内容”，将全部章节归入此卷。虽拼接正文可不变，跨卷结构已经丢失。

## 最小方案

1. 给分章 cut 增加可选 volume 字符串（上限300，与已有 ImportChapter.volume 对齐），仅当原文有独立、明确的“第N卷/部 + 卷名”标题时设置。不从模型、章号重启或本书专名臆造卷名。原书缺第八卷标题的旧候选保持已知来源缺陷，不能借此次修复判完整。
2. 检测时保留明确卷标题的原始字符位置与卷名。每卷首章的正文范围从该卷标题开始，卷标题保留在正文内，不增加“正文序言”伪章、不移到上一卷末章；任何非卷标题的前言仍保留独立正文序言。相邻章节全文拼接严格不变。正文中普通叙述含“第一部”等不识别为卷。
3. importChapters 及手动分章保活、renderer view、现有“核对卷章”界面状态带回可选 volume，不增加界面控件或新流程；set-chapters 协议允许该可选字段。已有无卷元数据会话保持原算法/指纹，不凭空迁移。
4. analyze scope 仅在存在 volume 时绑定它，改卷归属必须重新授权；planHash 已包括完整 chapters。既有未带 volume 的 scope 不变。
5. 发布器按首次出现的明确卷名分组创建 Volume/PlanningDocument.volumes；每卷 Chapter.index 从1开始，规划章节 order 及 narrative chapterIndex 保持全书顺序。无卷元数据的旧会话继续单卷“导入内容”；混合无归属章用明确的默认卷，不擅自附到某个卷。卷名重复及回到前卷需明确校验，不能无声重排章节。
6. 不改原文件、正文字符、模型结果或原生数据库 schema。不涉及模型、其它实体语义或旧六书工具。

## 定向用例（仅这些及直接必要回归）

- LOTM-V01：八个明确部/卷标题、每卷两个章、章号重启且末卷存在重复编号；应恰好16章、8卷元数据、首章包含自己的卷标题，拼接逐字等于输入。
- LOTM-V02：前言、无卷旧输入、正文中“第一部”普通句子、缺失卷标题；不臆造卷、不丢原文、无卷旧预期不变。
- LOTM-V03：自动分章→手动确认同一章界→source/confirm view→恢复重算，volume不丢；改卷名使 analyze scope 改变，无 volume 的旧指纹仍相同。
- LOTM-V04：真实临时 PGlite 发布8卷16章，原生 Volume/Chapter 与规划投影逐项对齐、每卷章号重启、全书顺序和正文不变；narrative全书索引引用仍落到正确卷章；重试不重复创建。该组件用合成文本，不能抵扣本书真实UI运行。
- LOTM-V05：既有无卷导入保留“导入内容”单卷、全局旧章节/大纲/规划引用；可选字段空白/超长/异常分组不静默处理。

## 独审后明确的兼容规则

- 新建会话显式使用 `chapterVersion:2`；旧会话字段缺省时仍使用原检测/章界行为，包括有卷标题的旧来源。恢复、失效重算、手动重新确认不得为旧会话偷偷补该字段。未知 chapterVersion 拒绝。新标记进入本身的授权/计划绑定；无该标记且无volume的旧scope/plan黄金值须在RED前固定。
- 检测器以显式选项启用卷信息，默认保持旧结果。明确卷标题位置归入本卷首章；缺少标题的章号重启撤销当前已知归属并显示诊断，不沿用上一卷名、不补造卷名。
- 新版本手动 cuts 的volume按来源标题及边界重新派生，输入若提供不匹配volume则拒绝；用户移动/删除明确卷首章界导致一个章跨越卷标题时拒绝，保留完整正文并要求保留卷界。不增加隐藏标签的任意继承。旧手动会话照原有行为。
- 发布前校验连续分组：同一明确卷名或默认组只准出现一个连续组，A→B→A、A→默认→A、默认→A→默认均拒绝，不打开新作品事务或创建部分卷章。两个独立同名卷标题因无法可靠区分也拒绝，不用Map聚合。
- 新增断言：旧带卷标题会话恢复及手动重确认保持原章界/黄金hash；新会话删除/移动卷界拒绝；未知版本拒绝；至少两处叙事分别关联第二卷首章和第八卷末章；旧仅大纲无正文仍有原默认卷。V01–05保持专项范围。
