## 必须明确的实现与断言

1. **旧会话兼容不能只检查 hash 函数。** `desktop/core/novel-import.ts:107` 的 `importSessionChapters` 会自动重算；`desktop/main/novel-import.ts:177` 的 invalidate、`:178` 的 defaultNewKinds 也会调用它。若全局换用新检测器，原本含卷标题但没有 volume 的旧 `semanticVersion:1` 会话可能被加上 volume，首章边界也会变化。必须明确新建会话启用的特性版本或等效保留策略；恢复旧会话不能凭空迁移，不得沿用旧授权去执行新分章。V03/V05须包含带明确卷标题的真实旧结构会话：恢复、自动重算及原UI手动重新确认后，按既定兼容策略验证正文、章界及旧 scope/plan身份；不能只拿本来就没有卷标题的输入测试兼容。
2. **固定 hash 兼容预期。** `importScopeHash` 当前章节投影只有 id/title/start/end（core:229），`importPlanHash` 已包含完整 chapters（core:233），稳定序列化会省略 undefined。可选 volume 应当仅在实际存在时进入 analyze scope；classify scope及无卷旧 analyze scope须保持原字节身份。定向 RED 前冻结小型旧会话的原 scope/plan黄金值，GREEN直接比较；改volume应改变 analyze scope与plan，触发重授权。不要为所有旧章节添加空字符串、null或默认卷名来“统一格式”。
3. **按源序连续分组，拒绝会重排的回跳。** “首次出现的卷名”不能实现成跨整书 Map 聚合。A→B→A、A→无归属→A、无归属→A→无归属，以及不同独立卷标题同名等，均需明确采取拒绝或保存独立有序分组的策略。当前方案倾向校验拒绝，可据此在发布前报错，不能先部分创建后留残行。V05至少覆盖一种非连续同名及混合默认组回跳，断言没有成功回执/部分出版；V04按 Volume.index、Chapter.index 重建正文并与全书源序相等，防止仅 PlanningDocument 的全局 order 正确掩盖数据库重排。
4. **手动确认要保留且不能携带过时归属。** `ImportView`、`toImportView` 和 `ChaptersScreen` 初始 map目前都会丢volume；协议 set-chapters也只接受start/title，须完整穿透。现有标题/起点编辑使用展开对象，可携带元数据，但新增cut、删除卷首cut、改变cut起点之后的归属需要明确处理；不能让用户看不到的旧volume在错误边界下静默生效。V03除了无改动确认，应增加一个界限变更/删除卷首的定向情形，验证正文仍完整、元数据按源标题重新核对或明确拒绝，而非任意继承旧标签。无须增加控件。
5. **缺标题不能误归前卷。** 仅凭后文出现“第一章”不能臆造第八卷名称；同样不能把缺标题的新一组章节静默全部标成前卷。V02须明确输入“已知卷A两章→缺卷标题的章号重启”，预期为保留文字、未确认归属/诊断，不能生成有据的命名新卷或宣称结构完整。本书旧候选缺第八卷标题，因此此次修复后也不能据此判 BODY02通过。
6. **卷章索引与叙事全书索引必须分开。** Prisma的唯一约束分别是 Volume(novelId,index)和Chapter(volumeId,index)；每卷重启 Chapter.index 合理，但 `data.chapters` 数组及 order须维持原全书顺序，`narrative.facts.chapterIndex`继续索引同一全书数组（publish:88起），不能改成卷内下标。V04至少将叙事分别指向第二卷首章与第八卷末章，并核对原生chapter.id、所属卷及事件refs；重试保持同一回执和卷章计数。
