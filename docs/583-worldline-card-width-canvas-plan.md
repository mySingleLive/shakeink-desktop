# 583 · 世界线：收起卡片弹性宽度、时间线全向拖动与滚轮分工 技术方案与测试用例

来源：用户 2026-11-17 修改要求（三条），基于已合入的世界线改版（docs/577、580、581）。本文同一处给出方案与用例，按 AGENTS.md 先审核再实现。

## 用户要求与本方案的理解

| # | 要求原文 | 理解 |
|---|---|---|
| R1 | 事件卡片（收起时）的宽度应该根据事件标题长度弹性伸缩，达到最大宽度为止（最大宽度可适当增加） | 收起卡片宽度 = 标题需要的宽度 + 卡片头部其他元素宽度，夹在最小/最大之间。展开卡片宽度不变（用户上一轮刚嫌展开卡片过大）。两个视图都适用 |
| R2 | 时间线视图中，鼠标拖动画布应允许上下左右所有方向移动 | 拖动空白处时，水平位移平移时间视窗（现状），垂直位移滚动车道 `scrollTop`（新增） |
| R3 | 滚轮用于缩放画布；Shift + 滚轮固定垂直方向，只横向移动；⌘/Alt + 滚轮只移动垂直方向 | 只改时间线视图。事件表是纵向列表，滚轮继续滚动列表、Ctrl + 滚轮缩放间距（docs/577 §9），不变 |

R3 原文“Shift+滚轮是固定垂直方向，只移动所有方向画布”字面有歧义。本方案按“垂直方向固定、只横向移动”实现，与后半句“⌘/Alt + 滚轮只移动垂直方向”对称。触控板横向轻扫（deltaX 占优）继续横移，触控板双指捏合（Chromium 以 ctrlKey 滚轮上报）继续缩放。

## 方案（修订 3，回应 583 审核 1–7、复审 N1–N3 与建议）

本方案取代 docs/577:71 的“Ctrl+滚轮缩放”、docs/577:164 的固定收起卡片宽度，以及 docs/580:155 中“Shift + 滚轮、横向滚轮平移”的描述；展开卡片宽度、事件表滚轮规则不变。

### R1 收起卡片宽度

- 最大宽度：事件表 760 → 880px；时间线根事件 260 → 340px，子事件 230 → 300px。最小宽度：时间线 150px，事件表 220px。展开卡片（时间线 420 / 事件表 920）不变；事件表父子分组框 820 → 940。
- **时间线**：卡片绝对定位，宽度参与 `buildFamilies` 打包，必须由纯函数算出，不读 DOM（真实数据约 850 张卡在构建范围内，逐卡测量回灌会重新打包、卡片首帧后移动，也会撤销 a491b98 去掉逐卡重排的性能修复）。
  - 新增 `collapsedCardWidth(input)`，输入是**实际渲染**的内容 [审核 1]：`{ title, depth, importance, avatars, more, kids }`。`avatars` = 能在角色表里找到的人物数取前 3，`more` = 其余可找到人物数，`kids` = 显示 `▸ N` 时的 N（`famInfo` 同口径的后代数，无子事件时为 null）。`buildFamilies` 新增可选 `widthOf(node)`；`EventTimeline` 用与 `EventCard.tsx:127-128`、`EventTimeline.tsx:167-173` 相同的口径构造它，不传时退回只看标题（单元测试与旧调用）。`widthOf` 用 `useMemo` 依赖 `[shown, ctx.characters]`，并加入重新打包的比较输入（EventTimeline.tsx:139 的 `inputs`），角色表变化即重新打包 [复审 N2]。
  - 头部宽度逐项对应 CSS [审核 2]：边框 2（`.card` 1px×2）+ 左内边距 14 + 右内边距 6（`.head` :66）；元素依次为 折叠按钮 20（`.fold` :84，仅有子事件）、圆点 6/9/12（:69-71）、标题、头像组、`▸ N` 徽标、`⋯` 24（:87）。相邻元素间距 = 9 × (显示的元素个数 − 1)。头像组 = 左内边距 4（:76）+ 16 + (n−1)×(16−5)，有 `+N` 时再加 16−5（时间线中 `.timeline .avatars i` :82 覆盖 `.more`，宽 16）。徽标 = 2×7 内边距 + 2 边框 + 文本宽（11px 字：`▸` 按 11、数字按 6.2）。
  - 标题宽度：13px 字号下全角字符（CJK、全角标点、`·`）按 13px，其余按 7.4px，再加 2px 余量。
  - 结果 `clamp(150, 头部 + 标题, 上限)`。估少时标题末尾渐隐（WU-35），不溢出；估多时右侧留白。真实字体与测试环境不同，最终在安装版中截图复核中文与中英混排标题。
  - 父事件标题栏仍取 `max(自身宽度, 260, 家族范围, 子事件)`（PARENT_BAR_MIN_WIDTH 不变）。
- **事件表**：宽度不参与布局，只用 CSS：`.slot:not(.slotOpen) > .card { width: fit-content; min-width: 220px; max-width: 100% }`，收起 slot 最大宽度 880px，展开卡片不受影响 [建议 7]。窄面板下 slot 仍随面板收窄。

### R2 全向拖动

`EventTimeline` 车道 `onPointerDown` 记录 `x、y、视窗 start、lane.scrollTop`；不调用 `preventDefault`（会让点击空白处的时间线根节点拿不到焦点，方向键失效），改为拖动激活后给车道加 `data-panning`，CSS `user-select: none`，并清掉已有选区 [复审建议 1]；`hypot(dx, dy) ≥ 5` 激活；激活后设视窗 `start − dx / scale`，`lane.scrollTop = top0 − dy`（浏览器自动夹在 0 与最大值之间）。纵向只是滚动，不重新打包，卡片相互位置不变；`vband` 已监听 scroll，窗口化渲染随之更新。Esc、失焦、pointercancel 同时恢复视窗与 `scrollTop`。卡片时间拖动仍优先。

### R3 滚轮（只改时间线视图）

wheel 监听仍在时间线根节点（原生、非被动）。像素换算：`deltaMode` 1（行）× 16，2（页）× 车道高度。规则按顺序匹配，先匹配者生效 [建议 2]：

| 顺序 | 输入 | 行为 |
|---|---|---|
| 0 | 未按 Ctrl，且从指针下元素向上、**到车道之前为止**（不含车道与时间线根节点）有一个在该方向还能继续滚动的元素（展开卡片中的 `pre`、表格、编辑器） | 不处理，交给该元素；该元素在该方向已滚到尽头时不让出，按下面规则处理。⌘/Alt 竖移同样先让给可纵向滚动的子元素 [建议 4、复审 N1] |
| 1 | ⌘（macOS）或 Alt + 滚轮 | 只滚动车道：`scrollTop += deltaY || deltaX`，视窗不变 |
| 2 | Shift + 滚轮 | 只横移视窗：取 `deltaY`，为 0 时取 `deltaX`（macOS 把 Shift 滚轮转为 deltaX）；`scrollTop` 不变 |
| 3 | 无修饰且 `|deltaX| > |deltaY|`（触控板横扫） | 横移视窗 |
| 4 | 其余（普通滚轮、Ctrl + 滚轮、触控板捏合） | 缩放，锚点为指针所在时刻 |

缩放 [审核 4、5]：
- 每次事件的步长：`|deltaY| ≥ 50`（Windows 一格为 100）按整步 1.2 倍（真实应用实测记录 macOS 鼠标一格的 deltaY，偏小则调整阈值）；更小的增量（触控板）按 `1.2^(deltaY/100)` 连续缩放。向下缩小（跨度变大）。
- 事件在 `requestAnimationFrame` 中合并：同一帧内各事件的缩放指数相加、横移/竖移像素相加，帧内用最后一个事件的指针位置作锚点，每帧最多 `setWindow` 一次。缩放改变比例尺就会全量重排（worldline-layout.ts:1082、1102），帧合并把连续手势限制为每帧一次重排。
- 纵向锚点：缩放后保持指针下那张卡片的屏幕纵坐标——缩放前记下指针下卡片 id 与其相对车道顶的偏移，重排提交后（layout effect）按新位置调整 `scrollTop`；指针下没有卡片时不调整 [建议 5]。

Shift 与 ⌘/Alt 同时按下时按顺序 1 处理（竖移）。

提示文案按平台区分 [建议 1]：时间线底栏 macOS 为“拖动空白处移动画布 · 滚轮缩放 · Shift + 滚轮横移 · ⌘/⌥ + 滚轮竖移 · 双击卡片原位编辑”，Windows 为“… · Alt + 滚轮竖移 · …”（平台取 `useDesktopStore(s => s.bootstrap?.platform)`，非桌面环境按 Windows 文案）。工具栏缩放控件 title（WorldlineToolbar.tsx:66，两视图共用）按 `view` 区分：时间线“（也可滚轮）”，事件表“（也可 Ctrl + 滚轮）”。

### 不改

数据模型、导入、展开卡片尺寸、事件表滚轮行为、角色变化泳道卡片宽度（230）、小地图。

## 测试用例（修订 3）

单元（`tests/unit/worldline-layout.test.ts`）：

- **CW-01**：`collapsedCardWidth` 在其他输入相同时，标题越长宽度越大（严格单调直到上限）；4 字标题根卡片 < 260。
- **CW-02**：超长标题根卡片 = 340、子卡片 = 300；空标题 = 150。
- **CW-03**：头部算式逐项：同一标题，加子事件（折叠按钮 + 徽标）、加 3 个头像、再加 `+N`，每一步宽度增加量等于对应 CSS 常量之和（含一个 9px 间距），且不超过上限。
- **CW-04**：`buildFamilies` 传入 `widthOf` 时，收起叶子 piece 宽度等于 `widthOf` 结果；展开为 420；父事件 piece ≥ max(自身弹性宽度, 260)。
- **CW-05**：人物 id 在角色表中找不到时，构造的输入 `avatars = 0`，宽度等于无人物时的宽度（构造函数从 `worldline-layout.ts` 导出，单独测试）。

浏览器（真实 `WorldlinePanel`，F60 / F885 合成夹具）：

- **CW-10**（时间线，F60）：短标题卡片宽度 < 长标题卡片；所有收起根卡片 ∈ [150, 340]，子卡片 ∈ [150, 300]；宽度小于上限的收起卡片标题没有 `data-fade`（估算不偏小）；对其中的**叶子**卡片，卡片宽 − 头部各元素实际宽之和 − 间距 − 标题文字实际宽（Range 测量）≤ 24px（估算不偏大）；父事件卡片只断言 ≥ 自身估算宽度与 260 [复审 N3]；展开仍为 420；无重叠（沿用 `overlaps`）。
- **CW-11**（事件表，F60）：收起卡片宽度不全相同，短标题 < 长标题，全部 ∈ [220, 880]；展开一张后它 ≤ 920，同时其他收起卡片宽度不变；分组框 ≤ 940。
- **CW-12**（窄面板 470px）：事件表收起卡片右边缘不超出卡片列。
- **CW-13**（角色表变化）：F60 变体中某**叶子**事件有 3 个人物；在页面中把 `planningState().characters` 改为不含这 3 人，并让查询重新获取（夹具新增 `globalThis.refetchWorldline = () => client.invalidateQueries()`，只加在测试夹具），该卡片宽度等于无人物时 `collapsedCardWidth` 的结果（±1），且无重叠。
- 更新 **WU-36b**（regression.test.ts:22-37）：事件表“≤ 760”改为“≤ 880”；时间线 `=== 260` / `=== 230` 改为“≤ 340 / ≤ 300 且 ≥ 150”；父事件 `≥ 260` 与展开 `=== 420` 保留。
- **CP-01**（斜向拖动，F60）：前置：`scrollTop = 160`，断言 `scrollHeight − clientHeight > 300`。从空白处拖动 dx = −300、dy = −120 共 12 步；结束后视窗起点（`viewWindow`，小地图 `aria-valuenow`）变化，`scrollTop` = 280 ± 2；拖动前后同时可见的卡片纵向位移全部相同（≈ −120，只是滚动）；任一步无重叠；`getSelection().toString() === ""`。点击空白处（不拖动）后按 ArrowRight，视窗起点改变（焦点仍可落到时间线）。
- **CP-02**：同前置，斜向拖动中按 Esc，`viewWindow` 与 `scrollTop` 都回到按下前。
- **CP-03**（普通滚轮缩放）：指针位于某张卡片标题上；deltaY 120 一次后跨度比 ∈ (1.1, 1.3)，指针所在时刻的屏幕横坐标偏差 < 2px，该卡片屏幕纵坐标偏差 < 2px；deltaY −120 放大；deltaY 100（Windows 一格）同样 ∈ (1.1, 1.3)。
- **CP-04**（竖移）：前置同 CP-01。Alt + 滚轮 (0, 120) 与 Meta + 滚轮 (0, −120) 各一次：`scrollTop` 分别 +120 / −120（± 2），`viewWindow` 与 `data-view-span` 不变。
- **CP-05**（横移）：Shift + 滚轮 (0, 120)，以及 Shift + 滚轮 (120, 0)（模拟 macOS 转换）：`viewWindow` 变化，`data-view-span` 与 `scrollTop` 不变。
- **CP-06**（让出可滚动子元素）：展开一张正文含宽表格的卡片，指针放在表格上横向滚轮，表格 `scrollLeft` 改变，视窗不变。用例内单独构造 F60 变体（追加一个正文为宽 Markdown 表格的事件），不改共用 F60。另：指针在同一展开卡片正文的普通段落上时，普通滚轮仍缩放；指针在表格上按 Ctrl + 滚轮仍缩放；表格滚到最右后继续横向滚轮，视窗开始横移。
- **CP-07**（性能，F885）：指针在车道中部，连续派发 30 个 deltaY = 4 的滚轮事件（每 8ms 一个）；跨度单调增大；PerformanceObserver 记录的 > 50ms 长任务不超过 2 个；结束后无重叠。浏览器测试环境耗时只作回归基线，真实应用另行实测并记录。
- 回归保持通过：WU-51（纯水平拖动 scrollTop 不变）、WU-54 / TL-R2（Ctrl + 滚轮一步 1.2）、WU-56i（Shift / 横向滚轮横移；↑↓ 竖移）、WU-56d（Esc 恢复）、事件表 WU-45/47/47b（Ctrl + 滚轮缩放、普通滚轮滚动列表）。
- 文案：`withWorldline(..., { controller: true })` 时夹具 bootstrap 平台为 darwin（worldline-browser-fixture.ts:37），断言 macOS 文案；不传 controller 时 bootstrap 为空，断言 Windows 文案。工具栏 title 两视图分别断言。

## 实现中的补充（未在审核范围内，需 code review 确认）

- **展开卡片延迟收起**：收起卡片改为按标题弹性宽度后，单击展开卡片立即收起会让卡片变窄，双击的第二下落在卡片外，原位编辑打不开（WU-32、WU-39d 失败）。改为：单击已展开卡片时，在 260ms 后收起；期间的第二次点击（双击）取消收起并打开编辑器。展开不延迟。新增 CW-14；WU-36b、WU-52 在收起后改为等待 `aria-expanded="false"`。
- **卡片正文中的宽表格**：`display: table` 上的 `overflow-x: auto` 不生效，宽表格会撑出卡片。改为卡片正文内表格 `display: block`，在卡片内横向滚动（CP-06 依赖）。
