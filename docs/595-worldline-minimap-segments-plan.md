# 595 · 世界线时间线小地图大部分区域没有事件 技术方案与测试用例

来源：用户 2026-11-20 缺陷报告（截图：小地图左侧有少量标记，右侧大段为空）。

## 现象与原因

真实作品 LOTM-587-wg-r1（371 个已定位根事件）的小地图宽 420px。用 `/api/novels/:id/planning` 的数据调用 `minimapModel` 得到：

| 量 | 值 |
|---|---|
| 段数（`railSegments`，与左侧时间轴的断开相同） | 30 |
| 段间距 | 固定 `MINIMAP_GAP = 14px`，共 29 × 14 = 406px |
| 留给事件的宽度 | 14px（每段 0–4.9px） |
| 相邻段扩展后时间范围重叠 | 29 对中 18 对 |
| 画到别的段里的根事件 | 371 个中 109 个 |

原因（`src/lib/planning/worldline-layout.ts:1733-1759`）：

1. 段间距固定 14px，段数多时间距占满宽度。
2. 每段 `t1` 取家族结束（`familyEnd`），再左右各扩 4%。跨越很长时间的事件会把 `t1` 推到后一段的开始之后。`toX` 用 `segments.find(t <= g.t1)` 找段，后一段的事件因此被映射到前一段，并被压到前一段的右端。
3. 同一原因让一段的显示范围远大于其事件开始时间的范围（例：第 9 段事件开始跨 8 年，显示范围 97 年），段内标记挤在一起。

结果：标记集中在少数几个像素上，大部分段框是空的。

## 修改（只改 `minimapModel`）

设段数为 n，宽度为 W。

1. **段间距**：`gap = n > 1 ? min(MINIMAP_GAP, 0.2 × W / (n − 1)) : 0`。段间距总和不超过 20%。两段时仍是 14px（WU-20 不变）。
2. **段宽**：`usable = W − gap × (n − 1)`，按根事件数比例分配；比例宽度小于 `MIN = min(4, usable / n)` 的段取 MIN，其余段按根事件数分剩下的宽度（循环到稳定）。宽度总和等于 `usable`。
3. **时间范围**：设 `a` 为段的第一个根事件开始，`z` 为最后一个根事件开始，`e` 为 `min(段内家族结束, 后一段的 a)`。`pad = max(dayHours, (max(z, e) − a) × 4%)`，`t0 = max(a − pad, 前一段 t1)`，`t1 = min(max(z, e) + pad, 后一段 a 与本段 z 的中点)`，且 `t1 ≥ z`。这样段与段不重叠，每个根事件的开始都落在自己段的范围内。
4. **`toX` 找段**：取最后一个 `t0 ≤ t` 的段（没有就取第一段），段内按比例、夹在段内。落在两段之间空档里的时间映射到前一段右端，`toX` 仍单调。`toT` 不变。

不改：标记、段框、视窗框的绘制（`EventTimeline.tsx:818-824`），小地图宽度，`railSegments`（左侧时间轴照旧）。

## 修订 1（按 `docs/595-worldline-minimap-segments-plan-review.md`）

| 审核项 | 处理 |
|---|---|
| P1-1 `toT` 用固定 7px 半间距 | 改：`toT` 按实际 `gap / 2` 找段。§修改第 4 条“`toT` 不变”作废 |
| P2-1 家族结束仍让标记挤在段左侧 | 采用：段范围只看根事件开始，不再用家族结束。`a` 为段内第一个根事件开始，`z` 为最后一个，`pad = max(dayHours, (z − a) × 4%)`；`t0 = max(a − pad, 前一段 z 与 a 的中点)`，`t1 = min(z + pad, z 与后一段 a 的中点)`。删除“`t1 ≥ z`” |
| P2-2 MIN 循环可能得 NaN | 改为一步公式：`MIN = min(4, usable / n)`，`width = MIN + (usable − n × MIN) × count / total` |
| P2-3 用例不足 | 见下表 |
| P3 aria、间距可见度 | `aria-valuemin/max` 仍取首段 `t0`、末段 `t1`，不改（`aria-valuenow` 超出已是现状）；间距不设下限 |
