# 场景清单循环父级修复方案独立审核

日期：2026-10-31。审核者：独立子代理 `scene_fix_review`。审核262方案并对照已定位的roster合并、候选父级解析、payload目录裁剪、生成桥及完整目录校验代码。未读取真实小说、私有journal、配置或Key，未调用模型，未修改实现。

## 结论

**方案通过，可以继续独立用例审核及RED。** 在清单展示前解决完整候选图中的循环，保持entity阶段原严格校验，可以消除“一个全局循环使无关场景同时失败”的机制；不需要放宽资料接受集合或本地任意断边。

R13的1014候选、334父关系及一组二节点循环属于主代理结构统计报告，本审核未独立读取该私有清单。现有service确实在每个entity结果中遍历完整可信目录的父图，因此该机制在源码上成立；这不据此认定历史每一轮失败均来自相同循环。R13正常停止及driver exit2同样按主代理报告保留为未通过，不能计作导入成功。

## 已核对的实施边界

- **阶段及响应唯一**：`sceneParentTargets` 仅用于semantic/analyze/roster/scene，artifacts为空；普通roster缺省时沿用原清单合同。纠错响应唯一根为 `sceneParents`，严格每目标一项固定结构，不允许同时返回roster、artifacts或其它阶段字段。空/重复/缺漏/额外targets和proposal应分别拒绝，不能把新字段加入通用可接受返回集合。
- **独立图门**：服务从完整可信PLACE目录自行计算全部循环节点，精确比较targets；不能只信controller声明，也不能只验证发送给模型的裁剪目录。原目录中非PLACE、外部父级或身份冲突不能被纠错请求隐式合法化。应用proposal后使用新完整目录走原严格父级类型、引用及无环检查，旧循环目录不再合入。
- **有据修订**：所有proposal来自本次模型输出，绑定既有ID和授权当前units的真实可定位引文。提示区分空间包含与连接/出入口/别名，不能依据名称相似推断双向隶属。没有明确包含依据可由模型省略parent；JSON null仅在该可选proposal字段规范化为缺省。其它非法值仍拒绝，不能catch后删键、默认置顶或自动选择要切断的边。
- **目录及材料覆盖**：serializer强制包含全部纠错目标及其父链；完整可信目录保留在service。材料先覆盖每个目标的名称/别名，再按共现密度纳入预算内单位；任何目标不能覆盖、超过32循环节点或整体payload/固定提示超预算均明确失败，不减少目标或放宽预算。沿用既有runtime roster通道，无循环时零新增请求。
- **完整性与原子性**：在临时副本一次应用全部proposal，只改变循环节点parentId；全部ID、名称、别名、证据、来源、选择状态及非循环节点所有字段保持。修正后的ID父引用不再经按名称解析的候选构建器重建。完整图通过、当前epoch仍有效后一次checkpoint提交候选并清理stash；失败/取消不提交部分边，也不清空成功批次coverage、原stash或旧候选。
- **纠错上限**：只增加一次已有roster生成请求，沿用generateJSON最多两次生成，不新增outer或自动循环重试。第二轮仍循环或其它非法关系必须失败。用户正式重试可从保留的coverage/stash恢复，但不能在同次后台运行中无限重发。
- **后续资料门不变**：entity阶段的目标、PLACE、确认父级、三个引用、四业务字段、证据和原生映射校验继续严格；259—261静态字段反馈保留。新sceneParents字段不能扩散到角色、item/world、普通scene分析、review/reconcile。

## 后续验证要求

用例应明确覆盖无循环零请求；二节点及多个独立循环；服务重算后的targets精确集合；proposal全覆盖/唯一与未知字段拒绝；保留非循环树枝和全部候选字段；第一次仍循环第二次有据成功、持续循环两次失败；外部/错类型父级和伪造/越界引用拒绝；材料不足和33节点容量门；取消或保存barrier下没有部分候选提交。新graph校验需有连接至现有非循环父级的正例，避免仅测试“全部置顶”而掩盖合法关系保留。

真实成功仍须正确应用身份的新session、指定原件全章/全文覆盖和默认全部本轮场景，最终全部未过滤任务/候选/资料ID及确认父级一致、零失败跳过丢弃映射警告、源和正文完整、正式发布正常退出及重开逐字段/逐章核对。本方案审核没有认证这些真实结果。
