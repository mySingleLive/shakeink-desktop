# 场景修复失败的固定业务标签

R41 两个正常 Worker 失败只显示“场景清单结构无效（响应结构）”。服务自己的 StructuredGenerationError 仍保有固定 feedback，但 scene catch 只识别旧 roster 字段，未识别 repairs 路径，故实际剩余失败原因被合并。先补准确可读的错误分类，不改模型合同、提示、次数、预算、接受/拒绝、来源或保留门。

限定现有 semantic v1 / analyze / scene / roster 的 invalid_schema catch：仅当已知 repairs 路径时，按源代码内已有固定反馈识别“原文限定”“称呼来源”“证据窗口”“资料保留”“修复事务”等有限业务标签；未知反馈保持原“响应结构”。只输出预置标签，不回显 feedback、任意键、值、索引、引用、Key、异常对象或小说。原非场景、旧 roster 字段及其它异常行为不变。若早前 apply/resolve 已把多种错误合并成事务指导，只能报“修复事务”，不能推断具体 CF/slot 原因。

计划仅服务错误映射与新增定向合成测试。方案和 377 用例按序独审，TDD/独立 code review/必要回归与构建后做新正常 fresh 全文。该轮有新准确错误则据实际分类修复；没有错误仍须完成全部场景、全文资料复核、发布及重开验证。不是盲加重试或已完成修复。
