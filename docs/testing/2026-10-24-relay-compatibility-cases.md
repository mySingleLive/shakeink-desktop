| 编号 | 输入及执行入口 | 必须观察到的结果 |
| --- | --- | --- |
| RELAY-01 | custom/openai 文本模型，端点为域名根路径；分别执行连接测试、真实 SDK 生成 | 两者均仅请求同源 `/v1` 下的正确资源；不发生失败后另一路径重放；原持久化 endpoint、密钥作用域与 authRevision 不改变 |
| RELAY-02 | 显式 `/v1`、尾部斜杠、`/api/proxy/v1`、其他自定义非根路径；其他协议 | 无重复 `/v1`，保留显式自定义前缀；其他协议保持现有逻辑；非法 URL、凭据查询参数、跨来源/越界路径仍拒绝 |
| RELAY-03 | 同名官方型号的 custom 配置及官方 OpenAI 配置 | 本轮不默默切换原定 wire；连接测试与生成 API 前缀一致；只发送一次真实生成请求；官方 Responses 与非流式行为保持 |
| RELAY-04 | 编辑已保存模型，揭示原密钥，修改端点并明确重输同一个值；执行测试与保存 | 前端发送显式输入，后端可以在新作用域下执行；未重输仍拒绝；同作用域保留旧密钥仍提交空字符串；取消不落盘 |
| RELAY-05 | 流式文本请求返回 HTTP 200 HTML、普通 JSON、缺失或错误 Content-Type | 主进程拒绝并返回固定可理解诊断；无正文/密钥/供应商原文泄露；请求及 transfer/lease 及时释放，禁止写 succeeded |
| RELAY-06 | `stream:false` 返回正常 JSON；图片/非文本传输 | 正常调用继续可用，不被 SSE 类型校验误拒；现有非流式官方模型可正常输出 |

| RELAY-08 | 有部分正文但无真实正常结束，或 finishReason 为 other、length、content-filter、error | 不能记完整成功；保留已产生的部分输出与原始更具体错误；业务终态失败；提示可恢复，无重复写入 |
| RELAY-09 | 正常正文完成；正常纯工具调用；文本工具兼容层生成合法调用 | 正文和合法纯工具步骤均成功；无正文工具交互不被误判；工具既有参数校验与执行回执保持 |
| RELAY-10 | 读流过程中用户取消、模型禁用/移除/密钥轮换、正常完成后的 EOF、无 finish 的提前 EOF、原始 error part | 正常完成后 EOF 通过，提前 EOF 失败；保留既有取消和撤销优先级，不用空响应错误覆盖原始错误；无陈旧文本/工具越权执行；reader 与 lease 释放 |
| RELAY-11 | 错误内容伪造认证材料、模型响应正文、端点路径或请求头 | 对外错误只含固定诊断和状态，不包含供应商原始错误、密钥或用户输入 |
| RELAY-12 | macOS 修复构建启动，使用已有自定义中转记录执行连接测试、普通 AI 对话及实际写作/保存/重开 | 真实已配置端点连接得到有效输出；不复制/变更密钥作用域；作品正文和字数可回读。网络失败如实记录，不能以 mock 通过冒充真实通过 |

## 执行与证据

- 优先复用 `model-configuration`、`model-service`、`model-settings`、`local-model-generation`、`local-chat-defaults` 的真实主进程与 SDK 测试模式。
- 新共享守卫测试要直接消耗真实 SDK 结果，另用最小模型对象精确测试 finish/EOF、推理、工具与取消边界。
- 定向测试后执行项目完整单元/集成检查、类型检查和安装产物检查。只记录实际执行的命令、用例数量、失败与修复结果。
- 原始认证值、真实正文与完整用户数据文件不进入测试夹具、日志、报告或版本控制。
