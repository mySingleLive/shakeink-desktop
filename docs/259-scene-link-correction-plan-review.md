## 结论

**方案可执行，可以继续独立用例审核及RED。** 在原严格校验已拒绝之后增加可证实的固定字段反馈，可以提高现有有限纠错的针对性，不需要改变接受集合。当前公开R12错误确实不足以确定具体坏字段，方案保留这种不确定性和原失败结论，表述准确。

源码依据：`desktop/service/novel-import-ai.ts` 中 `generateImportAiJson` 在 `validateIdentityLinks` 抛出任何异常后统一添加 `artifacts` 根级身份反馈；后者调用的 `validateSemanticLinks` 同时检查目标身份/父级、目录类型、三个关联外键及循环/锁定字段。因此不能把“场景身份与上级关系”直接等同于坏parentId，也不能凭该标签清空关系。

## 实施与用例必须保持的边界

- 精确限定 `semanticVersion=1 / analyze / entity / scene`，且仅处理原schema已得到恰好一个合法目标、原身份校验已经拒绝的结果。不改变 `validateIdentityLinks` / `validateSemanticLinks` 的成功或失败条件，不把诊断辅助函数当成新的接受门；无法确认具体字段时继续原通用错误。
- 父级比较绑定本次唯一可信目标，必须处理确认无父级而模型额外填入父级、填入目录内另一合法PLACE父级及外部父级三种情况。不能只测“父节点不存在”。显式非法类型仍由原schema拒绝；已补缺省控制元数据的合法响应继续原样通过。
- 三个引用的“完整可信目录”必须与现有校验一致，包含 `request.entities`、有效的上下文 `request.artifacts` 及本次结果形成的同一可信身份集合，不能只查发送给模型的裁剪目录。合法仅通过上下文artifact提供的引用、合法目标自引用或其它已接受引用，不应因诊断辅助函数的目录不完整而被错误归类。目录身份本身冲突、循环、锁定字段等未确认原因继续通用诊断。
- 字段路径仅来自固定枚举 `parentId / characterId / sceneId / itemId`，说明文字为静态常量。最终公开分类应从**最终失败轮次**的已知完整路径与固定反馈共同确认，不使用跨生成共享的旧失败标志，避免前轮坏引用、后轮网络或其它结构错误被误报为同一原因。不输出任意字段键、ID、场景名称、模型值或异常原文。
- 主进程外层纠错除完整消息白名单外，还应把对应的静态字段指导保留到第二请求提示中；仅新增“允许重试”而仍发送同一句泛化提示，不能证明本轮针对性目标已实现。多字段同时错误时使用有界、确定的反馈/分类顺序或明确白名单组合，不能以任意字符串拼接扩大可重试异常集合。
- 原最多2请求/4生成上限不变，第二请求仍在原catch之外。必须保留普通scene、角色、item/world、review/reconcile及网络/授权/取消/预算/保存错误的原行为；成功时目标ID、父级、四业务字段、text、来源及有效证据逐值保留。

后续用例应分别验证三个字段的未知ID/错kind、目录内合法引用和上下文artifact合法引用；错误parent的三种归属情况；首轮错误后恢复、持续错误精确上限、不同轮次错误类别切换、其它阶段不扩散及敏感哨兵不进入最终错误。以上为方案的具体实现/测试边界，本审核没有运行新增测试或认证真实导入成功。

真实验收仍需新session、指定原件全章及本轮全部识别场景，通过全部未过滤任务/候选/资料ID与确认父级、零失败跳过丢弃警告、正式保存及正常重开逐字段/逐章核对。R12部分完成和本轮后续合成检查不能替代该结果。
