# 场景清单有限恢复方案

依据 R40 实际非空/stop/JSON 括号错误及修复后的无据 context.label 错误。当前完全不可解析首答在 repair 回调直接终止，未使用第二代；当前可解析草稿只允许一次定点修复。对 130 包识别，这会把模型局部输出错误直接变成整步失败。

只修改 semantic v1 / analyze / scene / roster / concrete identity 的服务桥与通用生成器一个受信可选次数参数 maxGenerations；默认两代，合法值为 1..4 的安全整数，在供应商前校验并从 SDK rest 剥离。该范围注入四代，含第一次。网络重试、授权、取消、用量写入异常不进入此恢复；每代仍走原实际生成和用量路径。新场景恢复在无 draft 与 active 两态均要求 finish=stop，缺失或其它 finish 均立即保守失败，不扩张长度等异常的重试；generic 行为保持。

首答 invalid_json 且 SDK stop、没有可解析 roster draft 时，允许在原完整 prompt、首阶段 native schema 下重生成；把完整原回复标为不可信数据供修正，明确完整重新识别本包。不可解析回复没有可确定的完整记录、稳定 slot 或已接受结果；不做宽松解析、括号臆修、过滤坏项或部分入账。该分支不能宣称证明保留了其中可能存在的资料，最终仍须所有正文/事实完整复核通过。非 stop、其它根或超额 roster 继续原失败行为。

一旦得到可解析 roster draft，按现行 prepare 原子冻结草稿、全部好行与来源证明。后续只使用同一份原定点事务，绝不从失败 repairs 重建草稿或重算 slot。每个后续回复仍完整应用到原草稿，再过原 CF、strict wire、source、ownership、retention 和 final 门，失败不采任何部分。原 keep 窗口/限定/关系与好行不变；新增无据资料仍失败，最多重试剩余次数。

每次 typed 重试都携带原冻结 draft、同一 plan 及当前完整失败回复，不能只剩最新 repairs 而丢失原 slot 上下文；不累计已被取代的历史失败回复。每次纠错都先验证完整材料和实际 native schema 预算，不截断原文、原失败回复或保留证明；超额立即原失败。有限重试反馈使用当前固定字段要求，错误展示仍只固定安全分类；不公开模型原文、任意异常或 Key。没有循环重跑全文以碰成功，420000ms 原计时不改。

实施前顺序独审方案和用例；TDD 后独立 code review、定向必要测试与构建。随后新 fresh 正常全文运行：全部选中，不跳过失败或资料；全部场景、完整正文与事实/归属复核、正常 UI 处置、发布和退出重开持久化均实际通过才完成。四代上限只提高恢复机会，不保证供应商每次成功，不能把上限耗尽标成成功。
