# 场景资料正文含义澄清方案

2026-11-01。R25/R26均出现少量长尾请求，分别在固定7分钟门停于970/971、975/976；不算完整通过。R25同目标快照首请求只读复测，首gen达到32768输出token/50397字符，第二gen stop后通过。缺少历史流/原payloadHash，不能据此断定历史长尾为同一原因。

现有 `desktop/service/novel-import-structured-scene.ts` 明确写着 `text为完整非空白正文`。该字段实际保存单个场景的资料说明，而完整小说正文已经在units/workingProse；这句话没有明确两种内容的区别。输出长度接近输入单位字符数仅为调查线索，不证明已复现原文复写。私有只读诊断会只记录输出形态、完整原文单位匹配计数等标量，不能把猜测记成事实。

窄修范围仅此模块及定向测试：给 native scene text 字段添加静态业务说明，同时在场景prompt明确 text 是当前目标场景的资料说明、汇总全部不同的有据地点事实；小说正文仍由应用完整保存，避免把其它人物/场景剧情逐段复写进该字段。各不同事实及全部有据描述仍应完整保留，不以简短字数上限实现。服务端JSON schema仅新增text.description注释，结构、字段类型/required/enum/range/additionalProperties及适配validator不变。

不改变原始units/payload/目录/引文、任何现有事实值、4个长字段的完整性、输出cap32768、模型/endpoint/thinking、并发、预算、两层纠错和网络重试、finishReason门、Unicode/证据/知识/父级/发布门。不追加接受length结果，不截断文本或丢弃引用，不提高7分钟阈值，不接受整书部分成功。

依独审意见，排除的仅是与当前目标无关的逐段剧情复写；与该场景相关的跨人物/地点关系、历史、时间与信息归属仍完整保留。新增静态prompt与schema注释全部计入原预算，无文案豁免。

依次方案独审→用例独审→真实RED/GREEN→独立代码审→定向回归/类型/构建→单项真实接口及全新整书验收。测试重点为实际 native SDK wire携带业务字段说明、去除该注释后的原结构合同及全部输入原值保持、长资料/Unicode完整适配、严格限定到原native能力路径；只验证指导确实送达，不把静态测试当模型行为证明。真实效果由后续原接口测试与完整流程判断。
