## P1

### P1-1 §13 步数表的级别 5 / 6 步数错，TZB-01 的 −33、−35 步断言会失败

- §13 写 “−33 步约 0.197（级别 5），−35 步约 0.149（级别 6）”。纯函数：−33 步 d = 0.397，−35 步 d = 0.300，都是级别 5；0.197 是 −38 步，0.149 是 −40 步。表里把指数按 1.25（工具栏步长）或别的底算了。
- 后果：TZB-01 “−35 步只剩关键卡片” 在 −35 步看到的是 9 个重要时间点（r1 r2 r7 r8 r10 r13 r16 r19 r22），断言失败；“−33 步重要为时间点” 碰巧成立（级别 5 从 −31 步起）。
- 级别 6 需要 −40 步（d 0.149），新下限在 −41.56 步，只余 1.5 步；旧下限在 −38.37 步，到不了级别 6。所以 −40 步同时验证了 §1 / §8.6 P2-5 的下限放宽，这一点要写进 TZB-01：分级关闭（或不传 `{ levels }`）时缩小按钮在 −38 步禁用，分级打开时到 −41 步才禁用。
- 修正：TZB-01 改为 −31 步 重要为时间点、−40 步只剩 7 张关键卡片（r4 r5 r11 r14 r17 r20 r23）；§13 的表按上节实测表重写。方案已要求“用例引用常量、不手写数值”，建议在 `tests/helpers/worldline-zoom.ts` 导出 `TABLE_STEP = Math.log(1.15)` 与 `stepsTo(d)`（由 fit、gap 求步数），用例写 `stepsTo(ZOOM_HIDE_KEY) + 1` 一类表达式，不写 −40。

### P1-2 复位恰在 40 阈值上，且 1.15 的回差等于 1.15 的步长：TZB-02、TZB-12 和所有“从复位起数步”的断言都落在浮点边界上

- 复位 d 精确等于 `ZOOM_POINTS`（40），`zoomLevel(40, 0) = 1`。但组件按 `e` 累加 `±ln 1.15`：先缩小 12 步再放大 12 步，e 的累加结果给出 d = 39.99999999999999，`zoomLevel` 判为级别 2。复位按钮把 `e` 设成 0 时是 40、级别 1。同一个“0 步”在不同路径上级别不同。
- 回差带 [40, 46) 的宽度是 ×1.15，正好一步。从级别 2 放大回来：0 步 d = 40（或 39.999…）仍为级别 2，+1 步 d = 46.000（精确 46 为级别 1；累加后 45.999999999999986 为级别 2）。所以 TZB-02 的 “−7 / −6 仍有时间点，越过 46 后时间点消失” 中“越过 46”取决于浮点舍入，可能要 +2 步才发生，用例会偶发或稳定失败（取决于路径），且不同机器上一样（确定性的，但不在作者预期里）。
- TZB-02 还写着 “（d 15.0 / 17.3 < 46？按纯函数核对）”：这是未定稿的问句。纯函数：−7 步 15.04、−6 步 17.29，都 < 40，本就是级别 2 的缩小区间，与回差无关，测不到回差。真正的回差区间是 [40, 46)，在 zoomView 上只有 0 步这一个点，而且就在阈值上。
- 修正（任选其一，推荐 a）：
  - a. 时间线的 ZB-07 用细步（小 `deltaY`）逼近阈值，表格做不到：表格滚轮固定 ±ln 1.15（`EventTable.tsx:247`），与 `deltaY` 大小无关。所以回差的数值边界放在单元层（TZ 新增：从级别 2 起 d = 40、45.9 为 2，46.1 为 1；从级别 3 起 11.4 为 3，11.6 为 2），浏览器只断言 “从 −8 放大，在 d ≥ 46 × 1.001 的第一步之前时间点一直存在、之后消失、再缩小一步（d < 46 但 ≥ 40）不回来”。断言里 d 用页面读数（表格应输出 `data-crowding` 或等价属性），不按步数推。
  - b. 新增夹具 `zoomView(24, { gap: 700 })` 一类，使复位 d 不在任何阈值的 ±1 步内。
- 无论哪种，表格必须暴露当前 d 与级别（例如 `[data-event-table]` 上的 `data-zoom-level`、`data-crowding`），否则 TZB-01/02/11/12/14/18 都只能靠步数推算，任何步长或 fit 的改动都让它们集体漂移。§13 没有写这一可观察量。
- 回差的另一侧也要测：从级别 3 放大，−9 步（d 11.37 < 11.5）仍为级别 3（层叠），−8 步才回到级别 2、子事件重新出现。这是 T4 “放大回到级别 < 3 自动展开”的直接用例，TZB-02 现在没有。

### P1-3 TZB-07 依赖的“同刻两个事件”在 zoomView 中不存在；TZB-13 的“判定边界”没有可构造的位置

- 实测 `zoomView(24)` 所有事件的 `time.value` 互不相同（根间隔 720 h，子事件在 +48 / +96 / +144 h）。F885 有 4 对同刻，但都是“孙事件与另一个根”（f8c0g1 与 n150 等），不在同一层，按 §9.2 的判定不直接比较。
- 所以 TZB-07 “同刻两个事件在视图内：放大到上限不自动展开” 没有夹具可用；TZB-13 “滚到两个同刻事件附近 → 退出 / 滚回 → 进入” 同样没有。
- 修正：在 `zoomView` 增选项 `sameTime: [i, j]`（把 r_j 的时间设为 r_i 的时间，r_i、r_j 都是叶子），例如 `zoomView(24, { leavesOnly: true, sameTime: [12, 13] })`。这样 r12、r13 拉伸间距为 0 → 同刻对之间只有 `CARD_GAP` 6，展开卡（≥ 78）永远放不下。TZB-07 断言：放大到上限（+50 步），视图在 r12 处时 `aria-expanded=true` 计数为 0；滚到 r2 一带（远离同刻对、视图内不含 r12/r13）时全部展开。后半句是正向对照，没有它，“不自动展开”在功能完全缺失时也成立。
- TZB-13 的“边界”按此夹具定义为：视图底边刚好越过 r12 顶部的 scrollTop（由布局计算），用例先求出该 scrollTop，再在 ±20px 内操作。

### P1-4 TZB-06 的 +30 步对“全部展开”成立，但测不到“只在有空间时展开”；+10 步在放大路径上还是级别 1

- 实测 `leavesOnly`：`gapFor(d) = clamp(240·d/160, 240, 1200)`，Δt·k = d（gap 720 h）。估算展开高 78–106（无 fact、无 people 或有 people），需要 ≤ 可用间距 − 24 = 130 以下：
  - +10 步 d 161.8：可用 162，最大估算 106 + 24 = 130 ≤ 162，空间足够。但从复位（级别 1）放大，+10 步仍为级别 1（< 184），不在级别 0，不会自动展开；+11 步（186.1）才进入级别 0。
  - +20 / +30 步：可用 655 / 1200，远大于 130。
- 结论：+30 步确实有空间（问题中的疑问：有），而且宽裕到 9 倍。这让 TZB-06 只验证了“级别 0 → 全开”，“刚好放得下 / 差一点放不下”的边界在浏览器侧没有任何用例，只靠 TZ-07/10 单元。
- 注意：卡片宽度是事件表 slot 宽，不是时间线的 420px。表格的展开卡宽 = slot 宽（`min(880, cardsWidth − 36)`），“420px open cards” 是时间线 ZB-37 的断言，不能照抄到 TZB-06。
- 修正：
  - TZB-06 改为从复位放大到“第一个级别 0 步”（+11 步，用 `data-zoom-level` 判定），此时可用间距 186 − 估算最高 106 = 80 ≥ 24，应展开；并加边界对照：选一个使可用间距落在 [估算 + 12, 估算 + 24) 的夹具（例如给某根加长 fact 使估算 ≈ 170），断言该处不进入、在已进入状态下滚到该处保持（KEEP 12）。这是 GAP / KEEP 回差在浏览器侧的唯一用例。
  - 断言首帧为估算、测量后可能退出一次（§4、P3-d）：用例在判定后再等 160 ms + 2 帧读最终状态，不在首帧断言。
  - 相邻卡 top 与收起时相同（±0.5）要说明比较的是什么：收起时拉伸间距受 `gapMax` 限制（级别 0 时 `gapFor(d)`），展开后 top 应不变。用例应读收起时（关闭分级或 `autoClosed` 全部）的 top 与展开后的 top，同一 scrollTop 下对比；否则先展开再读“收起 top”无从取得。建议：用例在 +11 步展开后，记录每张卡 `getBoundingClientRect().top`；再点“全部收起”或缩小一步再放大回来前读一次。最简单的是直接断言相邻卡 `top(n+1) − top(n) = min(gapFor(d), Δt·k)`（±0.5），即“由时间决定、未被推动”。

### P2-5 计时（160 ms、260 ms、400 ms）与 TZB-13 的可执行性

- TZB-13(a)“停在边界 1 s 内变化 ≤ 1 次”：要先定义如何“停在边界”。按 P1-3 的同刻夹具，先求边界 scrollTop，然后设置 scrollTop（这是用户滚动，会清闩锁、计时）；1 s 内允许 1 次是对的。
- TZB-13(c)“程序恢复滚动后 1 s 内无变化”：锚点恢复写入只在布局提交后发生，而布局提交本身来自缩放、测量、切换或树变化，这些都会按 §12.3 P3-l 安排一次判定。浏览器侧构造不出“只有程序写入、没有别的输入”的场景，所以 (c) 无论 `programmatic` 判别是否存在都可能通过。修正：把判别抽成纯函数（如 `isProgrammaticScroll(written, current)`：`written` 非 null 且 `|current − written| ≤ 1`；写入前后相同时不设 `written`），单元测试覆盖 0 / 1 / 2px 与“写入前后相同”四种情况；浏览器侧改为：在 `on` 稳定后缩放一步（会有一次恢复写入），断言恢复写入产生的 scroll 事件之后没有第二次计时（判定次数可用 `data-decide-count` 一类调试属性观察，或者断言 `aria-expanded` 变化次数与“只缩放一步”的对照组相同）。

### 新问题

- **N1（P2）`stepsTo` 公式在缩小方向上差一步。** `ceil(ln(target / fitD) / TABLE_STEP)` 对负数会向 0 取整：`stepsTo(0.15, 40) = −39`，d = 0.172，仍是级别 5；`stepsTo(0.6, 40) = −30`，d = 0.604，仍是级别 4。§14.1 的示例 `stepsTo(ZOOM_HIDE_KEY, 40)` 正好会停在错误的级别上。修正：缩小方向用 `floor`（−40 步，d 0.149），放大方向离开级别用 `ceil(ln(t × ZOOM_HYSTERESIS / fitD) / TABLE_STEP)`；或者只把它当作上限，循环到 `data-zoom-level` 达到目标为止。
- **N2（P3）TZB-12 的 d = 400 到不了。** 改为“在第一个 d ≥ 400 的步（+17，d 430.5），根间距 = `min(d, gapFor(d))` = 430.5 ±0.5”，d 读页面的 `data-crowding`。
- **N3（P2）`data-crowding` 取 3 位小数会让 TZB-02 失败。** 沿滚轮累加的路径：+1 步实际 d = 45.999999999999986，级别仍为 2，有时间点，但属性显示 `46.000`；时间点要到 +2 步（52.9）才消失。“首次 ≥ 46 后消失”这条断言因此不成立。修正：`data-crowding` 输出不取整的 `String(d)`，或者 TZB-02 改为断言消失时 `data-zoom-level` 从 2 变为 1，并且上一步的 d 读数 ≤ 46.001。
- **N4（P3）GAP / KEEP 边界要按实测高度。** 卡片展开后测量值会替换估算值，[可用 − 24, 可用 − 12) 只有 12px 宽。修正：“可用”定义为下一根的拉伸起点减本根 top，边界按展开后的实测 `offsetHeight` 断言，夹具取区间中点（可用 − 18），给测量误差留 ±6。
- **N5（P2）`decideAutoOpen` 规格不够紧，测不出唯一实现。** 缺以下内容：(1) `fits` 是进入（GAP）还是保持（KEEP）的结果由调用方按 `on` 选择，要写明；(2) `input` 是否在 `fits === null` 或 `fits` 为假时也清闩锁；(3) `on` 为真、有输入、保持失败时的输出；(4) 未闩锁时的进入；(5) `input` 何时置位、由谁复位。建议一句话定为：`l = input ? false : latched; if (fits === null) return { on, latched: l }; if (on) return fits ? { on: true, latched: l } : { on: false, latched: true }; return { on: !l && fits, latched: l }`。TZ-14 按 on × latched × input × fits（true / false / null）共 24 种组合穷举。另外写明 `input` 由用户滚动、缩放、定位置位，每次 `decide()` 读取后复位。
- **N5b（P3）`isProgrammaticScroll` 缺两点。** 一是匹配后 `written` 是否清空（只用一次）。不清空的话，之后用户滚回 1px 以内也会被当作程序写入。二是负向差值。修正：TZ-13 加“差 −1 → true”，并写明调用方在第一次匹配或第一次不匹配的 scroll 事件后把 `written` 置为 null。
- **N6（P3）TZB-13e 没写怎样构造“退出”。** 建议用 N4 的 `fact` 夹具，把某根实测高放在 [可用 − 12, 可用)：先在别处进入，再滚到该根处，保持判定失败，于是退出并闩锁；然后用事件目录定位一张有空间处的卡片，断言重新进入。
- **N7（P3）`farRoot` 要指定为一般（importance 1）。** 远根如果是重要或关键，到了级别 4 断点仍在，过滤前后的 `breaks` 相同，TZB-16 测不到要测的规则。
