# 场景循环父级修复用例

日期：2026-10-31。262方案及独立审核通过，以下仅合成数据，先RED。

- **SH-01 图算法**：两节点、三节点、多个分离循环及其树枝；准确返回循环节点，不包含指向循环的后代。无循环为空。重复ID/缺父级明确拒绝，长链不递归溢出。应用合法proposal后图无环；全部非循环节点与候选元数据逐值不变；原输入不变。缺漏/重复/外部目标、外部父级、自指或持续循环均拒绝；不本地任意断边。
- **SH-02 专用请求/响应门**：只允许semantic/analyze/roster/scene、空artifacts、完整PLACE目录；服务独立验证targets恰好是全部循环节点（含最多32限制）。其它阶段/类型、空/重复/缺漏/额外目标或错类型目录在生成前拒绝。每目标唯一sceneParents项和可定位证据，非法父级/循环/漏项/多项/未知键与坏引文拒绝；根字段仍为普通roster时不接受sceneParents。
- **SH-03 两生成纠错**：首轮持续循环或坏引文、第二轮合法可恢复，静态反馈不包含模型值/未知键/原文哨兵。两轮持续非法严格失败，不增outer。合法无上级由模型省略或明确null，规范格式省略parentId；其它空串/数字/对象无效。不以清空所有候选或减少target通过。
- **SH-04 payload与材料**：包括仅别名出现在原文的循环节点，强制序列化所有目标和相关父链；服务保留全目录。所有输入units逐值保留。controller优先覆盖每目标来源，超过32循环节点或预算无法覆盖全部目标须明确失败、零entity请求。无循环时零父级纠错请求。
- **SH-05 真实controller链**：多个roster批次形成跨批循环，合成父级纠错后保持全部候选/别名/证据/来源/selection及非循环父级，进入清单后全选全部实体，严格service链完成全部场景并进入verify。请求次数：父级纠错一次（最多两次底层生成），每entity原有上限不变。
- **SH-06 原子性与失败**：纠错失败/取消/保存失败不发布部分父级变更，不启动entity；旧候选、stash/coverage保留可重试。成功后父级使用ID直接提交，不能重新按名称解析而丢失。新epoch/取消后不采用返回值；网络/授权/预算错误不进入新的自动纠错循环。
- **SH-REAL**：定向回归、类型检查、构建、独立代码审核后，以正确加密应用身份新session导入原件全文1402章，覆盖全部5589等实际单元、默认全选本轮所有场景。核对最终完整图无环、全部未过滤任务/候选/资料ID及确认父级、零失败跳过丢弃警告、源/正文与章界切片不变，正常保存退出并重开逐字段和逐章比较。R13失败及关闭提示继续保留，不能把局部修正或合成结果当整书成功。
