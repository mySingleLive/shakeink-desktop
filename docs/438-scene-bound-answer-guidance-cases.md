# 绑定答案显示与反馈用例

1. 显示投影：selection/replacement 混合任务和多 claim 联合方案均逐项印出连续 1-based answerNumber；每个方案显示 `[连续 optionNumber, 完整原 assignment]`。独立读取器深等还原原 tasks，含空数组的明确 reject、多窗口、首尾方案、不同行局部同号。不能改输入或冻结调用者对象；投影自身深冻结。
2. 真实业务桥：合成来源构造至少两个不同合法局部方案，由显号显示读取选择并经真实 SDK/服务桥恢复期望完整结果。原业务 oracle、来源/保留/归属判断不变。旧三种严格 replacement 正例、旧 repairs 正例继续通过。
3. 拒绝后具体指导：11 任务答 10 项、34 任务答 40 或 38 项，只反馈完整所需数量，不能给后续类型或范围首因。数量正确后，selection 回 0、负数、非整数、字符串、数组、对象或超出本任务范围都拒绝并指明可信任务号与合法局部范围；范围内共享 choices 号但超出局部方案号仍拒绝。不得补齐、截断、取首或默认 reject。
4. replacement 反馈：不可拒任务答 0、正整数或列表继续拒绝；可拒任务答 0 仍须原全局门。replacement 三种元数据结构互斥，mixed、只有 name、只有 aliases、primary 越界、缺必需数组、未知键继续拒绝。mention evidence 数组或旧 `{ref}` 键失败后，指导明确 mention 是单 `{choice:共享号}` 对象、context/link 才是非空 evidence 数组；不得展开旧 ref 或合并数组来自动修正。纠错解释仅输出固定词与可信任务号，不输出输入键名或值。
5. 协议隔离：当前 active answers 的 root/decode/record 或 apply 失败，后续 correction 不能要求“本轮只返回 repairs”或“逐字使用 choiceRef”；旧 repairs 兼容路径仍用原反馈。answers/repairs 混根拒绝。active 时错误 roster 根给 answers 指导。首轮、未解析重识别和额外根恢复提示不变。
6. 隐私：畸形未知键、嵌套键、literal/label/quote、伪控制 ref、Unicode/换行私密哨兵不能进入新增反馈或用户错误；不传任意 Zod/业务异常消息。最多六项诊断，无接受副作用；原有安全来源与保留反馈不丢。
7. 负控制：保留原 BD02 全负例、BD05 编译限额、BD07 禁拒与悬空链接、BD07c 跨旧成员组桥接、旧来源/保留与授权/版本门。新增显示读取器对跳号、重复号、错层、错类型、少列/多列、重排均拒绝，不能将坏格式修成合法。
8. 预算：130 首轮与 R46/R47/R61 共 196 个已捕获实际生成驱动新提示，全部原 payload、fixed、context 和 Native envelope 限额不变。旧回复接受/拒绝结果保持 70/20；这只证明本地规则不变与预算，不证明新接口行为。新显示若使原预算失败，先减编码与指导开销，不能裁原始资料或抬上限。
9. 验证次序：本新增用例先红后绿、现有相关用例、类型、桌面构建、根定向回归及独立 code review；全仓测试不运行。新构建冻结后才重新从正常向导跑全书，所有场景与正文完整性、发布及正常关闭重开逐项核实，未经实际执行仍为未通过。
