1. **[P2] #12 Linux 恢复默认快捷键清错命名空间。** [ShortcutSettings.tsx:157](https://github.com/shyser/shakeink-desktop/blob/a86523815a6c3744b8cf38fd78970c4cf4b87074/src/components/desktop/ShortcutSettings.tsx#L157)。新增 Linux 平台后，读取、编辑和删除使用 `shortcutNamespace("linux") === "win32"`，恢复按钮仍清空 `[platform]`，即 `linux`。实际组件的恢复按钮闭包执行后，Linux 的 `ai.send=["Ctrl+Enter"]` 仍在，Windows/macOS 清除成功。应统一恢复操作的命名空间，并覆盖编辑、恢复、重新读取及真实按键链路。复现仅模拟 React/view/store 环境，执行的是原组件闭包，**不是 Linux 真机 UI 验收**。
2. **[P2] #13 显式 Responses 仍按官方同名模型推断额外能力。** [provider.ts:80](https://github.com/autoConfiguration/shakeink-desktop/blob/dcb6ca9b626c302586a927da4600a7c23acf90f8/src/lib/ai/provider.ts#L80)。取消 SDK 型号推断的选项只用于显式 Chat。直接调用未修改的生产 `instantiateModel`，相同自定义 Responses 配置将型号从未知名称换成 `gpt-6.1-sol`，请求就把 `system` 改为 `developer`、添加 `include:["reasoning.encrypted_content"]` 并去掉 `temperature`。配置测试没有这些参数，所以只支持普通 Responses 的中转可能测试通过、实际生成失败。应对显式 Responses 同样执行独立接口策略，并断言配置测试和实际 SDK 的请求约束一致。
3. **[P2] #13 无效工具调用仍绕过空输出防护。** [validatedModel.ts:40](https://github.com/autoConfiguration/shakeink-desktop/blob/dcb6ca9b626c302586a927da4600a7c23acf90f8/src/lib/ai/validatedModel.ts#L40)，非流式分支第 23 行有同类缺口。新增守卫把任何 `tool-call` 计作有效产物。未开放任何工具的正文生成收到未知工具调用后，生产模型和真实 SDK 返回 `text:""`、`finishReason:"tool-calls"`、没有 `onError`，只将该工具标为 `invalid:true`。由原 `generate.ts:84–97、120` 的调用与返回逻辑可知，该业务入口仍可空文本成功；本次动态复现直接调用生产 `instantiateModel` 和真实 SDK，未将它冒充完整 `generateText` 业务入口执行。PR 的“有效工具调用”目标仍未覆盖此情形。至少无 `tools` 的生成必须要求正文；开放工具的路径应在适当的 SDK 修复/校验边界检查有效结果。现有 RELAY-09 也把未开放工具的纯调用当作成功，应补反例。本项是本次修复目标的缺口，不宣称它是新增的旧功能回归。

## 复核排除项与环境修正

早期怀疑 builder 为 AppImage 注入的 `--no-sandbox` 会禁用产品沙箱，主代理发现产品入口已有 `app.enableSandbox()`。锁定 Electron 的源码会主动移除此参数，实际最小进程也验证 `noSandbox:true→false`、`enableSandbox:false→true`，因此**撤回此误报，不列为缺陷**。依据：[Electron 44.6.0 实现](https://github.com/electron/electron/blob/v44.6.0/shell/browser/api/electron_api_app.cc#L1446)。Linux 实际沙箱仍保留待真机验收。

首次构建的依赖符号链接被 Turbopack 拒绝，后改为独立文件副本；沙箱内 Next 编译停滞后，在隔离目录的沙箱外执行标准构建成功。首次原生测试使用 macOS `/var` 路径别名触发目录保护，规范化测试根后通过。首次自制 ZIP 含资源分支，已改用 `ditto --norsrc`；系统 `/usr/bin/true` 签名探针在沙箱内报 `CSSMERR_TP_NOT_TRUSTED`，沙箱外实际命令通过。这些测试环境问题与 PR 的三项产品缺陷分开记录，保留初轮日志。

本轮原生离线检查使用 Playwright 的隔离浏览器 offline 设置与无模型初始状态，未改变操作系统网络；它证明被检查的本地工作台和持久化链路，不等同于目标机器真正断网首启。
