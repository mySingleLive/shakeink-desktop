# 统一来源选择：跨平台产品增补

日期：2026-10-26。用户已明确选择“其他平台也必须统一，需要另做文件选择界面”。此要求替代14方案中将Windows双入口作为终态的范围假设。

## 调研结论

[Electron 官方 dialog 文档](https://www.electronjs.org/docs/latest/api/dialog) 说明 Windows/Linux 不能在一个原生框同时选择文件和目录。macOS 可使用同一个原生框。通过先选文件/文件夹模式规避限制与用户要求冲突，因此其他平台采用应用内统一来源选择界面。

当前正式应用 Bootstrap 只登记 darwin/win32；本次需覆盖 macOS 与 Windows，不因选择器增加就声称完整支持 Linux。未来 Linux 接入时应复用统一选择界面的能力，不使用 Electron 组合属性冒充混选。

## 产品要求

1. 侧栏、文件菜单、可配置快捷键均只有面向用户的“导入作品”语义。点击后直接选来源，不先问文件或文件夹；已有导入草稿时维持恢复语义。
2. macOS 使用系统原生多选框；Windows 使用应用内统一来源选择框。同一列表中列出文件夹和受支持的文本文件，行前复选框允许选择一到多个文件、文件夹，也允许混选；最终以实际选中的文件系统项目类型分流。
3. 文件夹可单击勾选、双击或点击行尾“打开文件夹”进入；勾选与导航互不替代。顶部“上一级”、面包屑和常用位置用于浏览；勾选状态在进入不同目录后保留，底部集中展示全部已选来源，可逐项移除。
4. 当前目录可通过“选中当前文件夹”复选框纳入，便于导入正在浏览的目录；这属于选择项目，不是文件/文件夹模式切换。取消当前目录勾选不清除其他选择。
5. 显示支持的 txt、md、doc、docx、pdf、html、htm 文件。未知格式显示禁用并标明“不支持”；受保护、无权限或无法访问的项目不可选择。搜索只筛选当前目录，不触发全盘搜索或后台读取正文。
6. 尚未选择时确认按钮禁用；点击“选择”将选择项交给既有核对来源流程，文件夹递归扫描在确认后进行。选择框中只浏览项目名称/类型/大小等必要信息，不读取或发送正文、不调用AI。
7. 取消或关闭不创建导入任务、不改变已有来源。初次选择与“添加来源”使用同一个界面；不再显示“添加文件/添加文件夹”两个按钮。追加重复或重叠目录仍由既有扫描器统一处理并提示。
8. 目录载入显示等待状态；无权限、目录消失和读取失败展示就地错误，保留已有选择，可返回上一级/其他位置。确认前重新检查项目身份，项目变化要求重新选择，不静默替换目标。
9. 键盘可使用 Tab、Space、Enter、上下方向键操作；Esc 取消选择。列表和底部已选列表有清晰标签；小窗口可滚动，确认按钮始终可达。沿用玄墨/宣纸主题和既有对话框样式。

## 新增UI审核边界

HTML 使用合成文件树与示意盘符，不访问用户文件；只审核交互与视觉。通过独立子代理审核后交用户确认，再撰写新增选择器技术方案和定向用例，不把静态稿当作文件授权、目录读取或Windows原生验收。

macOS 已完成的窄修改可继续定向验证；跨平台任务最终完成仍依赖新增界面获批、技术/测试审核、实现与验证。

## 独立产品审核

审核者：独立子代理 `unified_picker_review`。日期：2026-10-26。结论：**产品增补审核通过，可进入新增 HTML/UI 独立审核，再交用户确认。** 本审核只读核对本文件、14方案及用户最新跨平台要求，没有运行测试、修改技术方案或生产代码。

本方案将 Windows 的文件与目录放在同一来源列表，取消预先选择类型的模式；macOS 延续同一个系统选择框，符合用户希望由实际选择决定来源类型的要求。列表复选框负责选择，双击/行尾入口负责进入文件夹；“选中当前文件夹”补足正在浏览的目录自身的选择。跨目录保留选择与集中移除能避免导航覆盖用户已选来源，混选及重叠选择交由既有扫描器处理。

取消/关闭无副作用、正文及递归扫描只在确认后发生、不调用 AI、载入/读取错误保留选择及身份变化要求重选均有明确约束。小窗口、键盘与两种主题纳入设计审核，Bootstrap 的 darwin/win32 范围与完整 Linux 支持明确分开，没有用模拟选择界面声称其他系统已验收。

后续 UI 核对重点：进入文件夹与勾选的点击区域应有明确区别，单击勾选不能同时导航；“选中当前文件夹”不清除其他选项；空选择禁用确认，错误/搜索/跨目录导航后底部仍能查看及移除全部已选项。静态稿应能演示这些状态；真实文件权限和身份校验留待获批后的技术方案及定向验证。
