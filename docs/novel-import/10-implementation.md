# 导入作品实施记录

2026-10-25 至 2026-10-26。以用户批准的 v4 UI 为基础，按技术方案与已审核的 52 项定向用例编号实施。代码、构建与实际验收结果分开记录；不运行全量测试。

| 范围 | 实际实现 |
| --- | --- |
| 严格契约 | `desktop/shared/novel-import.ts`：13 类来源与独立的 12 类补全目标、版本化动作、最小 renderer view，路径来自主进程原生选择 |
| 文件读取 | `desktop/main/novel-import-files.ts`：七种扩展名、递归/排序/排除、编码确认、只读身份/hash 校验、ZIP 限额、Word 附件与 PDF 页核对 |
| 领域与流程 | `desktop/core/novel-import.ts`、`desktop/main/novel-import.ts`：来源覆盖、完整正文切片、原文与工作副本、分批识别/补全/复核、持久任务、冲突决定及修改提案 |
| 模型与生命周期 | `desktop/service/novel-import-ai.ts`、主进程/worker/preload 接线：固定文本及审核模型、两次范围确认、每操作取消、等待排空后关闭数据 |

| 两条线 | worldline 的线/事件/父事件/角色/时间映射至实际规划 ID；narrative 的章索引/顺序/视角/事件披露映射至原生卡片；未知事实不捏造时间 |
| 真实入口 | 原生文件菜单、侧栏导入文件/文件夹、收起恢复任务、`NovelImportDialog`；复用已有工作台与业务面板 |
| 原材料核对 | 作品概览与真正注册的大纲投影面板提供 `NovelImportRecord`；本地只读 handler 分页返回完整原大纲/设定/最初正文 |

纯拷贝路径不调用模型，包括最终复核；不会声称已完成全书语义分析。AI 处理必须完整覆盖实际分批单元，来源引用与结构校验不代替真实供应商验收。已有冲突由作者决定，改正文先显示差异并逐处二次确认；原文件不变。

PDF 采用保守的纯文本导入边界：逐页核对文字并检查本地 PDF.js 的栅格图像绘制操作。即使页面能提取页码，只要含正文扫描图或其他栅格图片，也明确阻止导入并提示“PDF含无法核对全文的图像内容，请转为纯文本/OCR后重新导入”；本功能不执行 OCR。此限制也会拒绝带装饰位图的文本 PDF，需要用户先转为可核对的纯文本文件。图片解码有400万像素上限，超限同样作为图像内容待处理，不截取剩余页码冒充全文。

DOC/DOCX 的脚注、尾注、批注、页眉页脚和文本框独立标为附件待核对，全部部件字符范围连续覆盖提取结果。来源验证同时保留最初授权父目录链的设备/inode；即使叶文件 inode、hash 与时间戳不变，父目录被替换也须重新选择来源。

发布内容指纹同时绑定私有会话、目录预留、manifest、catalog、内容回执与原材料版本；遇到创建/提交/登记的未知结果，只能用原请求及原物理目录恢复。异常锁恢复先核对已有预留，再关闭数据库、确认本机原进程退出并明确确认，不能凭新请求抢锁。

生产不包含 `design/novel-import/` 示例、测试源文件或调试成功状态。新增依赖为 MIT 的 htmlparser2/word-extractor，以及从开发依赖提升至运行依赖的 JSZip/PDF.js；不新增数据库迁移。

独立审核分别见 `11-review-publish.md`、`11-review-engine.md`、`11-review-ui.md`；解析器及运行时接线由主代理独立组合审核。最终命令、结果、原生/受控界限与未执行项见后续验证报告。

最终组合补充：导入记录已登记到迁移路由台账并通过真实LocalDispatcher回读；私有journal的精确UUID/.owner/session.json归属规则由根清单和迁移两道边界共同复用，真实迁移后重新加载同一会话。最终原生文件/文件夹落盘及重开通过，见12报告。
