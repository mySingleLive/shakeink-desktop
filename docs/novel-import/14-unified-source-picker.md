# 导入入口调整：统一选择文件与文件夹

日期：2026-10-26。依据用户本轮截图与要求，覆盖此前入口的文件/文件夹下拉设计。

## 技术方案

- 左导航保留一个完整的“导入作品”按钮，移除箭头和下拉列表。当前有导入任务时仍恢复该任务。
- macOS 点击入口直接打开一个原生对话框，配置 `openFile`、`openDirectory`、`multiSelections`，保留七种文本扩展名过滤。可多选文件或选文件夹；不再要求先选择类型。“核对来源”中的补加操作也使用同一入口。
- 主进程继续只信任系统返回的路径。既有 `scanNovelSources` 逐项 `lstat` 判断实际类型，目录递归、文件提取；保持只读、顺序、去重、受保护路径与链接检查。取消选择不创建任务、不改变已有来源。
- `choose` 动作的 `mode` 改为可选：新入口不传类型；保留旧的显式模式作为其他平台兼容入口。没有模式时 macOS 使用统一选择框；Windows 保留既有文件选择能力及原生菜单/添加文件夹入口，避免 Electron 将组合属性降级成只能选目录。
- 官方平台边界：[Electron dialog](https://www.electronjs.org/docs/latest/api/dialog) 明确 Windows/Linux 不支持原生文件与目录混选。这次先实现当前 macOS，已向用户异步确认其他平台是否需要单独设计选择界面；不将 macOS 验证记为其他平台通过。
- HTML 设计稿同步移除入口下拉与先选类型的步骤，仅反映用户已明确要求的修改，不重开 UI 批准。

## 审核与验证顺序

技术方案独立审核 → 定向用例及独立审核 → 失败用例 → 实现 → 定向转绿 → 独立代码审核 → 本机原生选择框验证与构建。禁止全量测试；实际结果在完成后追加。

## 技术方案独立审核

审核者：独立子代理 `unified_picker_review`。日期：2026-10-26。结论：**当前 macOS 的窄修改方案通过，可以进入定向测试用例设计。** 本审核只读核对上述方案及六处已列明源码接点，未运行任何测试或修改生产代码。

现有扫描器已逐项检查系统返回路径的实际文件类型，能够使用同一输入列表处理文件及递归目录；不需要由 renderer 声明来源类型，也不需要改动解析、推断和发布流程。将 `choose.mode` 设为可选且继续使用 strict schema，保留主进程原生选择结果与窗口归属校验，能将本次改动限制在入口及选择器策略。

定向用例必须具体核对：左导航和原生“导入作品”命令均走不传模式的新动作；macOS 同一真实原生选择框的多文件与文件夹两条路径；核对来源的补加同样统一，取消补加保持来源及 revision 不变；真实文件与目录输入能由扫描器正确分流，混合/重叠选择仍使用现有去重和只读边界。应保留 Windows 的独立目录能力并验证其不使用组合属性，不能只删除导航菜单后使目录导入不可达。

Windows/Linux 的统一交互尚未得到用户范围答复；本结论仅支持文档已明确的 macOS 先行及其他平台保持既有能力，不代表全平台要求已经满足。若用户要求所有平台统一，应先补充相应技术方案与用例，再实施其选择界面。

补充接点复核：darwin 对旧显式模式仍使用统一原生选择框；macOS 的 `desktopMenu` 隐藏冗余 `file.import-folder`，命令 ID 与已有快捷键保留；Windows 菜单与 SourceScreen 的目录入口继续可达。这些接点与既有命令注册/分派兼容，无需扩展命令 schema。应在用例中同时断言 macOS 菜单去重、旧命令兼容分派与 Windows 目录入口保留；没有新增必须退回的技术缺口。
