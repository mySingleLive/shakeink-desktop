| ID | 输入/操作 | 预期及执行层 |
| --- | --- | --- |
| UP-01 | 无 mode 的 choose、append；原有显式 files/folder；夹带任意 path | 新语义可解析，旧语义兼容，伪造路径拒绝。定向 protocol 用例 |
| UP-02 | 真实 chooseNovelSources 函数，darwin 无 mode 和旧模式；win32 两种旧模式；取消 | mac 属性同时允许文件、目录、多选与扩展名过滤；Win 不用组合属性；取消返回 null；preload 原样转发无 mode 动作。更新 NI-L01，仅执行该用例 |

| UP-05 | 原 SidebarTree JSX 与 desktopMenu | 无“更多导入方式”下拉，整行单按钮直接 requestNovelImport()；mac 文件菜单只出现导入作品，win32 保留导入文件夹；兼容命令 ID 不删除。定向 AST/菜单断言 |
| UP-06 | 当前 macOS 实际编译应用，隔离数据/合成文件，通过同一侧栏按钮分别选两个文件、一个目录；取消追加 | 真实 OS 选择框接受两种选择；来源清单与逐字文本正确；取消保持清单和 revision；无下拉；原生菜单去重。独立 picker 验证脚本+CUA，不接管 picker、不写用户数据、不调用模型/发布 |

## 定向用例独立审核

审核者：独立子代理 `unified_picker_review`。日期：2026-10-26。结论：**UP-01–UP-06 独立审核通过，可进入 TDD。** 本审核只核对 14 技术方案与本用例文档，未运行测试、启动应用或修改生产源码。

用例覆盖本轮核心链路：单按钮入口 → 无模式 IPC → macOS 统一原生选择框 → 按实际类型扫描 → 来源补加/取消/已有任务恢复。协议和主进程门控、真实扫描器与文本保真、实际 React、导航/菜单及真实 macOS 选择分别有证据层；受控 bridge 和模拟平台断言不冒充原生平台验收。测试范围未扩展到既有推断、冲突、发布或全仓用例，符合用户禁止全量测试的约束。

执行时将以下细节纳入现有编号，不增加额外测试范围：UP-02 同时核对 win32 无 mode 的默认文件选择，避免新侧栏入口在 Windows 退化成仅目录；UP-05 核对原生 `file.import` 命令不传 mode、保留的旧 `file.import-folder` 仍能分派，以及 HTML 示例不再显示旧下拉或要求先选类型。UP-06 的“不接管 picker”按“不替换或伪造原生选择结果”执行，由 CUA 操作真正的 OS 选择框。
