## 目标与边界

把已有小说文件或包含正文/设定的目录导入为一个新的独立作品：保留作者文本，识别已有资料，从正文补齐缺失资料，询问事实冲突，生成世界线与叙事线。支持 txt、doc、docx、md、pdf、html、htm。保留当前真实 DashboardShell、SidebarTree、ChatPanel、ContentTabs、业务面板和 MarkdownEditor。

不扩展成批量多书导入、覆盖/合并已有作品、备份恢复、在线抓取、自动 OCR、图片/音频分析或重新创作原正文。一次选取的所有文件属于同一本书；混入其他作品时在核对清单中移除。无正文的设定集也能形成独立作品。

## 入口与整体流程

左导航在“创建作品”之后、“新对话”之前增加“导入作品”行（32px，与既有入口一致），Upload 图标；行末独立下拉箭头提供“从文件夹导入”。原生文件菜单增加“导入作品…”与“从文件夹导入作品…”；不占用 Cmd/Ctrl+O，不改变“打开作品目录”。快捷键目录可配置，初始不额外预占按键。

主按钮或菜单点击后立即弹原生文件选择器（多选、支持格式过滤）；文件夹子入口立即弹原生目录选择器。取消选择回原界面，不建书。任务进行中重新触发入口打开当前导入会话，避免重复任务。没有其他任务时重新触发可新建。

选择 → 本地读取/提取 → 核对文件与正文 → 识别并选择内容 → 确认补全范围、模型和保存位置 → 正文起点逆向导入 → 按需询问冲突 → 一致性复核 → 原子发布 → 打开真实作品。

选文件后显示一个可滚动模态；顶部标题“导入作品”，下方三步轻量进度“核对来源 / 选择内容 / 导入”。底部固定返回/继续，错误靠近相关字段。运行阶段可收起到导航任务条，不能把关闭视为成功或丢弃。

2026-10-25 用户修订：来源清单使用真实文件类型图标；选择页不展示右侧导入计划，计划移至确认导入页；可选类别整卡手形可点击，来源按钮独立打开预览且不改变勾选，未识别类别仍禁用；补全标题为“根据正文补全以下内容”；AI 分类授权后、选择内容前增加“内容识别中”等待动画。

## NI-01 来源与原文核对

- 文件清单显示相对路径、格式、提取状态；所有支持文件默认包含。目录递归，按数字自然顺序排序；用户可调整顺序、排除文件、重新选择或补加文件/文件夹。
- 每文件可预览完整提取文本（分页/虚拟滚动），含页码/段落/行位置。原文只读；分类、章节切分、顺序及去重均为旁路标注。重名不合并；内容哈希相同提示重复，用户确认后排除一份。部分相同不能自动去重。
- txt/md 编码无法确定或有替换字符时，提供编码重选与前后对照；确认前阻止下一步。不能 trim、替换标点、自动繁简转换或重排段落。
- PDF、Word、HTML 的承诺是“核对提取文本后，正文逐字导入，不由 AI 改写”；页面提供“查看提取文本”。图像页/损坏/加密/缺字、无文本、过大、权限变化逐项可见。含失败文件时可重试或明确排除，不能悄悄忽略。
- 正文/设定边界与卷章标题可以校正。标题留在保真段落序列中，不因提取到章节标题而丢失字符；章节内容拼接按原顺序与确认的正文范围逐字相等。跨章节空白明确归属，不能自动删。
- 无明确标题的长篇保留为“未分章正文”，可按用户指定边界切分，不用 AI 重写章名或正文。扉页、目录和设定附录先标候选，最终范围由用户核对。
- 所有文本都有来源位置；未归类片段单列“待归类”，必须明确归入正文/某设定/排除，未解决不得继续。多个文件角色同名、正文卷章重号提示核对，不能静默覆盖。

## NI-02 识别与来源内容多选

识别先用明确文件名/标题/样式与范围规则，再用已配置模型做语义分类。模型只输出源位置与分类，不能重写来源；所有文件与片段覆盖完才显示识别结束。没有模型可核对明确分类并手动指定；需模型时提供配置/重试入口，不假装已识别全部内容。

首次语义分类严格发生在本地提取、来源核对之后：先展示“允许模型识别内容？”确认层，按已纳入文件清单列出拟发送的提取文本范围、接收的实际模型/端点；此时不引用尚未生成的来源类别选择。用户可返回排除文件或片段，也可选择“仅本地分类”。点击“允许识别”后才发送。分类授权只覆盖该次确认的源文本指纹、范围和模型；不得预先运行模型再询问。手动分类结束后无需此确认。

AI 请求开始后进入“内容识别中”：说明正在识别正文、大纲、角色、世界观等内容成分，显示持续等待动画与所处理的文件范围，不展示无依据的百分比或预计耗时。识别结果完整可用才进入选择页；允许收起后恢复当前识别任务、或取消识别返回来源并保留核对信息。无模型和仅本地分类不假称正在用 AI。正式产品由真实请求回执结束等待；HTML 合成审核稿通过窗口外的“完成合成识别”演示结束，不调用模型。

对话框询问“要导入哪些内容？”列正文、大纲、主题、文风、世界观、角色、场景、物品、伏笔、金手指、爽点/泪点、世界线、叙事线，共13类。存在有效来源片段的类别默认全勾；没有片段的置灰、不勾选，并标“未识别到”。不以模型猜测冒充来源已有设定。

2026-10-25 用户追加修订：移除“其他设定”泛称，采用软件已有的“爽点/泪点”和“文风”。依据 `SidebarTree.tsx` 的对应入口与 `src/lib/setting-types.ts`；爽点/泪点为 Trope（SATISFACTION/TEAR），金手指为 Setting（GOLD_FINGER），文风为 Setting（STYLE），三者独立。等级/力量/势力/地图等现有世界级设定仍归入世界观，不新造类别。

每个可用类别显示来源文件/片段数和“查看来源”，正文另显示已核对卷章数。低置信度必须核对或手动归类后才计入可用项；原设定只拷贝，不摘要代替。至少选择一项才可开始。用户取消勾选的来源类别不得导入原文。

## NI-03 独立的正文分析补全

选中正文时，来源列表下方显示默认开启的“根据正文补全以下内容”。大纲、主题、文风、角色、场景、物品、世界观、伏笔、金手指、爽点/泪点、世界线、叙事线共12项补全目标始终展开，使用整卡可点击的复选卡片，不提供展开/收起按钮。默认全部勾选，用户可逐类关闭；关闭补全总开关只禁用卡片，不隐藏列表。爽点/泪点和文风也遵循有原文先拷贝、缺失时有证据才分析的规则。

本轮用户调整选项形式：“从文件直接导入”为普通复选框列表，保留已识别默认勾选、未识别禁用、独立查看来源；“根据正文补全以下内容”为选项卡片。两组选项的来源/补全语义不互换，选择独立保存；未选中正文时仍进入仅拷贝路径，不展示正文补全选项。

这组控制是“允许推断哪些缺失内容”，不改变上方“未识别到”的禁用状态。已有且勾选的来源先原样导入；勾选补全可补证据充分的缺项，但不能自动重写已有字段。用户取消的来源类、但补全仍开启时，在摘要明确显示“角色：不导入源设定，仅从正文分析”，避免相反意图被隐藏。

选中正文但关闭全部补全时，允许保真拷贝正文与已选设定，流程跳过推断并显示“仅导入原文，未分析全书”。没有选中正文（包括检测到但取消勾选），不运行正文推断，隐藏补全选项，仅按选中的设定原文拷贝；已识别的世界线/叙事线可直拷贝/映射，不能从无正文材料编造两条线。

正文补全依据为完整的所选正文，之后参考已导入大纲与人物资料；来源冲突未决时不能将有争议字段当事实输入下游。伏笔、金手指、主题无可靠证据可标“未发现/待确认”，不补写故事。区分客观事实、角色陈述、推测、不可靠叙述；未明示未来情节不能当既成事实。

## NI-04 开始前确认

- 书名：从文件/文件夹名建议，可修改，1–100 字；不会改来源名称。
- 保存位置：选择与来源分离的独立空目录，支持默认作品父目录下新建。源/目标相同、互为祖先或在应用内部数据目录时阻止；目标已存在作品时引导更换，不能覆写。目标冲突/权限错误当场显示。
- 模型：显示实际文本模型、审核模型及配置可用状态；没有配置时显示真实空态。需 AI 分类/分析时禁用相应继续操作，可先手动归类并只拷贝原文；模型配置返回保留会话。
- 发送范围分两次确认：分类前按 NI-02 的文件/片段范围点击“允许识别”；内容多选确定后，分析前展示实际所选正文、已选设定及推断目标，点击“允许分析并导入”才开始推断。纯本地拷贝不发送。模型/端点、源文本指纹或发送范围扩大后使原授权失效并重新确认。
- 摘要：选入来源类别、推断目标、跳过类别、章节顺序、待排除文件和原文保真说明。保存位置选妥、来源核对结束、所选范围有效才启用“开始导入”。

## NI-05 正文起点的逆向工作流

| 顺序 | 行为 | 保留/推断规则 |
| --- | --- | --- |
| 1 正文 | 按确认范围/章节顺序拷贝原文 | 校验字符与来源映射；AI 无正文写权限 |
| 2 大纲 | 有来源则保留已有大纲，否则从正文还原 | 已有大纲与正文矛盾先询问；原文保存到正式大纲可访问位置，规划映射不能覆盖原文 |
| 3 角色 | 先导入原角色设定，再解析正文与大纲提及人物 | 别名、同名不同人必须区分，证据不足待确认；覆盖整书提及人物 |
| 4 场景与物品 | 原设定优先直拷贝，缺项依正文与已决人物推断 | 实体关系追溯到具体源段落，不编造描述 |
| 5 世界观 | 导入已有世界/规则，补齐正文已证实规则 | 不把角色传闻当世界事实 |
| 6 主题、文风与情节设定 | 主题、文风、伏笔、金手指、爽点/泪点 | 无证据保留空缺；低把握列待确认 |
| 7 世界线 | 依正文和已决设定构建客观事件及时间关系 | 可保留未知时间；保留导入世界线原文，有冲突询问 |
| 8 叙事线 | 依原卷章阅读顺序构建披露、视角与事件引用 | 保留倒叙/插叙，不按世界时间重排正文；保留已有叙事线原文 |
| 9 一致性复核 | 检查所选范围全部来源覆盖、引用、冲突、正文哈希与依赖 | 未解决疑点/冲突不允许“导入完成” |
| 10 发布 | 一次发布可用作品与会话结果 | 打开原 NovelOverview/正文/设定面板，不另建业务工作台 |

步骤只运行用户选择的目标；每一项明确“直接拷贝 / 正文分析 / 已跳过 / 待你确认 / 失败 / 完成”。不会为了满足步骤顺序假造完成计数。已有资料映射失败时保留原文并询问，不截断或拆字段丢失信息。

无正文路径：拷贝已选大纲/角色/主题/世界观/场景/物品/伏笔/金手指及其他来源 → 保留原有引用（无法映射则提示）→ 来源之间的一致性与结构检查 → 发布。只指出来源中的明确矛盾，不生成缺失剧情、人物、两条线或假装全书分析完成。

## NI-06 冲突询问与正文修改

检测到设定和正文、设定之间、正文内部的矛盾时暂停相关步骤。询问框含冲突主体/字段、原设定全文定位、正文证据（可多章）、推断候选、受影响的下游内容。决定绑定当前来源版本；不提供无条件“后续都按此处理”。

每项提供三种明确决策，默认不选择：

1. **坚持导入原设定**：保留原设定，填写解释/指定证据，或把错误的实体/语义识别修正。解释能消除矛盾才通过；只坚持而没有解释仍待解决，可保存后处理。
2. **使用推断出的设定**：展示设定字段修改对照，用户确认后只修改作品内该设定，保留原设定快照与来源；正文原文保持。对证据不充分的推断仍标待确认。
3. **保持原设定，但修改正文**：生成修改建议，逐处原文/拟改文对照；必须用户勾选改动并再次确认，才修改导入作品内的正文。来源文件始终只读、初次导入原文快照保留；更新过的正文显示“经你确认修改”，原文保证不扩张为未发生修改。

可“暂不决定”，保持导入草稿。应用决定后重算受影响的大纲、实体、两条线与一致性检查，不直接进入完成。若候选仍有冲突继续询问。人工修正、版本变化或重试导致旧决定不再适用时重新询问。

上面的三项用于存在已选正文、且原设定与正文推断冲突的情况。其他冲突按对象提供有效选项：纯正文矛盾可修正识别关系/补充解释或逐处批准正文修改，不出现不存在的“原设定”；无正文或设定彼此冲突只提供“保留来源 A / 保留来源 B / 手动合并与解释”，显示两侧原文，不能生成第三种模型事实，也不显示修改正文选项。多来源超过两份时逐份列出候选，保留未选原文快照；有正文时若取舍影响已决事实，仍须重检正文相关一致性。

系统不能证明文学作品的绝对逻辑正确；交付条件是所选范围覆盖完整、明确冲突清零、未明示事实不过度断言、引用完整、用户决策留痕。结果不得显示“AI 已保证绝对正确”。

## NI-07 暂停、失败、恢复与发布

- 进度只显示实际文件/章节覆盖与完成步骤；未知总量使用活动状态，不展示虚构百分比、剩余时长或模型费用。
- 可暂停、继续、收起；暂停等待在途请求停止/结束后才确认“已暂停”。模型失败、上下文预算不足、权限变化、空间不足提供实际原因和从检查点重试，不重复创建实体。
- 提取与分析按全量来源分块，保留每块覆盖状态、证据引用和跨章实体关联；任何片段未处理时不允许宣称全书分析完成。不把头几章抽样当完整导入。
- 意外退出后发现未完成会话时提供“继续导入 / 丢弃草稿”。来源变更需重新核对并使受影响的分析与决定失效；无法找回来源时提示重新选择，不从同名文件推定相同来源。
- 运行中取消需明确“停止并保留草稿 / 丢弃导入草稿 / 继续导入”；丢弃只清理本次拥有的临时数据，不能删除来源、用户预先存在的目录或其他作品。关闭窗口按未完成会话处理。
- 最终发布前核对当前源指纹、目标目录、writer lease 与结果版本；中途目录/作者上下文变化暂停任务，不能写入另一个作品。最终发布与目录登记需提供全有或全无的可恢复语义；具体机制在 UI 批准后的技术方案确定。
- 现有作品列表只接收已发布结果；中间草稿在独立“导入中”任务条可恢复。未知发布结果按同一请求查询，不能新请求再建一本。

## NI-08 完成与可访问性

完成摘要按直接导入、经正文分析、跳过/未发现、人工修改展示实际数量、来源覆盖和全部冲突结果；不以所选范围完成冒充所有可选业务都已补齐。无正文或关闭补全时明确“仅导入所选资料，未执行全书推断”。

操作为“打开作品”“查看导入记录”，记录可从作品概览再次访问。点击正文打开原正文面板，点击角色打开原角色面板。空白记录不显示伪造计数。

模态最大 920px，视口四周至少 16px，低窗正文滚动、头尾固定；640px 以下分栏堆叠，冲突对照竖排。宣纸/玄墨沿原令牌，焦点可见、状态不只靠颜色；复选用原生/现有组件，禁用原因与标签关联。Tab 约束在模态、关闭回到原触发入口；运行 Escape 等同收起，未提交编辑 Escape 进入离开提示，不能无声丢弃决定。
