## 文件选择与解析可行性

Electron 的原生打开对话框支持多选文件，官方明确 Windows/Linux 不能在同一对话框同时选择文件与目录。主入口立即打开多选文件对话框；旁边的“从文件夹导入”直接打开目录选择器，菜单也有同名独立项；macOS 同样提供两项，避免平台行为差异。[Electron dialog 官方文档](https://www.electronjs.org/docs/latest/api/dialog)。

| 格式 | 本地提取策略候选 | 必须向用户展示的边界 |
| --- | --- | --- |
| txt / md | 确认编码后解码；原文和分析副本分离 | UTF-8、UTF-16 BOM、GB18030 候选；乱码不得静默替换；MD 不渲染执行 |
| doc | 纯 Node Word 二进制提取候选，后续用真实 OLE fixture 验证 | 不依赖用户安装 Office；密码、损坏、伪扩展名逐项报告 |
| docx | 解析段落、样式和表格并建立文本位置映射 | 文本导入不等于版式还原；保留段落/表格文字及源文定位 |
| pdf | 本地 PDF.js 提取文本项、页面与位置；按阅读顺序预览 | PDF 提取可能有换行/空白差异；扫描页、缺字、复杂排版需用户核对，不生成不存在的字 |
| html / htm | 惰性解析为文本，保留段落/标题/表格文字 | 不执行脚本、不加载外链；导航/页眉等先标记，不能擅自删除可能的正文 |

`word-extractor` 官方仓库声明支持 OLE `.doc` 与 `.docx`、Buffer 输入及正文提取，无需 Office 或原生二进制，适合作为评估候选；这不是本项目已经验证通过。[官方仓库](https://github.com/morungos/node-word-extractor)。

Mammoth 的原始文本 API 会忽略格式，并在每段后添加两个换行，不能直接称为“逐字保真”的通用方案。若使用它，必须保留段落映射、明确提取结果预览并单独验证。[Mammoth API](https://github.com/mwilliamson/mammoth.js#api)。

PDF.js 的文本 API 明确说明空白字符会替换成标准空格。因此“正文原封不动”应落实为：确认提取结果后，导入层逐字拷贝该正文，AI 不改写；保留来源文件与映射以核对。不能承诺从任意 PDF 还原字节或版式。无文本层的页必须报告并阻止静默漏页；本次不自动 OCR。[PDF.js 官方 API 源码](https://mozilla.github.io/pdf.js/api/draft/api.js.html)。

文件夹按相对路径自然排序递归扫描，包括子文件夹；默认全部支持格式进入待导入清单，用户核对重复内容、卷章顺序及失败项。符号链接/别名、隐藏系统目录、应用作品内部数据不跨越读取；文件类型以扩展名和签名共同判断，所有排除均可见。不能以“扫描完目录”冒充“导入完所有正文”。

## 核心产品结论

1. 分开“来源内容”和“正文补全”。来源列表：检测到的默认勾选，未检测到的禁用。选中了正文时，另有默认启用的补全设置，补齐大纲/主题/人物/场景/物品/世界观/伏笔/金手指与两条线；无证据的内容不编造。
2. 正文只从来源拷贝，正文事实优先于模型猜测；来源设定有则拷贝，冲突进入询问。来源缺失才推断；不能用模型重新摘要替代已有原文。
3. 选中正文：正文 → 大纲 → 角色 → 场景/物品 → 世界观 → 主题/伏笔/金手指等 → 世界线 → 叙事线 → 一致性复核 → 提交。无选中正文：只拷贝选中来源设定，保留关联，基本不做事实推断。
4. “坚持原设定”不自动解决已证实的正文矛盾：需用户说明是别名/伪装/不可靠叙述等，或选择修改正文并逐处批准。未解决时保持草稿，不能完成为“整书一致”。
5. 完整小说不能一次塞进模型窗口。先全量提取与分块证据，维护实体别名、跨章关联和覆盖台账；任何被跳过的正文都必须阻止“全书分析完成”。
6. 没有模型也可本地选取、提取和识别明确标题；需要语义识别或推断时，先说明所用文本/审核模型和发送范围。无平台后备；配置模型后回到原步骤。
7. 导入会话可暂停、重试、恢复；正式作品只在所选范围完成、冲突清零、原文校验成功后发布。失败和取消不污染现有作品或来源。
