## 执行细节

以下属于现有编号的必需展开，不增加测试范围：

- CP-L01 和 CP-U02 必须各在真实的对应层验证取消：main/backend 有在途目录/confirm；renderer bridge 的navigate promise尚未返回、loading事件尚未送达时，Esc也立即发cancel。不能仅通过backend测试推断renderer没有排队。
- CP-F03 应包括确认时仍为同一对象、确认后扫描前被替换的窗口；至少一项直接文件和一项选中目录/祖先，断言替换文本不进入导入结果。不能只验证confirm前校验。
- CP-L02 的预算断言以真实未settle的控制promise计数，超时后的操作仍占预算；反复cancel/重开后不能继续启动更多IO，迟到opendir资源关闭。单纯断言超时返回不足以证明预算与句柄收敛。
- CP-L01/CP-B01 的main接线应逐项核对beginClose、stopTasks/closeData、worker失联、releaseOwner/主frame导航/窗口销毁及根迁移/修复入口；原choose等待应已解除，gate drain才能完成。测试不得为方便而把原choose预先替换成已完成promise。
- CP-U01 的双击在原未选和原已选目录均核对选择集合保持；触发的navigate只使用能力ID。CP-U02 的焦点验证至少包含目录加载前后、移除最后已选项和空/错误目录。
