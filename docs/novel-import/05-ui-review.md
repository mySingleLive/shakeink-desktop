## 待修订问题

### UI-01 · P1 · 返回来源核对会覆盖用户的内容取舍

位置：`preview.js` 的 `refreshSelection`，及 `approve-text`、`allow-classify`、`local-classify` 的调用。

`refreshSelection` 先与可用类型求交集，随后又把所有可用类型全部加入 `selected`。因此取消勾选“角色”后，查看正文来源并点击确认文本，就会重新勾上角色。产品 NI-03/04 和 UI 状态契约要求返回保留选择，不能把用户明确排除的设定重新加入。

建议：区分首次识别的默认全选与后续核对。后续只裁剪失效选项，新增可用项单独处理，不覆盖已有的明确取舍。补全目标与来源取舍的区别在摘要中直接说明。

### UI-02 · P1 · 逐类关闭补全没有对应到运行与完成状态

位置：`preview.js` 的 `progressRows`、`route`、`donePage`。

只要启用任何一个补全目标，`progressRows` 都列出大纲、人物、场景/物品、世界观、其他设定、世界线、叙事线全部步骤；用户关闭的类别仍会显示为“等待前序/处理中/完成”。`donePage` 则以已选目标减去直接导入类别作为“根据正文补全”的结果，无法表现“允许分析但未发现证据”。这使审核者难以确认逐类关闭的真实含义，也容易把目标当产物。

建议：按来源选择与逐类补全选择构建运行项，关闭项目显示“已跳过”；区分“分析范围”和“实际发现/生成结果”，完成摘要保留“未发现/未执行”，不要把许可目标直接视作已补齐的事实。这里只需合成状态可切换，不要求此阶段实现真正的推断算法。

### UI-03 · P2 · 导入任务收起后，原入口未恢复当前会话

位置：`preview.js` 中 `choose-files` / `choose-folder` 分支与 `minimize` / `reopen`。

任务条的 `reopen` 能恢复任务；但同一任务存在时，点击原“导入作品”主按钮或文件夹入口仍进入新文件选择位置示意。产品“任务进行中重新触发入口打开当前导入会话”没有体现在原型中，并可能让已开始任务与来源选择混用同一状态。

建议：存在未完成会话时，主入口和文件夹入口统一恢复该会话；只有明确丢弃/完成后才启动新选择。

### UI-04 · P2 · 冲突单选框重绘后焦点可能丢失

位置：`preview.js` 的 `conflictPage`、`change` 监听、`render(false)`。

冲突 radio 没有稳定 `id`。选中触发 `render(false)` 会替换整个 dialog DOM，而焦点恢复仅依赖旧元素的 `id`，因此无法恢复刚操作的 radio。箭头键连续比较选项和后续 Tab 路径可能受影响；补全展开按钮也缺少对应稳定焦点目标。

建议：为重绘涉及的 radio/按钮提供稳定标识，并按真实控件恢复焦点；仅在页面真正切换时聚焦标题，选择后保持当前选择控件。

### UI-05 · P2 · 文本范围核对未表达未纳入片段的去向

位置：`preview.js` 的 `previewPage`、`approve-text`，UI 设计“来源核对”契约。

原型对所有来源固定提供段落范围 1–2，而正文示例实际包含标题和多个段落。选择范围后没有显示哪些原文属于当前片段，也没有呈现范围外的待归类片段；改变分类会用一个类型覆盖整份文件的分类。这不能让用户审核“一份文件同时包含正文和设定”时如何确保所有文字有归属。

建议：使用合成文件的真实段落序列，标出当前片段；其他片段列为已归类/待归类/明确排除。没有必要实现真实格式解析，但需要让片段归属、边界修改与继续门控在原型中可见。

### UI-06 · P2 · 窄窗安全边距与文字契约不一致

位置：`preview.css` 的 `@media(max-width:700px)`，产品 NI-08 与 UI 布局规格。

窄窗将 dialog 宽高上限设为视口减 24px，边距降为 12px；产品与设计文档要求至少 16px。初始稿静态可见此差异，尚未有本审核者成功渲染的几何证据。

建议：统一为至少 16px，并由主代理的限定预览核对记录 390×600 / 560×640 的头尾可见、正文滚动与横向溢出结果。

## 已成立的主要设计

- 来源列表包含 12 类，有来源的默认勾选，无来源的禁用并显示原因；独立正文补全区没有把推断冒充原文件已有内容。
- 分类前的“允许识别”展示文件范围，后续“允许分析并导入”独立确认；无模型保留本地分类与仅拷贝路线。
- 没有正文时隐藏补全；来源冲突适配为保留 A / 保留 B / 手动合并，不显示修改正文。
- 正文冲突三选无默认；坚持原设定需要解释；采用推断显示字段差异；修改正文另开逐处勾选与二次批准页。
- 收起、暂停、保留/丢弃草稿都有明确动作；原生选择器、模型设置与业务面板衔接注明示意边界，不把此稿当真实安装版实现。
- 审核工具在产品预览之外，资料明确为合成；未发现供应商请求、应用 IPC 或真实用户资料采集。
