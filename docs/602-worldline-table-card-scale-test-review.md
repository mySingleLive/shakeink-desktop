## P1（必须修改）

### P1-1 等距模式全部展开后，展开卡比拉伸间距高时出现“签名变、画面不变”的步；夹具和真实目标都测不到

- 签名第 3 项按 `effStretch(min(cap, Δt·k))` 比较（`worldline-layout.ts` `tableZoomSignature`）。但全部展开时根块的实际位置是 `max(上一块底 + 间距, 上一根 + 拉伸)`，展开卡高于拉伸时拉伸不起作用，k 再变画面也不变。
- 实测：zoomView(24) 每个事件 `fact` 300 字（估计展开高度约 300px），等距放大从 +8 到 +13、+26 到 +32 共 13 个停点的卡片 top 与前一停点相同（≤ 0.5px），其余字段也相同（`/tmp/r602/h.ts`）。F885 缩小方向 −29 也有一处。事实为空的 zoomView(24)、zoomView(24, leavesOnly) 没有这种步，所以 TS-07、TSB-04 用的夹具恰好避开了它。
- 这是 S3“每步都有可见变化”在等距模式下的真实缺陷，LOTM 的事件事实很长，真实数据大概率会出现。§8 真实目标只记录 `data-card-scale`、`data-zoom-level`、`data-auto-open`、读数、卡片 / 时间点数、字号，等距模式在全部展开后这些值全都不变，“每步至少一项变化”的断言要么误报失败，要么实现者会把读数算进去而放过。
- 修改：
  1. TSB-04 增加一个 `fact` 较长（例如 `zoomView(24, { leavesOnly: true, fact: {…每个根 300 字} })`）的变体，沿用现有 `look()`（已含 `tops`），在全部展开后逐步断言 `tops` 变化。现实现下它会失败，这是该用例要抓的问题，需回到方案层定签名（例如全部展开时用估计高度判断拉伸是否生效，或在 §5 写为已知限制并经用户确认）。
  2. §8 真实目标的逐步记录加“视图内前 40 张卡片 / 时间点的屏幕 top（0.5px 取整）与相邻根间距”，等距模式的“每步至少一项变化”以它为准。

### P1-2 TSB-13 在回差实现出错时仍然通过

- 用例：zoomView(24) 缩到级别 3，点 `[data-legend-importance="1"]` 隐藏一般事件，再取消，断言级别 = `zoomLevel(d0, lvF)`。
- 实测（`/tmp/r602/f.ts`、`/tmp/r602/i.ts`）：在 −10 步（L3）隐藏重要度 1 后 d 变为 47.27 × e^e，画出 L2；取消后“按画出级别 L2 求回差”得 L3，“按存的级别 L3 求回差”也得 L3。两种实现结果相同，P2-1 的缺陷（只存步进时的级别）不会让用例失败。
- 能区分两者的场景在对齐停点上实测存在：复位（L1）隐藏重要度 2 或 3（d 变为 27.83 / 29.09，画出 L2），取消后正确结果为 L2，错误实现为 L1。
- 修改：TSB-13 改为在复位处隐藏重要度 2（或 3），断言筛选中级别为 2、取消后级别仍为 2（`d0 = 40 < 46`，回差保持）。同时保留 `assert.notEqual(期望值, zoomLevel(d0, 复位前级别))` 这一自检，证明场景能区分两种实现。

### P1-3 TSB-05 的标题截断检查是空检查

- 选择器是 `[data-card-title][data-lines="1"]:not([data-fade])`，判断条件是 `scrollWidth > clientWidth`。`useFade`（`EventCard.tsx:93-107`）在同一条件（`scrollWidth > clientWidth + 1`）下给标题加 `data-fade`。所以凡是被截断的标题都会被选择器排除，检查永远为空，§9.7 的 `TITLE_SLACK + 2` 去掉也不会失败。
- 方案 §10.2 写的“`data-fade` 的除外”与 P2-6 的要求（“凡 z = 1 下不截断的单行标题，在 s = 1.1、1.2 下也不截断”）不是同一件事。
- 修改：先在分级关（或 s = 1 的位置）收集不带 `data-fade` 的单行标题 id 集合 B；再到 s = 1.1、1.2，断言 B 中每个标题仍无 `data-fade`，且 `scrollWidth ≤ clientWidth + 1`。`data-fade` 由 ResizeObserver 异步设置，读之前等两帧。另外夹具要有接近卡宽上限的标题（zoomView 的 28 字长标题在 900 宽下会被 slot 截断，属于“布局判定需截断”），应补一个短于 slot 但宽于 220 的标题，才能测到估宽余量。
## P2（应修改）

### P2-1 TSB-11 没有测 P2-3 的场景

- §9.4 P2-3 的风险是：一个有效步让 `zoomKey` 变了但布局没有变（effect 不运行），之后不相关的提交消费旧键，把视图拉回第一张卡片。TSB-11 用工具栏 + 改变尺寸（布局一定变，恢复 effect 当场消费键），然后滚动、展开一张卡。去掉 §9.4 的“每次提交都回写”时它照样通过，因为键在第一次布局提交时已经比较过。
- 方案 §10.2 写的是“全部展开前一步（布局变、键变）后不操作，展开一张卡”，同样是布局变的步。
- 工作区实现中 `zoomKey = ${zScale}|${on}`（`EventTable.tsx:421`）。`zScale` 经 `layoutPlan.scale` 进入 `tableLayout`，`on` 经 `expanded` 进入，所以键变时布局一定变，P2-3 描述的“键变、布局不变”在当前实现中构造不出来，浏览器用例无法让它失败。
- 修改：§10 把 TSB-11 写为“布局变的步之后不再误恢复”的回归保护，不在追溯表中记为 §9.4 已覆盖；§9.4 的保护改为代码审核项（审核点：键的回写在无依赖的 layout effect 中，且键只由布局输入组成）。以后若键加入非布局输入，再补用例。

### P2-2 TSB-03 只断言“级别变”，不断言“跳过了无变化步”

- 方案 TSB-03：s 到 1 后每步 `data-zoom-level` 都变。若实现没有跳步、而是每个滚轮步都停（旧行为），zoomView(24) 在 −7 到 −9 等步上级别不变，用例会失败，这一点成立。但若实现跳步跳过了头（例如一步从 L2 直接跳到 L4，漏掉 L3），每步级别仍然都变，用例照样通过。
- 修改：TSB-03 在 s = 1 后断言级别序列为逐级（相邻停点级别差为 1，或差值等于该夹具中“外观相同”的级别数，zoomView(24) 为 2 → 3 → 4 → 5 → 6，leavesOnly 为 2 → 4 → 5 → 6），并复用 TSB-10 的读数跨度断言（`r1 < r0 / 1.15²`）证明确实跳过了步。实测读数：L2（−6 步）43%、L3（−10）25%、L4（−20）6%，余量足够。

### P2-4 TSB-12 没有比较值

## P3（建议）

- **P3-1** TS-06 只断言 `m.pairs` 中有 1000 h 的对，没有像 TS-05 那样调用 `tableZoomStep` 证明“该步不跳过”。如果实现把对算进去了但签名没用（例如取错 hide 键），TS-06 照样通过。建议加一步：在级别 4、合并对 1000·k 处于 (24, cap) 区间的 e 上，`tableZoomStep` 返回 e + 一步。
- **P3-2** TS-08 的 10 个中间探测点用 `tableZoomLevelAt(m, e, 0)` 求级别，即都从“从上方进入”的回差求值；缩小途中画出的级别可能更高。建议对每个探测点用 0 和 6 两个 prev 各测一次。
- **P3-3** TSB-01 的选择器排除了组头，但没有排除层叠卡以外的子事件卡（`[data-event-group]` 内的子卡也在包层内，结论相同，可接受）。字号断言 `13px` 依赖 CSS `zoom` 不改 computed font-size 的 Chromium 行为，Electron 44 与 Playwright 的 Chromium 一致，可保留，建议在注释中写明。
- **P3-4** TSB-06 的缩小回到 s = 1 用 `for (i < 13 && scale > 1)`，从全部展开（+7）缩到 s = 1 需要 13 步（+7 → −6），循环上限恰好等于所需步数。建议放宽到 20，或改为断言步数等于 13。
- **P3-5** TSB-15 的 `extra` 允许“第一行变化时多渲染一次”。尺寸每步都变，视图内第一行在放大时经常变化，这条放宽会让 TZB-09 规则（每步 ≤ 1 次）在大部分步上变成 ≤ 2 次。建议记录 `extra` 生效的步数并断言它小于总步数的一半，或在方案中写明这是接受的变化。
- **P3-6** 编辑中的卡在 s ≠ 1 时不缩放（S2）只由 TZB-20（级别 2，s = 1）覆盖；工作区实现是“`zoomOn && !isOpen` 才包层”，编辑卡算 open，所以在 s = 1.1 下也应无包层。建议 TZB-20 改在复位（s = 1.1）执行，断言编辑卡祖先无 `[data-card-zoom]`。
