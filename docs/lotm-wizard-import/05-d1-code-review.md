## 非阻塞意见

1. 行首空白后被切断时会丢失标题。如果切点正好落在缩进（如全角空格 `　`）和标签词之间，例如 `"…\n　" | "　物品\n旧灯"`，后一单元不算行首，旧代码会识别成 item，新代码沿用 body。实测：`'第一章 开始\n正\n　　物品\n旧灯\n'`，`max=10`。修正办法是判断“前面到行首都是空白”，而不是只看前一个字符。这种情况需要 1000 字切点恰好落在缩进里，概率很低，可以留到以后处理。
2. 行中切开的单元会整段跳过标题检测。如果这个单元的第二行是行首标题（“物品”“第三章”），新旧代码都识别不到，属于原有缺陷，这次没有扩大。可以考虑改为“跳过开头的残行，再取下一条非空行”，但这会改变现有行为，需要另开用例。
3. CLS-04 用的是 `max=1000`，单元按空行切分，所以它测的是“空行之后的标题”，没有覆盖切点落在 `\r` 和 `\n` 之间（前一个字符是 `\r`）的分支。建议补一条用例，比如 `'第一章 开始\r\n正文\r\n场景\r\n河岸\r\n'` 配合合适的 `max`，断言 scene，或直接断言单元以 `\n` 开头。
4. CLS-01、CLS-02 先断言测试数据确实在标签词前切开，然后才断言结果，能防止用例在条件不成立时空跑通过，做法很好。
5. 代码风格：单行压缩写法、`??''`、`/u` 标志都与周围代码一致。英文注释与文件中已有的英文 JSDoc 一致。
6. 方案中“修复后重跑探针确认第 4 步不再误判”属于真实目标验证，本次审核没有执行，台账里不应标为已通过。
