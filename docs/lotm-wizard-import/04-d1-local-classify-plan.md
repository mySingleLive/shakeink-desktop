# D1 本地分类误判：修复方案

日期：2026-10-29。来源：`01-research.md` 只读探针。

## 问题

`classifyLocalUnits`（`desktop/core/novel-import.ts:48`）用每个单元第一条非空行判断标签（“物品”“场景”“角色”等）和章节标题。`splitImportUnits` 在没有空行时按约 1000 字符切分，切点常在行中间。切点后的残行如果恰好以标签词开头，该单元及后续单元会被改判为资料。

本书 5620 个单元中有 4090 个从行中间开始，实测 9 个正文单元被判为 item/scene。第 4 步因此出现“物品/场景 识别到 1 处”并默认勾选。

## 修复

只有单元从行首开始时，才用第一行判断标签或章节标题。行首的定义：`unit.start===0`、单元起点等于所在来源部件的起点，或 `file.text[unit.start-1]` 是 `\n` 或 `\r`。从行中间开始的单元沿用前一个单元的类别。

不改变的行为：行首标题的识别、文件名标签、附件部件仍为 unknown、AI 分类路径。

## 用例

- CLS-01（RED）：正文中某单元从行中间开始，残行以“物品”开头，分类结果仍为 body，后续单元也是 body。
- CLS-02（RED）：同样情况下残行以“第三章”开头，不能把资料文件中的单元改判为 body。
- CLS-03（应不变）：行首的“物品”标题仍把该单元及后续单元判为 item。
- CLS-04（应不变）：CRLF 换行后的行首标题仍能识别。

## 回归范围

`tests/unit/novel-import-domain.test.ts` 及引用 `classifyLocalUnits` 的测试文件。修复后重跑探针，确认第 4 步不再出现误判资料。
