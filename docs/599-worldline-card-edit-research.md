### 展开形态（`EventCard.tsx:176-277`）

自上而下：

1. 头部 `.head`（42px）：子事件折叠钮（有子事件时）· 重要度圆点（大小 6 / 9 / 12px）· 标题 `h3`（14px / 600，可换行）· `N 个子事件` · 时间线的 ⌄ 收起钮 · 「…」菜单。
2. 元信息行 `.meta`：类型标签 `.tag`（类型色胶囊）· 时间文本 `.when`（`timeText()`，例如“后24小时 · 持续 6 小时”）· 重要度文字（一般 / 重要 / 关键）。
3. 正文 `.fact`：`MarkdownPreview`，13px / 1.75，段距 8px。
4. 参与角色 `.people`：头像 + 名字的胶囊，无角色时整行不显示。
5. 关键变化 `.change`：每条一行，“**角色** 维度 变化前 → 变化后”，灰底圆角。
6. 叙事引用 `renderRefs`（`eventReferences()`，`PlanningWorkspace.tsx:2064`）：按钮列表。

### 编辑流程（保留不变）

- 进入：卡片双击（事件表 `actions.toggle` detail ≥ 2，`:2276`；时间线 `select` detail ≥ 2 转同一路径）、「…」→ 编辑（`:2345`）、新建子事件（`:2349`）、详情对话框“编辑时间”（`:2742`）。只读、冻结前史、已有草稿时不进入（已有草稿提示“请先保存或取消当前事件编辑，输入已保留。”）。
- 草稿：`eventDraft`（`PlanningWorkspace` state），`ctx.hasDraft` 禁用其他卡片的编辑类菜单项。保存校验：标题非空、结束不早于开始、时间窗口结束不早于开始；`put("events", d)` 成功后清空草稿并 `revealEvent`。
- 点击编辑器外部不丢草稿（`:333-337` 只清叙事线 `draft`）。Electron 中 Esc 到不了页面（菜单加速键 ai.stop，见 docs/595–596 记录），所以取消只能靠按钮。
- 测试依赖的可访问名（`tests/browser/planning-worldline-*.test.ts`，约 30 处）：`事件标题`、`事件类型`、radio `关键`、`开始时间偏移`、按钮 `保存事件`、`取消`。

## 方向：同一张卡，原位可改

编辑形态 = 展开形态的同一 DOM 结构与同一套 class，每个信息元素换成“外观相同、可以修改”的控件。不再渲染 `renderEventEditor` 的表单盒子。

| 展开形态元素 | 编辑形态 | 说明 |
|---|---|---|
| 标题 `h3` | 同字号字重的自动增高文本框，无边框；悬停显示浅底，聚焦显示类型色下划线 | 解决 P2；可访问名 `事件标题` |
| 重要度圆点 | 不变（随重要度实时变大小） | 仅显示 |
| 类型标签 `.tag` | 同一胶囊，右侧多一个 9px ⌄；点击弹出 7 种类型（色点 + 名称） | 可访问名 `事件类型` |
| 时间文本 `.when` | 同一行文字（随草稿实时重算 `timeText`），虚线下划线；点击弹出“时间”浮层，放现有全部时间字段，分“开始”“持续”两组 | 解决 P3；字段与校验不变，只换容器 |
| 重要度文字 | 同一文字 + ⌄；点击弹出“一般 / 重要 / 关键”三段 | radio 语义保留，名称 `一般/重要/关键` |
| 正文 `.fact` | 见下文“正文编辑器”取舍 | 解决 P4 |
| 角色 `.who` 胶囊 | 同一胶囊，悬停 / 聚焦出现 ×；末尾一个同形状的虚线“＋ 角色”胶囊，点击弹出可搜索角色列表 | 解决 P5；无角色时编辑形态只显示“＋ 角色” |
| 关键变化 `.change` 行 | 同一灰底行：角色名（点击换角色）· 维度 · 变化前 → 变化后，文字原位可输入；行尾悬停出现“结束时 ⌄”与 ×；末尾一条虚线“＋ 关键变化”行 | 解决 P6 |
| 叙事引用 | 不变（编辑中禁用，与现状一致） | — |
| — | 卡片底部新增一条操作行：校验提示（左）、“取消”“保存事件”（右） | 必须有的提交入口；唯一的新增区域 |

编辑中的整卡提示：边框换成类型色（与选中同色系），不加额外文字。

### 正文编辑器取舍（需用户在设计稿里定）

| 选项 | 外观一致 | 功能 | 风险 |
|---|---|---|---|
| A 自动增高文本框（推荐） | 同字号 13px / 1.75、同色、同内边距，单段文本几乎与预览重合；Markdown 符号（`**`、`-`）以源码显示 | 纯文本编辑，撤销 / 复制粘贴走浏览器原生；无字数、无分屏 | 失去 Monaco 的 Markdown 高亮；`MarkdownEditor` 在本面板不再使用（项目约定只要求“复用 Web 真实组件”，未要求所有正文都用 Monaco） |
| B 保留 `MarkdownEditor`，只去掉外框并按内容增高 | 有模式条、状态栏，字体为 Monaco 等宽/编辑器字体，与预览不同 | 功能不变 | 与 R3 冲突；Monaco 自动增高需要额外布局代码 |

设计稿默认展示 A，可切到 B 对比。

### 宽度与高度

- 时间线展开卡宽 `OPEN_CARD_WIDTH = 420`（`worldline-layout.ts:49`），事件表槽最宽 920px。所有复杂字段放进浮层，卡身只有原来的几行，420px 下不换行错位（P3、P6）。
- 编辑形态高度 = 展开形态高度 + 正文编辑区多出的光标行 + 角色 / 关键变化的“＋”行 + 操作行（约 +80px），不再到 800px（P7）。时间线已有 ResizeObserver 测高重排（`openKey`），无需新逻辑。
- 浮层挂在卡片内（绝对定位、`z-index` 高于相邻卡片），时间线缩放（`.cardZoom`）时随卡片一起缩放；“…”菜单已用同样方式。

### P8 不在卡片里的草稿

新建子事件、被筛选隐藏的事件仍在视图上方单独显示，但显示的是**同一张编辑形态卡片**（宽 420px），不再是表单盒子。

## 审核第 1 轮修改（R4 尺寸不变）

设计稿按 R4 调整，下面的规则替换上文表格中对应的行：

| 元素 | 第 0 轮 | 第 1 轮 |
|---|---|---|
| 正文 | 自动增高文本框（A）或 MarkdownEditor（B） | 平时显示渲染后的正文（同一个盒子）；点击或 Tab 后回车，原位变成按段落编辑的可编辑区域（每段一个块，段距仍是 8px，以 Markdown 源码显示），离开后恢复渲染。B 方案和文本框都去掉：文本框里的空行占 23px，展开形态的段距是 8px，多段正文进入编辑就会变高 |
| ＋ 角色 / ＋ 关键变化 | 角色行末尾的虚线胶囊、关键变化下面的虚线行 | 合并为元信息行末尾一个 18px 的“＋”，弹出菜单：参与角色（可搜索）、＋ 关键变化，正文为空时还有 ＋ 正文 |
| 空的角色 / 关键变化 / 正文 | 编辑形态显示“＋”占位 | 与展开形态一样不显示 |
| 取消 / 保存事件 | 卡片底部新增一行 | 卡片右下边缘外悬挂的保存条（绝对定位，不占布局），校验提示在按钮左侧；编辑中的卡片 z-index 高于相邻卡片 |
| 关键变化行尾“结束时 ⇄ / ×” | 行内元素 | 浮在行尾（绝对定位，带渐变底），悬停或聚焦时出现 |
| 时间线 ⌄ | 不变 | 编辑中置灰（编辑中卡片保持展开） |
| 编辑中边框 | 类型色边框 + 外发光 | 不变（边框宽度不变，外发光是 box-shadow，不占尺寸） |

设计稿自测（Chromium，`design/worldline-card-edit/index.html`，三个示例 × 两个视图）：进入编辑时展开卡与编辑卡的宽 × 高完全相同，正文进入输入状态后也不变。

| 示例 | 事件表 | 时间线 |
|---|---|---|
| 完整事件 | 920 × 238 / 920 × 238 | 420 × 238 / 420 × 238 |
| 长标题（两行） | 920 × 269 / 920 × 269 | 420 × 269 / 420 × 269 |
| 新建子事件（无正文、无角色） | 920 × 84 / 920 × 84 | 420 × 84 / 420 × 84 |

之后用户改了内容（多写一段、加一个角色）卡片才按内容变化，变化后的尺寸与保存后展开形态一致。

实现注意：

- 保存条悬挂在卡片下方约 34px。事件表下一张卡片的槽位、时间线下方家族都可能和它重叠，需要编辑中卡片抬高层级（时间线 `.tcard` 已有 `:has([aria-expanded="true"])` z 5，编辑中改为高于它）。卡片在视图底边时保存条可能被 lane 裁掉，进入编辑时的定位滚动（`EventTimeline.tsx:589-608`）要把保存条高度算进去。
- 正文段落编辑：真实实现用 `contenteditable` 段落块还是“每段一个自动增高文本框”，技术方案阶段再比较（粘贴纯文本、撤销、IME、docs/598 的复制粘贴快捷键都要覆盖）。

### R8 与现有行为的冲突（技术方案处理）

- 现在点击编辑器外部**保留**草稿（`PlanningWorkspace.tsx:331-337`，注释“World events keep their draft while the canvas is inspected”）。R8 改为丢弃。需要确认现有用例里哪些依赖“编辑中去点画布 / 工具栏 / 事件目录后草稿仍在”，按 R8 改写。
- 以下仍算“卡片内部”或不算点击，不取消：`[role="dialog"]` 内的点击（现有规则，例如编辑中弹出的确认框）；浮层若用 portal 渲染到卡片外，需要标记为卡片的一部分；时间线缩放、滚轮、键盘平移不是点击。
- 以下会取消：点另一张卡片（首击取消，双击则进入那张卡片的编辑，“请先保存或取消当前事件编辑”的提示基本不再出现）、工具栏、事件目录、对话区、其他标签页。
- 新建子事件 / 被筛选隐藏的事件显示在视图上方的那张编辑卡同样适用：点它外部即取消，新建的草稿丢弃。
- 取消时会丢失未保存的输入，这是 R8 的明确要求；技术方案里不加二次确认（项目约定主进程确认要用 React 对话框，见记忆 no-native-message-boxes），审核时如需“有修改时先确认”再加。

设计稿自测（Chromium）：编辑卡胶囊替换 林衡 → 沈既白，尺寸 238 不变；改标题后点卡片外部，卡片回到展开形态、标题恢复原值、尺寸 238 不变；在类型浮层里选择、点胶囊 × 都不会取消编辑；展开卡片胶囊点击给出“打开角色详情”的提示（设计稿替代标签页）。

## 审核第 4 轮修改（时间浮层简化）

用户要求：时间浮层不够简洁易懂，需要美化和优化。

第 3 轮浮层的问题：两组共 9 个选项按钮（开始 4 个、持续 5 个）一次全部摆出；“方式 / 参考 / 偏移 / 窗口结束 / 时长”是数据字段名，不是用户的问题；“时点 / 持续 / 结束于 / 结束未定 / 持续中”五选一混了两件事（是否有长度、长度怎么填）；开始是时间窗口或未定时，“持续”一组没有意义却仍显示。

新浮层：两个问题，每个问题一行选项 + 一句话填空，顶部是实时预览。

| 区域 | 内容 |
|---|---|
| 预览 | 卡片上的时间文字（`timeText`，实时）+ 一条小时间轴示意：瞬间 = 圆点；持续 = 实心条；结束未定 = 渐隐条；至今仍在持续 = 带箭头的条；某段时间内 = 虚线框；未定 = “开始时间未定” |

## 审核第 5 轮修改（时间轴可拖动）

| # | 用户要求 | 设计稿 |
|---|---|---|
| R11 | 持续一段时间且结束确定时，线段右端也是一个点 | “持续一段时间”的两端各一个 12px 圆点；瞬间只有一个点；结束未定（渐隐条）、至今仍在持续（箭头条）只有开始点；某段时间内是虚线框，两端各一个点；只知道哪天是一天宽的虚线框，无端点 |
| R12 | 点和线段可用鼠标拖动端点修改 | 拖开始点：改开始，结束不动（持续时间随之变化）；拖结束点：改结束（时长或窗口结束），开始不动；拖线段 / 虚线框：整体平移，长度不变；只知道哪天：拖框按天移动 |

细节：

- 刻度：浮层打开、切换开始 / 结束类型、或输入的值超出可见范围时，按事件当前起止自动取可见范围（左右留白）；拖动过程中范围固定，不跟着变。左右两端标出范围的起止值（按吸附步长取整）。
- 吸附：拖动的值按可见范围取整到 小时 / 天 / 月 / 年（范围 / 30 以内最大的单位）；只知道哪天固定按天。拖完后数字框自动换成能整数显示的最大单位（例如拖到 29 小时时开始单位从“天”换回“小时”），不出现 1.208 天这样的小数。
- 拖动时，被拖的点放大并带光圈，下方显示该点的值（整体平移时显示起止）；不拖时显示范围两端的值。
- 结束点不能拖到开始点左边，开始点不能拖到结束点右边（时长不会为负，现有“结束时间不能早于开始时间”的校验仍保留给手填）。
- 键盘：圆点是 `role="slider"`，可 Tab 聚焦，← → 一次一步，Shift 一次 10 步；可访问名“开始时间 / 结束时间 / 发生时间 / 时间窗口开始 / 时间窗口结束”。
- 拖动结束后的点击被吞掉，不会关闭浮层或触发“点卡片外部取消编辑”。拖动不改变卡片尺寸（自测 238 不变）。
- 实现注意：真实实现的刻度、吸附与标签用世界线日历（`CalendarAdapter`：天 / 月 / 年长度来自 `calendar.hoursPerDay` 等，纪年历按 `adapter.label`），设计稿用固定 24 / 720 / 8640 小时示意。时间线缩放（`.cardZoom`）下拖动量按浮层实际像素宽度换算。

设计稿自测（Chromium）：后24小时 · 持续 6 小时 → 拖结束点 +80px → 持续 9 小时；拖开始点 −60px → 后22小时 · 持续 11 小时；拖线段 +50px → 后25小时 · 持续 11 小时；结束点 → / Shift+← → 持续 2 小时；某段时间内拖结束点 → 后25小时～57小时；只知道哪天拖框 → 后1天；瞬间拖点 → 后29小时（单位自动换回小时）。全程浮层保持打开、卡片保持编辑、无页面错误。
