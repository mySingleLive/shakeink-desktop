# 591 · 世界线图例筛选 技术方案独立审核

审核对象：`docs/591-worldline-legend-filter-plan.md`。对照代码：`c0e98c9` 加上工作区未提交改动。审核时工作区里已经有 591 的部分实现：`filterEvents`、`wViewTree`、图例重要度按钮、CSS，以及 WU-33/34、WU-34b、WU-09e、WU-21b、LF-01..04、LF-B1..B4 的测试。下文行号以当前工作区为准。

结论：主体思路正确。“用筛选后的事件建视图树，时间仍按完整 `data` 解析”这一点成立：`eventTree(events, data)` 用 `data` 作为 `resolveTime` 的上下文（`worldline-layout.ts:466`），锚点指向被隐藏事件时照常解析。不过方案只改了视图树，许多派生值和操作仍按全部事件计算，导致**不可见的事件可被删除或移动**，搜索序号越界，空状态提示有误。下列问题按严重程度排序，P0 和 P1 应在实现前写进方案。

## P0：必须处理

### 1. 隐藏事件保留在多选里，删除、引用、整体拖动会作用到看不见的事件

方案 §2 写明“选择仍用完整的 `wTree`，隐藏事件的已选状态保留”。当前代码中：

- `selection`（`PlanningWorkspace.tsx:274`）按 `wTree` 过滤，隐藏事件留在选择中。
- `deleteSelection`（`:2312`）删除 `[...selection]`，时间线的 Delete/Backspace 键（`EventTimeline.tsx:448`）也调用它。用户框选 10 个事件，隐藏“冲突”后按 Delete，看不见的冲突事件会一起删掉，确认框只显示数量。
- `quoteSelection`（`:2324`）从 `wTree.byId` 取节点，引用内容会包含隐藏事件。
- 拖动标题（`drag`，`:2345`）在 `selection.size >= 2` 时把整个选择传给 `startTimeDrag`；`finishTimeDrag` 中 `shiftSelection(data, drag.group, …)` 会保存隐藏事件的新时间。预览（`EventTimeline.tsx:154-158`）只在 `tree.byId`（已筛选）中查找，所以用户看不到这些事件移动。
- 状态栏“已选 N 个事件”（`:2617`）把隐藏事件也计入。

建议：保留原始选择以便恢复后不丢（符合方案意图），但另算“有效选择” `selection ∩ wViewTree.byId`，删除、引用、整体拖动、“已选 N”和传给 `EventTimeline` 的 `selection` 都只用有效选择。方案需写明，并增加浏览器用例：框选后隐藏一类，按 Delete 只删除可见事件（或对话框中数量等于可见数量）；整体拖动不改动隐藏事件。

### 2. 搜索序号在筛选变化后不重置，可能越界

`wHits` 已改为只在 `wViewTree` 中查找（`:283`），但 `hitIndex` 只在输入框变化时归零（`:2559`）。例如先搜索“码头”并跳到第 5 个结果，再隐藏“冲突”，结果只剩 2 个：工具栏显示“6 / 2”（`WorldlineToolbar.tsx:87`），`hitId={wHits[hitIndex]}` 为 `undefined`，当前命中高亮消失；之后点 ↑/↓ 按 `(hitIndex + dir + n) % n` 计算，会跳到意外位置。

建议：筛选变化时 `setHitIndex(0)`，或渲染时把序号限制在 `[0, wHits.length)`。增加用例：搜索后切换图例，计数不越界。

### 3. 正在编辑的事件被筛掉，或保存后不再符合筛选

- 原位编辑器在卡片内（`EventCard.tsx:233`）。编辑中点击图例隐藏该事件所属类型，卡片和编辑器一起消失，`eventDraft` 仍然保留。兜底编辑器（`:2721`）只在事件不在作品中时渲染，这里不会出现。结果是用户看不到草稿，再编辑其他事件只会收到“请先保存或取消当前事件编辑”。
- 编辑时把类型改成已隐藏的类型，或在“其他”“一般”被隐藏时用“＋ 事件”新建（默认 `category: 其他`、`importance: 1`），保存后事件直接消失，没有任何提示。

建议二选一，写进方案：(a) 正在编辑的事件及其祖先始终保留在视图树中，`filterEvents` 增加 `keep` 参数；(b) 编辑时禁用图例。另外，保存后若事件被当前筛选隐藏，提示“已保存，当前筛选隐藏了该事件”。补充对应用例。

## P1：方案遗漏的 wTree/全量用户，应明确改用视图数据

### 4. 定位类入口会定位到隐藏事件，静默无效

`locateWorldEvent`（`:2362`）用 `wTree`，会设置 `eventSelection`，但卡片不在 DOM 中，滚动和闪烁都不会发生（`:2384-2390` 找不到元素时直接返回）。受影响的入口：

- 深链接（`:2393` 用 `wTree.byId.has(id)` 判断）：从引用或 AI 引用跳转到一个被隐藏的事件时没有反应。
- 时期下拉（`:2526`）：`inside` 来自 `worldAllEvents`，`inside[0]` 可能是隐藏事件，同时提示“N 件事件”也计入隐藏事件。
- 卡片菜单“定位子事件”（`:2339`）：`wTree.byId.get(e.id).children[0]` 可能是被隐藏的子事件（父事件可见、子事件类型被隐藏时）。
- 待定位/延续弹层、角色变化轨道中的按钮调用 `locateEvent`（`:2470`），列表本身包含隐藏事件，见第 5 条。

建议：深链接和外部定位遇到隐藏事件时，清除筛选（或只重新显示该事件的类型和重要度），再定位，并提示“已显示被筛选隐藏的事件”。时期下拉和“定位子事件”改用 `wViewTree`。方案目前只说“深链接仍用完整的 `wTree`”，没有说明之后怎样显示。

### 5. `renderWorld` 里的派生值全部未筛选

`renderWorld` 自己重新取 `worldEvents(data, worldId)`（`:2405` 起），方案没有提到：

- `pending`（`:2408`）：工具栏“待定位 N”和弹层仍计入隐藏事件，而事件目录里的“待定位 · N”（`EventTree.tsx:96`）已经筛选，两处数字不一致。
- `continuingAt`/`continuing`（`:2448`）：“延续事件”计数和弹层包含隐藏事件。
- `resetTimeline`（`:2417`）：“复位”“全部时期（全貌）”和空视图里的“复位”按钮按全部事件求范围。只看一类时，复位后可能落在没有可见卡片的范围，又出现“视图内没有事件”（`EventTimeline.tsx:423`）。
- `changeItems`（`:2454`）：时间线的角色变化轨道仍显示隐藏事件的变化，点击后定位失败。

建议：在 `renderWorld` 中用 `wViewEvents` 计算 `placed`/`pending`/`continuing`/`changeItems`/复位范围，并在方案里列出这张表。角色变化轨道是否跟随筛选需要定一个规则，建议跟随。

### 6. 全部类型都被隐藏后的空状态提示有误

`wViewTree` 为空时，时间线显示“当前世界线还没有已定位事件。添加事件，或为待定位事件设置时间。”（`EventTimeline.tsx:621`），这与事实不符。事件表和事件目录变成空白，也没有恢复入口。只看一类时，如果这一类事件都是被隐藏父事件的子事件（D1），也会得到空视图。

建议：传入“有筛选”标志，空状态显示“当前筛选下没有事件”加一个“显示全部”按钮。补充用例。

## P2：语义与界面

### 7. D1 与图例计数、“只看这一类”的关系需要写明

图例计数和“N 件事件”仍按全部事件计（方案 §2）。在 D1 下，隐藏“谋划”后，“冲突 106”不变，但谋划父事件下的冲突子事件也已消失，用户无法从计数看出实际显示了多少。双击“只看揭示”时，非揭示父事件下的揭示子事件也会消失。F60 中“港口危机”这类父事件的子事件多是 冲突/揭示，《诡秘之主》的导入数据层级更深，差距会更大。

建议：状态栏改为“显示 X / 共 Y 件事件”；方案中明确写出“只看这一类 = 隐藏其余类型，并按 D1 隐藏其子孙”，必要时向用户确认。另外 `filterEvents` 按原始 `parent` 链判断，而 `eventTree` 会把父事件已定位、自身待定位的子事件单独放进“待定位”（`worldline-layout.ts:494-499`）。这类事件在目录里看似独立，父事件被隐藏后也会被隐藏，这是 D1 的直接结果，建议在方案中注明。

### 8. 事件表缩放基准随筛选变化

`wZoom = tableZoomBounds(wViewTree)`（`:279`）的 `fit` 由主分段的根事件数计算，`tableZoom` 是相对 `fit` 的对数值。筛选后 `fit` 改变，在同一缩放档位下 k 会跳变，对齐模式下的刻度密度也会变化。这符合“重新排版”的要求，但方案中 LF-B1 写的“相邻顶层卡片间距与筛选前相同”只在等距模式下成立：对齐模式（默认，`tableRail="aligned"`）的间距与时间成比例，并随 `fit` 变化。LF-B1 的期望应改为“没有因被隐藏卡片留下的空位”，并在两种模式下各测一次。另外 `EventTable` 是否虚拟化按 `tree.byId.size > 300` 判断（`EventTable.tsx:82`），筛选可能切换渲染方式，需要在《诡秘之主》（885 事件）实测中覆盖。

### 9. 时间线内部使用视图树的部分没有问题

以下部分检查后没有问题：

- 缩略条 `minimapModel(tree.roots)`（`EventTimeline.tsx:359`）、`famInfo`/子事件数 `▸ N`、`stamps`、`TimelineTreeNav` 的“视窗内 N 件”（`:686`）都使用已筛选的树，与可见内容一致。
- 拖动预览用 `tree.byId`。只要第 1 条改用有效选择，预览和保存的内容就一致。
- 事件目录的方向键导航（`EventTree.tsx:131`）按 DOM 行移动，自动跟随筛选。
- `pinnedCard` 指向隐藏事件时，`rootOf` 找不到节点，打包时没有固定卡片，可接受。
- “全部展开”（`:2547`）按全部事件判断，并把隐藏事件也放进 `openCards`，恢复显示后仍是展开状态，可接受，但应在方案中写明。
- 折叠集合 `foldedEvents` 保持按 id 存储，正确。

## P3：可访问性

- `aria-label` 写在没有 role 的 `<span>` 上（`WorldlineToolbar.tsx:131`、`:146`）。ARIA 不允许给通用元素命名，读屏软件通常不会读出。应加 `role="group"`。重要度组嵌套在类型组里，建议改为两个并列的 `role="group"`。
- `aria-pressed=true` 表示“显示中”，按钮文字是“冲突 106”/“一般”，按下状态的含义需要靠组名说明。上一条修好后可以接受。
- 筛选后卡片消失，读屏用户得不到反馈。建议用现有的 `setMessage` 或状态栏 `aria-live` 播报“已隐藏 冲突 · 显示 X / Y 件”。
- `title`“圆点大小表示重要程度；点击隐藏或显示”只在鼠标悬停时出现，键盘用户看不到；有组名后影响不大。

现有新用例的不足：

- 缺少单元用例：父事件已定位、子事件待定位时，父事件被隐藏，待定位子事件也被隐藏（第 7 条）。

需要补充的浏览器用例（与 P0/P1 对应）：

1. 多选后隐藏一类，按 Delete 或整体拖动，只作用于可见事件（第 1 条）。
2. 搜索并跳到第 N 个结果后筛选，计数不越界、不显示“N+1 / M”（第 2 条）。
3. 编辑中隐藏该类型，编辑器仍可见或图例被禁用；保存成隐藏类型后有提示（第 3 条）。
4. 深链接或时期下拉定位到被隐藏的事件（第 4 条）。
5. “待定位”“延续事件”计数和“复位”范围跟随筛选（第 5 条）。
6. 隐藏全部类型后显示筛选空状态和“显示全部”按钮（第 6 条）。
7. 图例组名可被 `getByRole("group", { name: "类型筛选…" })` 找到（P3）。
