# 场景复核证据定位用例独立审核

日期：2026-10-31。审核者：独立子代理 `scene_hierarchy_review`。先完成272方案独审，再审核273；未参与测试或产品实现，未读取真实数据或调用模型。

**RA-01—04及RA-REAL设计通过，可以先取得RED再实施。** 测试须落实下列判定，避免被无关错误提前拒绝或把既有末端行为误判成新增变换。

- **RA-01**：conflicts和missingTargets分开使用其它字段及范围均合法的真实生产桥夹具，只改变一条证据的quote。请求采用生产review结构，kind省略且selectedTargets恰为`['scene']`。第一条错误不能直接在外层runImportAi拒绝；应观察generateJSON内实际第二次生成及修正后的成功结果。与同一完整合法结果通过原流程的基线比较，允许既有末端冲突hash/id计算及唯一排版恢复，不把这些原行为误称资料丢失。
- 实际第二次prompt的纠错段须含固定证据项路径和对应原因指导，不含仅存在于坏模型输出中的合成quote/ID秘密或原始cause。原数据prompt本来就包含已授权单位和实体ID；应检查纠错段或专用输出哨兵，不能以删除正常输入来满足“不回显”。
- **RA-02**：四种原因应分别断言具体定位指导，不能只验证“拒绝”。unknown-unit应是不存在的声明ID；too-short使用非精确且不足8个非空白字符的引文，同时以真实精确短引文作正控；ambiguous须在同一声明单元产生多个排版恢复命中且原始quote并非精确子串；no-match须足够长且在声明单元确实不存在。另构造声明单元有效、quote只在另一单元唯一精确存在的反例，防止误用analyze专用rebindEvidence而移动单位。
- 唯一排版恢复正例在早期schema返回时应仍保留原quote，最终runImportAi才得到原末端恢复的源排版；精确短引文、多条合法引用的接受结果与旧门一致。合法primary位置之后夹入坏证据仍整项失败，conflicts与missingTargets两种数组都覆盖，不允许筛选坏项或只查首项。
- **RA-03**：持续失败以真实generateText计数证明仅两次生成且没有返回可提交结果；如验证controller落盘，应额外核对没有新增结果/复核完成标记，不能只用计数替代落盘断言。其它类别、混合目标、缺selectedTargets及其它阶段使用本身合法的请求；非semantic旧协议夹具同时移除只属于semantic的上下文，否则会被旧请求门提前拒绝而无法证明隔离。
- 网络、授权及取消从实际生成依赖抛出，分别证明不进入第二生成；AbortError/已有异常身份不被新增schema检查替换。输入对象及早期schema结果不得因调用anchorEvidence而改变。前置检查只能读取该函数成功/失败，不采用返回值。
- **RA-04**：合法证据不能代替阶段、缺失投影、完整typed引用/语义或末端授权。分别构造可通过证据检查但超出本次artifact/unit范围的结果，并验证原late门仍拒绝；末端撤权、snapshot变化、取消也要在成功生成后触发，避免只测生成前拒绝。测试须经过实际generateImportAiJson→generateJSON→runImportAi接线。

RA-REAL顺序与方案一致：本地独审/定向检查/类型/构建通过后才进行真实只读失败范围复测及新的整书全流程。982场景阶段成绩、一次复核或历史部分进度不得替代本轮完整复核、发布及正常重开一致性。本审核仅通过用例设计，未执行新增用例或认证真实运行结果。
